# 模块接口与开发验收规格

状态：首版单人 B 的接口实施草案，目标 Godot 4.7.2。纯 typed GDScript 数据定义位于 [code/contracts](../code/contracts/README.md)；这些文件不是游戏服务实现。行为以 [17](17-首版行为与实现契约.md) 为准，资产/UI 见 [20](20-资源表现与界面实施规格.md)，持久化细节见 [18](18-进度数据库与存档实现规格.md)，任务/星区/经济实施见 [19](19-首版任务星区与经济内容规格.md)。SQL 与本文件签名共同作为字段核对入口。

## 1. 类型、所有权和时间边界

协议枚举定义在 `contract_types.gd`，typed DTO 定义在 `contract_dtos.gd`。自定义类、字段和数组使用显式类型，禁止把任意 Dictionary 当业务协议。GDScript 的枚举底层是整数，typed 本身不能证明枚举值合法，入口仍验证成员；数组/RefCounted 也不是自动不可变数据。[GDScript 静态类型](https://docs.godotengine.org/en/stable/tutorials/scripting/gdscript/static_typing.html)

- 世界、玩家、舰船、装备、容器、任务、动作、事件、快照、转移均使用独立稳定字符串 ID；定义 ID 和实例 ID 不互换。ID 格式与唯一性由创建服务负责，不能用节点序号、中文名、位置或数组下标生成实例身份。
- `world_id/session_id/epoch` 标识当前写会话。epoch 必须严格增加；读档或整次世界切换使旧请求与回调失效。校验顺序为世界/会话→权限→动作去重→版本→业务条件；旧 epoch 不能借“同 action_id”绕过会话校验。
- EntityVersion 的版本由权威模拟拥有，每次相关业务改变递增。舰船 `state_version` 持久化；容器、报价、任务等未设独立 SQL version 的对象使用当前 epoch 内的版本索引，读档时重新初始化。版本索引不能伪装成持久化字段；epoch 隔离确保重置后旧命令仍无效。快照 `capture_sequence` 是保存顺序，不能拿来当实体 version。
- DTO 不含 Node、Resource、RID、Callable、SQL 连接、Godot 对象实例引用。向量/姿态存分量；UI/VFX 与场景工厂内部可使用 Node，但该句柄不进入 DTO/存档。后台只传独占或深复制的 DTO；发布后不得修改其字段/数组，不能用 `duplicate()` 浅复制假冒完整隔离。
- 模拟层独占运行状态，固定物理 tick 接受命令。渲染帧仅读取 WorldView/Event；世界暂停时模拟 tick、计时与随机流停止，UI 动画不产生业务时间。B 不按离线时间结算；非当前星区状态也在全世界快照中。
- 场景树、物理与 GPU 的调用统一在主线程。SQLite 保存 worker 不创建 Node、不加载渲染材质、不共享可变数组；串行连接不跨线程同时调用。[Godot 线程安全 API](https://docs.godotengine.org/en/stable/tutorials/performance/thread_safe_apis.html)

## 2. 正式命令与返回协议

`CommandEnvelopeDto` 公共字段：`action_id`、`session(world_id,session_id,epoch)`、`actor_player_id`、`action_kind`、`target_entity_id`、`requested_tick`、`versions[]`。每个 version 为 entity_kind/entity_id/expected_version。所有写动作先验证所有参与对象的版本，包括源/目标容器、当前舰、站点报价或任务；不能只验所选物品而忽略另一侧容量。请求中时间仅用于排序/日志，客户端不能指定过去 tick 回填奖励。

同一动作始终沿用同一 action_id 重试；UI 禁止重发时新建 ID 绕过 pending。已 APPLIED 的 action_id 返回原结果，不执行第二次。已恢复快照的 receipts 随世界一起回退，不能查“未来世界”的全局日志否决旧档合法动作。持续飞行输入是覆盖式 input intent，不为每图形帧写永久 receipt；制造、交易、奖励、借船、交付、转移等不可重复结算业务须记录 receipt。动作 ID 一旦绑定 payload 不可复用；同 epoch 重复 ID 的不同 action_kind/payload 一律 INVALID_COMMAND。

下表是正式 port 约定；GDScript 没有本任务已实现的运行服务。每一 port 接收 envelope + 指定 DTO，不接受自由键值 payload。异步返回按 action_id/session 关联，成功返回 APPLIED、新版本、生成 ID 和可选自动保存请求 ID；拒绝返回 REJECTED/稳定 RejectCode，不部分扣款或移动资产。

`WorldSnapshotDto` 是一致快照，先完成当前 tick 原子业务，再捕获深复制。扫描、采矿、修理等付费交互未完成周期和在途攻击不能进入快照；扫描在稳定周期边界保存后，已发现结果保留、半完成累计进度读档重开。已付费引擎增益允许保存剩余期，读档不重新扣能或把 enabled 当“按住 Shift”；输入键状态不持久化。飞行锁定目标、粒子、音效与动画不入档。

### 3.1 RNG算法与恢复契约（pcg32_v1）

`pcg32_v1` 固定为 **PCG32 XSH-RR：64位state、64位奇数increment、32位无符号输出**。乘数 `6364136223846793005`（`0x5851f42d4c957f2d`），state运算模 `2^64`，输出旋转为uint32右旋；不能替换为其它PCG变体或直接调用Godot全局随机函数。[官方最小算法](https://www.pcg-random.org/download.html)、[官方C实现与初始化/有界采样](https://github.com/imneme/pcg-c-basic/blob/master/pcg_basic.c)

**新世界初始化**：B仅一个业务流 `stream_id="world"`，initstate取SQL `world.seed` 的完整64位二补码位模式，initseq固定为54，故increment=`(54×2+1)=109`。54是算法流标识，不是游戏平衡值。标准初始化依次执行：state置0→设置increment→调用一次next并丢弃输出→state加initstate后模 `2^64`→再调用一次next并丢弃输出。不能直接把seed赋给state或将55当initseq。官方demo的参数是initstate=42、initseq=54。[官方demo源码](https://github.com/imneme/pcg-c-basic/blob/master/pcg32-demo.c)

每次 `next_uint32` 先保留旧state，再计算新state：`(old×乘数+increment) mod 2^64`；输出使用**旧state**：`x=low32(((old logical_shr 18) XOR old) logical_shr 27)`，`r=old logical_shr 59`，结果是 `ror32(x,r)`。先更新再从新state出数、漏截x到32位或用算术右移都会改变序列。

**有界整数**：`bounded(bound)`只接受整数 `1≤bound≤2^32−1`；非法bound在取随机数前拒绝。threshold=`2^32 mod bound`，反复调用next，丢弃 `raw<threshold`，首次 `raw≥threshold` 返回 `raw mod bound`，结果为 `[0,bound)`。不能直接对任意raw取余、四舍五入或限制拒绝次数后改用取余。需要完整32位范围直接调用next；加权抽样的整数权重总和也必须在bound范围内。一次被拒绝的raw同样推进state。[官方有界采样说明](https://www.pcg-random.org/using-pcg-c-basic.html)

**GDScript整数实现约束**：保存/运行state使用非负32位hi/lo，`value=hi×2^32+lo`只是数学解释，不能在GDScript将它拼成有符号64位后逻辑右移，更不能经float。乘加使用四个低位在前的16位limb：乘数limb为`[0x7f2d,0x4c95,0xf42d,0x5851]`；每列k=0..3计算 `t=carry+increment[k]+Σ(i=0..k) state[i]×multiplier[k−i]`，输出limb=`t & 0xffff`、carry=`t >> 16`，第四列后丢carry。中间和小于 `2^35`，不溢出有符号64位。seed加法也逐limb进位。

逻辑右移64位以两个非负32位limb执行：移n（1..31）时hi变`hi>>n`，lo变`(lo>>n) OR ((hi & (2^n−1))<<(32−n))`后截32位；移32..63时hi为0，lo为`hi>>(n−32)`；移0不变。XOR逐limb，32位右旋所有操作数非负并截32位。SQL seed提取原始二补码hi/lo，负seed也保留其位模式；算法过程不使用float、字符串十进制转float或Godot RNG对象。

**存档/恢复**：在同一稳定tick保存 `state_hi/state_lo/increment_hi/increment_lo`，每列在0..`2^32−1`，B要求流world且increment_hi=0、increment_lo=109。读档直接恢复这四列，验证algorithm/流/位宽/increment；不重新seed、不重新做两次初始化、不因载入场景或重试动作先取数。随机流只由权威模拟按既定动作/tick顺序推进，渲染、音效、UI、保存和加载不消费该业务流；业务拒绝不取数，同action_id重放返回既有结果不再次抽样。

黄金序列：42/54完成标准初始化后，前六个输出依次为 `a15c02b7 7b47f409 ba1d3330 83d2f293 bfa4784b cbed606e`。[官方示例输出](https://www.pcg-random.org/using-pcg-c-basic.html) 独立参考测试 [test_rng_contract.py](../jiaoben/tests/test_rng_contract.py) 验证该序列、hi/lo经SQLite保存后续序列、有界拒绝路径及16位limb与数学参考一致；测试不是正式游戏实现，Godot RNG接入仍须用同一黄金序列验收。将来增加用途流或改变算法必须新规则版本与明确存档迁移，不能把B的world流默默拆开。

## 5. 保存、读取和跨区状态机

### SaveService

`REQUESTED → DEFERRED（如不稳定）→ CAPTURING → QUEUED → WRITING → COMMITTED`；任何资格/写库失败进入 FAILED，只有未开始写的请求可直接 CANCELLED。DEFERRED 由脱战、周期结束、场景 ready 等事件重新检查；提示阈值取 catalog，用户决定继续或取消。自动保存可合并成最新一致快照；手动槽不能被自动槽抢占。合并结果返回 QUEUE_SUPERSEDED，不显示假 COMMIT。

串行 worker 内使用同一事务：确认 runtime_session/session/epoch 与 transfer barrier→INSERT building snapshot→所有状态行/FK检查→seal完整性检查→`status=sealed`→以 expected_slot_generation 条件 CAS 更新/新建槽→推进 session last_committed_sequence→COMMIT。第一次空槽 expected generation=0，成功后generation=1；既有槽只从期望g变g+1。`changes()!=1`、旧 epoch、sequence倒退或任何 SQL 错误都 ROLLBACK，槽保留最后好档。sealed 内容/快照只读；以后更新新建快照，不能UPDATE旧档行。

RuntimeSessionRowDto 映射 runtime_session 控制表，loaded_snapshot_id表示最近读入边界，resume_snapshot_id表示当前会话的合法恢复点，transfer_barrier_id与last_committed_sequence防旧队列；它不属于业务WorldSnapshot行。读取旧手动档后，resume首先指向该合法档，后续成功保存同事务推进，不能重启又自动恢复读取前的未来自动档。

SaveRequest 对新槽同时给 slot_kind（manual/auto/quick）、slot_index、slot_label；既有槽须匹配其固定身份，不能通过更新槽改世界/用户/类型。profile由world所属用户解析，不信任UI传任意owner。SaveEligibility.allowed=true须reasons为空，false须至少一个实际阻塞原因。NPC已警戒、追击、攻击或脱离警戒阶段即 COMBAT，首次攻击前也不能钻稳定保存窗口；仅idle/patrol/return/dead状态可进入稳定快照。

取消 WRITING 时只标记 UI 取消意愿，等事务结果：若已 COMMIT，报告 COMMITTED；若可 rollback 才报告 CANCELLED。业务不因 save 失败回滚当前内存，也不把失败写入说成成功；不允许未经确认将当前世界清空。

### LoadService

`REQUESTED → VALIDATING → ISOLATING → PREPARING → READY → ACTIVATING → ACTIVE`。LoadRequest 显式携带 UI 选择的 `target_snapshot_id` 与 `expected_slot_generation`。先建立加载屏障停止新保存入队、撤销未写旧请求并等待正在执行的 SQL 结束；随后重核槽generation与目标快照，变化则返回 STALE_SELECTION，请用户重选，不能悄悄载入后来自动档。固定该snapshot后验证 sealed/结构/内容/资源兼容，并准备独立候选场景/WorldSnapshot；旧场景保留作为失败恢复来源。加载期暂停新业务与模拟，不能同时驱动两份世界。

候选 READY 后，在原子持久会话操作中 CAS 当前 session/epoch 并推进 epoch、指定 loaded_snapshot_id，成功才替换当前权威世界并清旧输入/事件/目标；不会把旧快照行的 writer_epoch 改成新 epoch。验证、准备或会话 CAS 失败保留旧 epoch/world 并解除屏障；不能提前推进 epoch 再回退计数。epoch切换后的意外激活异常进入恢复页，用已经切换的有效会话重建目标世界，不复活旧回调。LoadResult 返回实际有效会话，UI 只在 ACTIVE 时退出加载页。

加载阶段不消耗物资或发奖励；恢复已付费引擎剩余期/周期计时不触发新扣费；asset/schema/rules 不兼容不默认采用当前catalog。存档迁移须完整复制并另生成 sealed快照，本任务不实现自动转换。

### TravelService

`IDLE → PREPARING → ACQUIRING_BARRIER → ORIGIN_SAVING → DESTINATION_LOADING → DESTINATION_SAVING → COMMITTED`。准备期攻击、超范围、死亡、切舰或取消终止且不扣费。准备完成后排空/合并旧保存，持有 transfer_id 屏障，暂停权威模拟/世界时间/外部业务；仅该转移内部保存能入队。origin COMMIT 失败保持起点；目标加载失败释放 staging；destination 快照包含新的位置、门状态、费用、transfer receipt，COMMIT失败保持origin。

destination COMMIT成功才替换内存与活动场景、释放屏障；随后崩溃恢复destination，不第二次扣费。若切场景激活在 COMMIT 后异常，必须按已提交destination重新构建或停在恢复页，不能回到未扣费origin继续玩。origin/destination保存都使用同一全世界快照契约；常规旧origin自动档不得在屏障后覆盖最新槽。任何旧 load/save/transfer回调在通知UI或改场景前重检epoch和requestID。

## 6. 开发任务及最低验收

本表划定可编码工作，验收是未来运行测试，不把纯DTO或SQL存在当作功能通过。

| 工作项 | 输入 → 交付 | 最低可验证验收 |
| --- | --- | --- |
| 契约与adapter | typed DTO/SQL → 显式字段读写及枚举/NULL编码 | 全状态行往返无损；int数量/credit、quat、品质/耐久、活动引擎剩余、借船attempt不漏；错enum/非有限数拒绝 |
| Catalog/Asset加载 | frozen manifest/资源manifest → 只读definitions与资源索引 | 改hash、缺槽/资源、错asset版本拒绝；正确四船能够加载，参数不从脚本补齐 |
| 权威世界/飞行 | 输入intent/DB/起始档 → 唯一WorldSimulation | 30/60/144渲染FPS行为不变；暂停和离线无增长；零电容返航；观察镜头不转舰 |
| 战斗/资源交互 | 目标/模块/资源/事件 → 命中、采集、发现 | 扫掠阻挡、三层溢出、战斗锁门；周期末满舱/目标失效不出货；扫描已发现去重 |
| 库存/配装/经济 | container/item/stack/slot/market → 一次原子动作 | 重复action不重复资产；双容器余量/整数校验；卸装仍保留政策品质耐久；拒绝不部分扣款 |
| 教学/任务/保障 | 起始/attempt/loan/unlock → T0–T4闭环 | 新档不重复补给；借船毁/放弃可恢复但无可兑现资产；满载返回；返航交接需可替代舰且奖励一次 |
