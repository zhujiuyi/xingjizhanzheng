# 星际战舰 · 首版行为与实现契约

版本：v0.3 开发基线，2026-10-03。用户已确认：先完成单人闭环，保留联机所需数据与接口。本文明确行为边界，正式进度 DDL/任务数据/资源/接口分别见18–21；具体操作和损失规则为可调整的原型默认方案，不代表已经实测。

范围对应总纲 A 技术验证与 B 双星系四舰闭环。数值、单位、公式与参数以 [数值系统](15-数值系统与平衡基线.md) 及其数据库资产为准；持久化架构见 [数据库方案](10-数据库与存读档技术方案.md)。

## 1. 唯一规则来源与业务边界

- 配置数据库定义“允许什么、数值多少”；内存中的权威模拟保存当前运行状态；进度数据库保存已提交的完整快照。
- 每次业务动作先校验前置条件，构建候选变更，再在模拟边界一次性应用到内存并登记 `action_id`。失败不产生部分扣款、扣料或产物。
- **业务成功与保存成功分开**。业务成功表示本次运行状态已改变；只有 SaveService 的数据库 `COMMIT` 成功才表示已持久化。任务交付、制造、交易等完成后请求自动保存；保存失败保留当前会话并提示重试，强退恢复最后成功档。
- 初版不同时实现“每笔交易单独实时落库”和“整世界快照”两套权威写入。数值定义不得通过执行配置内任意脚本文本改变规则；定义 ID 映射到代码中的合法行为实现。
- SQL 初始化/迁移是可审查的数据库生成材料，运行时查询生成的数据库；设计文档中的表格用于评审，不另作运行时配置源。

## 2. 新世界与首个任务链

新世界从锚港的停靠状态开始：读取数据库起始档案，创建保障雨燕、其合法初始配装、信用点、基础材料、基础扫描能力和可用服务。保障来源写入船体及附属物品实例。初始快照提交成功后才进入游戏。

| 顺序 | 任务与前置 | 完成行为 | 保证可获得的下一步能力 |
| --- | --- | --- | --- |
| T0 出航准备 | 新世界已建立 | 学会离港、推进、制动、转向和靠泊 | 初始雨燕即可完成，无采购或研究要求 |
| T1 航标识别 | T0 完成 | 使用船体内置基础扫描识别教程航标 | 产生唯一情报记录，校准锚港—回声门 |
| T2 资源试采 | T1 完成 | 领取教学铁砧及采集头，进入回声带采矿并返航交付 | 借船与设备无需先买矿、研究或提高声望 |
| T3 配装与战斗 | T2 完成 | 在锚港领取教学游隼并试装，完成基础战斗目标后返航交接 | 弹药/耗材补给可在锚港获得，不依赖低安全区材料 |
| T4 独立探索 | T3 完成 | 借用提灯与扫描阵列，完成一次普通信号发现并返航 | 四型可通过教学借用体验；永久购买/制造按独立经济条件进行 |

“解锁”必须区分已见图鉴、可借用、可购买、可驾驶、可制造。B 阶段基础驾驶不设长期训练门槛，蓝图解锁不自动赠送实体舰船。教学船领取在同一世界、同一任务阶段幂等；已有借船不能重复领取。

教学借用使用稳定 `loan_id`，记录本次有效船/模块实例。旧实例已毁或已归还时允许同一借用合同受控换发新实例，不重复发放启动材料、已领取奖励或额外套装；原实例保持永久失效。专业借船丢失后的换发不依赖玩家已经失去雨燕，避免保底雨燕阻止重新学习采矿或战斗。借船及附模块不可出售、拆解获利或有偿交付；完成教学后归还，永久拥有仍需正常购置/制造。

飞行中的目标达成只进入待交接状态，不立即撤销当前借船。教学最终结算在锚港停靠后进行：预先确认当地有可切换的保障雨燕/自有可驾驶舰；再原子切换角色、归还借船和绑定资产、登记完成并发奖解锁。普通战利品先转入当地仓库，绑定资产不得混入普通堆叠；若交接条件不满足保留借船并显示原因。不能因击毁目标触发任务完成而让玩家在太空失去正在驾驶的实例。

教学采样任务只开放其目标所需的采集配额，产生带 `mission_bound` 来源的样本，只能交付指定教学任务，不可销售或用于普通配方。失去样本允许按剩余目标重采，不能重复领取已经结算的阶段奖励。普通自有舰船在正常采矿中得到的矿物是正常商品，不因驾驶过保障船而被错误限制。

初始仓库材料为每世界一次的普通资产，不能重复创建世界初始化奖励。按19分别在T2/T3/T4后开放采矿/战斗/测绘合同，借用服务绑定当前有效合同；普通合同矿可交易，但quota跨换发累计，损失不复制丢失的货物。B普通制造拒绝受保护输入；起始赠品、教学样本和正常商品的来源政策不得混为一类。

任务目标明确区分 `collect`（记录有效采集成果）与 `deliver`（向接收点提交实物）。交付必须在正确接收点，从当前可交付库存扣足指定物品并一次发奖；历史挖过的数量不能代替已出售的货物。单纯舰船损失不使任务failed，保持同attempt的active/ready、期限与目标，按19受控换发；样本丢失按有效样本缺额补采，普通货不复制。B教学无时限或不可恢复失败条件，主动放弃清理后才能重接；重复受理不能再次领取已结算阶段奖励、启动材料或额外套装。

基础采集头、标准火控、基础修复与基础弹药有锚港采购或教学来源。高级热束、支援与遗构模块允许暂不开启，但不得成为基础教学的前置条件。数值版本与数据库表中未开放内容不能在可用菜单或星图上显示为可立即进入。

## 3. 飞行输入与暂停

原型默认采用带辅助稳定的六轴平移与限速转向，键鼠作为首个输入方式。手柄、完全无辅助的惯性模式和自动环绕指令后续评估。

| 输入动作 | 键鼠默认绑定 | 行为 |
| --- | --- | --- |
| 前后/横向推进 | W/S、A/D | 请求局部推力；多轴输入归一化，斜向不额外加速 |
| 上下推进 | Space/C | 请求局部垂直推力 |
| 偏航/俯仰 | 鼠标 | 产生目标方向，船体按数值上限转向，不随鼠标瞬时旋转 |
| 滚转 | Q/E | 绕船体前向轴旋转，受转向能力限制 |
| 制动/增推 | X / Shift | 制动使用辅助稳定；按住 Shift 请求已安装且可用的矢量引擎周期增益，消耗与倍率取模块定义 |
| 主武器 | 鼠标左键 | 按武器挂点顺序请求射击；判定与纯视觉表现分离 |
| 自由观察 | 按住鼠标右键 | 仅移动观察相机，暂不将鼠标位移发送给船体转向 |
| 目标选择 | Tab | 循环选择当前可识别合法目标；HUD 显示锁定状态 |
| 场景交互 | F | 按目标类型显示并执行扫描、采集、靠泊或虫洞门交互 |
| 镜头切换/星图 | V / M | 跟随、前向、战术观察循环；星图明确当前目的地和门路线 |
| 菜单 | Esc | 单人暂停菜单；世界时间、AI、制造与刷新同时暂停 |

键位属于首版输入资产，允许重绑定；实际鼠标灵敏度、镜头参数与玩家偏好按数据库方案保存。输入映射本身可使用 Godot InputMap，不能在输入逻辑中另写舰船速度等平衡数值。

基础推进、姿态控制和制动在零电容时仍可用；只有增推及主动设备消耗电容。B 阶段不引入消耗式燃料。电容按世界时间恢复，暂停和离线不继续计算；零电容不会导致无法返航。

B 的“增推”就是15中的矢量引擎主动效果，不是额外叠加的独立技能。未安装、损坏、过热或电容不足时请求失败；松开 Shift 后不续订下一周期，已付费周期到期后恢复基础倍率。三倍局部巡航保留为后续候选，B 默认不开启。

局部空间采用米制、Y 向上、船艏沿本地 -Z；转换方向由资源导入规范统一。B 阶段船体与场景有碰撞和滑移/停止，暂不施加碰撞伤害，避免首次出航因占位碰撞体损失资产。伤害性撞击属于后续独立机制，不能由引擎碰撞冲量隐式触发。

## 4. 目标、扫描与采集

目标必须具有稳定实体 ID、类别、所属星区和可交互状态。光标、相机或 Node 路径不充当持久 ID。远离、销毁或跨区后清理失效锁定；镜头锁定不等于武器自动命中。

扫描条件为目标可扫描、在扫描距离内且未被要求遮挡检查的实体阻断；进度由定义和扫描能力计算。离开范围或电容不足时暂停进度，重新满足条件可继续当前目标；更换目标清空本次尚未完成的扫描进度。已完成情报以唯一记录保存。B 稳定边界保存不包含半完成扫描进度，读档重新开始该次扫描，已发现结果保持。

采集周期开始前检查目标、模块、距离、电容、兼容矿舱/货舱、载荷质量与剩余矿量；周期结束原子结算前再次检查所有可变条件，包括距离、目标、模块状态、实际容器余量与当前载荷。只产出完整整数物品；末次按当时资源余量和接收容量减少产量，无可接收产物则不启动。中断未完成周期或结算时不满足条件不产生物品，周期消耗规则以数值库为准，不同时按起止两次扣能。

专用矿物舱只收兼容矿物。选择接收容器时先矿物舱后通用货舱；实际体积与载荷上限共同限制装载，不把升数和千克直接相加。空间站仓库是独立位置，购买物品进入当地仓库；货物不会自动跨星系进入舰船。

## 5. 战斗、资源与失败

伤害按数值文档规定的护盾→装甲→结构及剩余原始伤害传播，所有层和抗性均使用有限值并执行上下界检查。同一模拟 tick 的动作按规定优先级和稳定实体/挂点 ID 执行；电容不足时不能让全部设备各自读取旧电量而同时成功。

射线武器命中依据实际射界和碰撞检测；弹道武器按物理运动与扫掠检测判断命中，不仅检查本帧终点。视效不生成第二次伤害。敌我、支援目标许可、射程、冷却、弹药与能量均由权威模拟校验。

温度达到禁用条件后暂停相关主动设备，按恢复阈值重新允许，具体数值和同 tick 顺序见数值系统。B 阶段品质为标准档，模块耐久不按每发随机磨损；已有损伤和非标准实例数据仍应能存读。

交战状态由有效敌对攻击尝试更新，未命中也会更新双方最近交战时间；对空乱开火不影响无关实体。脱战等待读取15的参数，不能仅因当前盾未扣血就允许穿门或保存。稳定快照还需没有在途攻击和未完成交互。

结构归零时，移除舰船的可驾驶资格，执行一次舰毁恢复：原船实例进入已摧毁状态；玩家返回锚港。此事件不自动触发任务fail。可回收部分形成唯一残骸容器，原舰和残骸不能同时持有同一件物品。B原型默认安装模块随舰损失，普通货物按数据库回收比例形成残骸；保障物品不产生可交易回收物。残骸拾取检查距离、归属、容量和重复领取。

保障船及附带模块不可出售、拆解获利、交付有偿采购合同或转移给其他世界；保障标记随拆卸继续存在。只有失去最低行动能力时提供替代保障套装；有可驾驶基础舰、借船或可领取救援时不再叠加赠送资产。该规则用于避免重复领奖套利，不限制正常购买/制造资产的交易。

## 6. 停靠、换舰与配装

站点交互核验距离、速度和敌对状态。成功后转入停靠状态并解除当前飞行控制，角色、船体实例和当地仓库关系保持。换舰必须选择该站点内属于玩家且可驾驶的舰船；原船留在当地，不能因角色换到穿梭器就跨系传送大舰。

配装命令包括船实例、挂点、模块实例和预期版本；校验所有权、位置、尺寸标签、挂点、功率、算力、安装质量和互斥类别。提交在内存业务边界同时移动装备位置并更新属性，失败则全部不变。装备属性修改不凭空补满护盾/装甲/电容；上限降低时夹紧当前值，上限提高时保持当前绝对值，停靠修理/补能按服务规则单独执行。

货物转移、出售和拆卸后重新计算总质量及有效推进能力。窗口展示冲突字段与不足的具体预算，不能静默卸下其它模块以强行满足配装。

## 7. 虫洞门与中断恢复

跨星系只有指定锚定虫洞传送门与已发现的游离虫洞能够触发。教程门 `conn_anchor_echo` 为四型合法配装和合法满载保留双向通行，无燃料、收费或有限总通行质量门槛。后续门按定义核验准入与载荷；路线规划和装货界面展示最窄门余量，超限可在合法站点卸货、明确弃货或请求救援。

| 状态 | 条件与操作 | 失败或退出处理 |
| --- | --- | --- |
| 可交互 | 在入口范围内、满足速度和非交战条件 | 显示具体不满足项，不开始演出 |
| 准备 | 展示目的地和成本，蓄能；候选扣除尚未应用 | 玩家取消或受击则返回当前星区，不扣跨区成本 |
| 出发前保存 | 固定 origin 状态并提交完整自动档 | 保存失败不离开；提供重试或取消 |
| 目标准备 | 保持 origin 权威状态，加载目标场景并确认出口可用 | 加载失败回 origin；不消耗门容量或生成掉落 |
| 目标提交 | 构造目的地完整候选快照，包含位置、成本、门状态与实例转移，一次提交 | SQL 失败回 origin；只允许旧完整状态或目标完整状态 |
| 完成 | 提交成功后替换运行世界，再播放出口效果、恢复镜头与控制 | 此后崩溃从目标完整快照恢复，不再扣一次通行成本 |

转移使用唯一 `transfer_id`，写入对应快照/动作记录。恢复时只使用已提交的 origin 或 destination，不恢复半程隧道坐标。读旧手动档会按本地存档规则回退全世界，不能强行沿用未来转移记录。

准备期离开入口、舰船销毁、角色换船或门状态失效均中止；同一实例只允许一个转移请求。提交目标快照前再次检查实例有效性和准入版本，不能用准备开始时的旧检查结果直接放行。

准备完成后先排空/合并旧保存请求并取得 SaveService 转移屏障；从 origin 捕获到 destination 提交期间暂停单人权威模拟与外部业务命令，世界时间也暂停。只允许该 `transfer_id` 的内部保存操作进入队列，常规自动档不得在目标提交后用旧 origin 覆盖最新槽。成功切换或失败退回后解除屏障并恢复模拟；不能仅冻结镜头而让采矿、NPC 和库存继续变化。

教程目的地出口设在安全位置，NPC 出生区不覆盖出口。普通战斗中不能直接触发门逃离；脱战判定、门范围和速度阈值由数据库给出。游离虫洞暂在 C/D 阶段开放，B 不执行寿命或不稳定连接随机生成。

## 8. 保存与读取边界

手动保存允许在停靠或稳定飞行状态请求；交战、半完成业务操作、扫描/采集周期或跨区期间延后到稳定边界。UI 必须标明延后原因，允许用户取消请求，不能无限显示“已保存”。退出时可等待保存或明确放弃未提交进度。

`SaveEligibility` 返回允许状态与原因枚举（combat、interaction_cycle、transition、scene_not_ready、pending_mutation）。等待有数据库配置的提示阈值；达到阈值给出继续等待或取消选项，不擅自丢弃手动请求。脱战、交互周期结束和加载完成触发重新检查。用户选择立即退出时明确显示最后成功保存时间，不把延后请求当作已落盘。

combat 延后还包括本世界中 NPC 的 `acquire/pursue/attack/disengage` 阶段，即使尚未发生第一发攻击；不保存缺少目标锁定信息的半程敌对 AI。`idle/patrol/return/dead` 可进入稳定档，仍须满足无在途攻击和其它资格。该预检应先返回 DEFERRED，SQL seal 防线只防止漏检，不能把正常等待变成 SAVE_FAILED。

自动保存覆盖独立槽，按返回站点、重要任务交付、跨区成功和定时规则触发。先捕获全世界一致状态，再串行写库；重复触发合并，手动槽独立保留。读档必须先隔离旧会话请求，按新会话代次恢复，不允许旧写入回调覆盖已读档后的槽。

LoadRequest 固定 UI 选择的 `target_snapshot_id + expected_slot_generation`。先取得加载屏障，停止新写入入队、取消未执行旧请求并等待已开始 SQL 结束，再检查槽 generation；变化则返回 `STALE_SELECTION`，不能悄悄换读另一档。读出并验证目标、搭建 staging 场景全部就绪后，才 CAS 推进 session epoch 并切换世界。准备失败保留旧世界和 epoch，释放屏障后仍可保存原会话；成功切换后拒绝旧 epoch 请求。完整次序与字段映射以18/21为准。

最低持久状态包括：起始/教学资格、保障来源、角色与当前船、船体三层损伤与能量/温度、装配和未装装备品质/耐久、货仓与当地仓库、信用点、任务与领取记录、发现、门与资源状态、世界时间、恢复所需RNG、已开放的生产/商店和必要实例位置。B不开放长期研究/生产队列，进入C阶段时补其定义和状态迁移，不能让未实现研究成为B存档必需表。演出粒子、临时锁定和正在播放的动画不持久化。

## 9. 模块边界与通信

| 模块 | 输入 | 输出/责任 |
| --- | --- | --- |
| Input / Camera | 键鼠、镜头偏好 | 意图与观察，不直接扣款、扣血或写 SQL |
| WorldSimulation | 固定 tick、已校验命令 | 唯一运行状态、业务事件、状态查询 |
| Ship / Combat / Interaction | 定义与实体状态、动作 | 飞行、命中、扫描、采矿、停靠和挂点规则 |
| Inventory / Economy / Mission | 有类型的业务命令 | 原子候选变更、动作结果与错误码 |
| TravelService | 两端定义、转移请求 | 协调保存、加载与目的地提交，不自行维护第二套库存 |
| CatalogRepository | 内容版本/定义 ID | 只读有类型定义；缺失时显式失败，不硬编码回退平衡值 |
| SaveService / ProgressRepository | 完整快照、目标槽、会话代次 | 数据库事务、耐久结果、版本/迁移/备份 |
| UI / VFX / Audio | 业务事件及状态 | 显示与演出，可降低画质而不改变命中或掉落 |

命令至少有 `action_id`、`session_epoch`、发起者 ID、目标实例 ID 和必要预期状态版本；返回稳定结果码和可解释参数。重复命令返回已有结果，不再次产生资源。未来房主联机可在命令入口验证并转发，渲染和玩家输入不会成为数据库权威。

暂停、世界时间、实体生命周期和随机数由模拟层拥有。物理 tick 与图形帧分离，所有数值效果按秒或固定 tick 明确定义，不能随显示器帧率变化。

基础接口数据形态：`ShipFactory(def_id, instance_state)` 从同一内容快照创建船；`SectorLoader(system_id, sector_id, frozen_catalog)` 返回已就绪场景及稳定锚点索引；`WorldSnapshot` 包含版本、世界/玩家/实体/物品/任务/门/事件状态集合。DTO 使用标量、向量分量、稳定 ID 和有类型列表，禁止保存 Godot Node、Resource 实例引用或依赖加载顺序的节点编号。

内容摘要在数值构建时产生，采用显式版本的 `catalog_hash_v1`：注册所有内容表、字段顺序和主键；按表名及主键 BINARY 顺序遍历，类型和长度分隔编码；整数十进制、REAL 转有限 IEEE 754 binary64 的大端十六进制、TEXT 为 UTF-8 字节、NULL 单独标记。所有用于派生数值的 SQL 视图也须显式登记，按名称顺序把 `sqlite_schema.sql` 的精确 UTF-8 定义文本加入摘要；未登记的表或视图使校验失败。视图来自受审迁移 DDL，不能让配置提供任意可执行 SQL。排除摘要字段自身与构建时间，SHA-256 得到逻辑内容摘要。不能用整个 `.db` 文件哈希代替内容身份；文件哈希另用于分发校验。正式实现可集中在构建工具，兼容测试确认相同值与视图定义在两平台生成同一摘要。

冻结定义必须包括所有已注册玩法表及其引用闭包；规则代码版本、资产清单版本和数据库格式版本独立记录。数值兼容不代表规则或资源兼容。旧档缺少所需规则/资产时保留旧档并报告不能加载，不静默改用当前默认船或价格。

## 10. 场景、资产与界面最低清单

首个工程需要启动/存档菜单、锚港、回声带、共享舰船场景、门与出口锚点、矿点、敌方目标、残骸、HUD 和站点界面。资产初期可用占位网格；真实缩放、碰撞、挂点和资源 ID 应稳定。

舰船场景约定包含视觉根节点、简单碰撞体、推进视效锚点、与数据库槽位对应的挂点、相机跟随目标和交互定位点。挂点只保存几何结构与稳定槽 ID，伤害、射程和供能仍来自数据库。武器模型朝向、碰撞层和敌我查询掩码由统一导入/场景规范维护。

最低 UI 状态包括：当前船和三层防御、电容/热量/货舱；目标与距离；当前任务；门目的地和准入；配装预算错误；存档成功/失败/等待；读档不兼容；基础站点仓库/修理/交易。UI 原型可在对应功能开发前补，完整美术界面不阻断技术样例。

## 11. A/B 验收入口

1. 通过数据库配置创建新世界，起始资格和资产可恢复；没有未定义物品或硬编码默认船值。
2. 单人完成 T0–T4，能借用/驾驶四船并理解职责；初始资源不会要求先完成尚未解锁的玩法。
3. 满舱铁砧从回声返回锚港，零电容保留基本行动，无法开启增推/设备有具体反馈。
4. 配装失败不丢装备；卸装、买卖、制造、矿点扣除和任务领取保持一致；保障套装不能套现。
5. 穿越失败、保存失败与强退分别只恢复合法 origin/destination；不产生重复舰船或重复扣费。
6. 退出再加载恢复完整业务状态；高帧率/低帧率只改变表现，不改变单位时间采集或伤害。

本文定义验收条件，本轮没有实现这些 Godot 行为。数值与 SQLite 资产校验结果见 [26](26-开发阶段与交付记录.md)。
