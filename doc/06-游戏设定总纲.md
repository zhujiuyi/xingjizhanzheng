# 星际战舰 · 游戏设定总纲

版本：v0.2 评审修订。日期：2026-10-02。

状态：用户需求已提取；以下原创世界、舰船、玩法和阶段范围是第一版设计稿，尚未确认或实现。已确认的技术栈和数据库要求不属于待选项。

## 1. 用户需求与本版设计

| 类别 | 已确认内容 | 本版设计方向 |
| --- | --- | --- |
| 游戏主题 | 星际探索、采矿、战斗，操作不同样式、类型和功能的战舰 | 以一支小型船队恢复航路、拓展基地能力为成长主线 |
| 星系与势力 | 多星系，各有侧重或独有产出；星系与所属势力的舰船、武器、护甲科技有差异 | 以资源分布、工业专长、科技路线与通行网络共同驱动航行和贸易 |
| 风险与出行 | 星系通过特定虫洞传送门连接；高、中、低安全区的 NPC 等级不同 | 锚定虫洞门形成固定航线；安全区影响敌人、执法/救援、任务与收益 |
| 参考对象 | 参考 EVE 的玩法、舰船类型、能力和样式 | 借鉴职业分工、配装取舍、区域风险与资源循环；名称、世界、舰船外形与数值原创 |
| 飞行体验 | 要考虑战舰操作、飞行视角和视角转换 | 第三人称跟随为基础，自由环绕、船头观察与目标构图配合直接飞行操作 |
| 跨区表现 | 穿梭器跨星系虫洞穿越及相关特效 | 穿梭器负责开路、扫描和侦察；虫洞容量决定其他舰船能否通行 |
| 战斗表现 | 舰船交战特效与镜头转换 | 武器、护盾、引擎和受损表现清晰，玩家能够判断攻击与逃脱机会 |
| 使用与成本 | 自己和朋友玩，macOS / Windows 独立客户端，不采用收费授权技术栈；首版单人闭环已确认 | 为朋友合作保留数据与权威模拟接口，后续联机人数与接入方式另定 |
| 技术栈 | Godot 4 + GDScript + Forward+ + Blender 已确定 | 编辑器、插件与导出模板版本在工程搭建时固定，性能由原型验证 |
| 数据 | 必须保存、读取存档；游戏数值通过数据库存储 | SQLite 作为当前数据库工程方案，区分配置数据库与进度数据库；细节见数据库方案 |

“第一版设定”描述的是设计方向，不等于一次实现全部内容。EVE 参考事实和原创改造逐项记录在 [参考说明](11-EVE参考与原创边界.md)。

## 2. 游戏定位

玩家在原创的 **断航星域** 接管一座边境锚港和少量舰船。在既有航路崩解、区域联系减弱的背景下，玩家寻找虫洞与遗迹、采集建造资源、修复舰船并应对敌对势力，逐步建立可靠航线。

体验重点是：**不同舰船带来不同任务选择，配装影响实际操作，探索结果推动下一次出航。**

- 探索舰擅长发现信息和逃离危险，战斗舰负责威胁清除与护航，采矿舰将发现转化为资源，穿梭器承担快速侦察和跨区先遣。
- 飞行与战斗采用实时 3D 操作；任务、制造、仓库和配装通过界面管理。
- 世界有危险和损失，但默认体验允许合理恢复，避免朋友试玩因一次失误陷入无法继续的状态。
- 画面方向建议为科幻半写实：舰船轮廓清楚、工业结构可信、推进和武器效果突出。完整驾驶舱及电影级过场按后续工作量决定。

## 3. 四个设计支点

| 支点 | 玩家获得的体验 | 首轮验证方式 |
| --- | --- | --- |
| 舰船分工 | 换舰船会改变能力和决策，较大船不在所有任务中占优 | 穿梭器、探索护卫舰、战斗护卫舰、采矿舰具有可感知差异 |
| 航路探索 | 信息和路径有价值，发现可积累到星图 | 扫描一个异常点并找到可通行虫洞 |
| 资源与成长 | 采矿、回收、任务所得能用于修理和改装 | 一次采矿返航后完成一次模块制作或购买 |
| 战斗与风险 | 航线、射程、能量和配装影响胜负，也允许撤退 | 击败或避开一个威胁，保护货物并返航 |

## 4. 核心循环

**查看星图和任务 → 选择舰船与配装 → 出航 → 扫描、采集或战斗 → 根据风险继续或撤离 → 返回锚港 → 交付、加工与改装 → 开启下一次航行。**

跨区循环是：**选择虫洞门航线或侦察未知通道 → 核验容量和返回条件 → 穿越 → 建立目标星区情报 → 完成任务 → 返回或接入新锚点。** 穿越动画衔接星区加载，发现记录与目标星区进度均入库。

## 5. 完整游戏的系统版图

完整设定先建立互相连接的系统，再分阶段实施，不以技术样例的规模替代整体游戏设计。

| 系统 | 设定要点 | 权威文档 |
| --- | --- | --- |
| 星图与星系 | 固定门连接、发现状态、安全区、航线规划、特色资源和站点服务 | 世界观、星系与势力科技 |
| 势力与科技 | 舰船、武器、防御、引擎和传感专长，声望和蓝图来源 | 星系与势力科技、装备研发 |
| 舰船与配装 | 功能舰种、尺寸分工、预算约束和原创外观，装备取舍 | 战舰设定 |
| 探索与资源 | 扫描、遗迹、矿脉、回收、产区与运输风险 | 玩法、星系与势力科技 |
| 工业与贸易 | 精炼、部件、制造、维修、回收、市场与货运 | 装备研发与工业经济 |
| 战斗与敌人 | 伤害/防御/能量、难度等级、角色 AI、危险事件和撤退 | 玩法设定 |
| 任务与成长 | 主线、职业合同、声望、研究与舰船解锁，主动游玩推进 | 玩法、装备研发 |
| 后续朋友协作 | 侦察、采矿、护航与支援分工；首版单人，后续合作/PvP 规则另定 | 玩法、数据库方案 |
| 持久世界 | 世界生成和变化、资产、任务、存读档、版本与事务 | 数据库方案 |

舰种、科技和装备依赖关系应避免必须从事所有职业才可继续：稀缺产物可以通过探索、交易、合同或合作取得。危险程度与收益相联系，同时保证基础舰船、修理和返回路径可获得。

## 6. 内容阶段建议

| 阶段 | 目标 | 建议内容 |
| --- | --- | --- |
| A：技术样例 | 核验引擎、数据库、操控、镜头和特效 | 简化战舰与穿梭器、两个测试星区、敌方目标、一次穿越；完成数据库存读档与两平台导出验证 |
| B：首个可玩闭环 | 从任务选择到返航交付可以完整游玩 | 锚港与回声带、四种基础舰船、扫描/采矿/战斗/穿梭任务、基础配装和资源加工 |
| C：内容扩充 | 增加角色分工与探索深度 | 扩展至约 3–6 个星系与三种常规势力；驱逐舰、巡洋舰、运输/支援舰及贸易制造；根据实际决定朋友联机 |
| D：完整蓝图与深化 | 逐步实现整体十星系及高级内容 | 分批开放危险航区和静默遗构，战列舰、复杂制造、基地扩展、协作任务；舰队规模与高级视觉效果另行测试 |

原型复用占位模型；“四种舰船”先指四套可区分的功能配置，精细外观逐步替换。各阶段数量为提案，不视作已完成或用户锁定的交付承诺。

## 7. 数据与存档底线

- 舰船、模块、武器、矿物、配方、任务奖励、敌人、虫洞容量、掉落和经济数值由数据库提供，运行时代码不散落维护另一套平衡值。
- 存档保存玩家、世界、舰船实例、配装、库存、任务、星图发现、资源消耗和跨区状态，读档从一致快照恢复。
- 数据库保存内容版本和结构版本，防止改动数值后无声破坏旧存档；存档与配置修改通过受控迁移或版本兼容处理。
- 模型、声音、场景和着色器仍使用资源文件；数据库记录资源标识与影响玩法的配置。文档中的表格是设计稿，实施时对应正式数据库条目。

具体选择、表结构方向、事务、备份和验收见 [数据库与存读档技术方案](10-数据库与存读档技术方案.md)。

## 8. 暂不纳入首个闭环的内容

持续运行的 MMO 宇宙、万人市场、主权战争、长时间离线技能等待、付费订阅、大型行星登陆、完整舰内行走和超大舰队会改变开发规模。当前阶段以可独立运行和朋友试玩的任务体验为范围；是否扩展后续另定。

用户已确认先完成单人闭环，保留联机数据和接口。后续合作人数、PvP 与世界转交规则再评估；当前不因未选这些后续规则而阻断单人开发。
