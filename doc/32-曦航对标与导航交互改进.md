## 1. 参考来源与实际观察

参考入口为 [曦航·DAWNLINE](https://dawnline.eveai.vip/)。名称已通过页面标题核对，此前称“曙航”的记录为误读。本轮以游客进入并操作，以下区分实际观察与本项目的实现选择。

| 参考中的实际观察 | 可以支持的结论 | 本项目的采用方式 |
| --- | --- | --- |
| 总览有全部、战斗、导航分类；距离、名称、类型可排序 | 信息密度可通过分类和排序控制，选中对象有独立操作区 | 紧凑总览、固定选中卡片、分类与排序；沿用现有雷达和唯一目标标注 |

| 星图显示风险颜色、节点连接、选中势力及描述；主线港口显示 1/16 与下一步 | 星图与任务应提供下一行动所需信息 | 绘制数据库中的真实虫洞连接、风险、势力、站点与资源；保留现有真实任务流程 |

## 2. 现有问题与本轮实施边界

此前飞行界面能选中目标、使用近距 F 交互和跨系虫洞，但缺少清晰的本星系导航指令。远站与敌舰共用局部探测上限，也使玩家难以直接找到已知空间站；星图主要为文字列表，设备循环信息分散，界面容易呈现为技术演示。

本轮实施六项改进：

1. 总览分类、排序与选中操作面板，支持远处已知站点定位。
2. 本星系跃迁、普通接近、三维环绕、停船，以及自动接近后停靠。
3. 选中敌舰的自动开火辅助，与已有武器规则共同工作。
4. 真实设备栏，显示配装启用、损坏、循环、冷却、电容和热量状态。
5. 数据库关系驱动的图形星图，展示真实连接与地点信息。
6. 本星系跃迁的准备、运行和停止反馈；保持现有中文字体、工业模型、淡白虚线、唯一名称与跟随镜头修复。

本轮未增加公开宇宙、多人房间、付费素材、无人机编队、无限距离探测、任意地点跨星系瞬移。参考中的 75% 起飞速度门槛、逐帧战斗数值和自动打捞链不属于已验证或已实现功能。

## 3. 已确认导航交互规格

### 3.1 目标选择与资格

| 对象 | 选择范围 | 支持的导航与操作 |
| --- | --- | --- |
| 当前星系已知空间站 | 总览可远程列出；不受敌舰局部探测上限裁剪 | 跃迁、接近、环绕、停船、自动接近后停靠；服务操作仍须真正停靠 |
| 当前星系固定虫洞门、资源点、信号和航标 | 仅当前世界中已有且定义有效的实体 | 类型允许时跃迁、接近、环绕；虫洞穿越仍须入口范围与独立准入检查 |
| 活着的敌舰 | 当前星系、实际局部探测范围以内 | 接近、环绕、停船、自动开火；禁止跃迁到移动敌舰 |
| 当前星系残骸 | 必须为真实残骸容器 | 接近、环绕与既有回收；不作为固定跃迁锚点 |
| 远景行星等天体 | 仅航向参考 | 保留参考标记，不允许跃迁、接近或停靠 |

定义的星系归属、稳定实体 ID、活着状态与场景节点必须同时有效。另一个星系的站点不能通过传入 ID 变成本星系目的地。选中新目标只改变界面选择；已经接受的导航保持原目的地，直至停止或接受另一条指令。

玩家通过总览、雷达、Tab或左键短击模型选择目标，光标始终可见；选择不发射武器。双击总览中的实际目标单独下令转向并接近。界面控件优先消费鼠标事件，拖动列表不控制相机；新版入口验证见33，原v0.7.0指针模式入口的专项与截图属于历史结果。

### 3.2 本星系跃迁

1. 选择合法固定目标，面板显示距离、跃迁资格与拒绝原因。
2. 启动前必须是当前舰船处于 `FLYING`、同星系、没有其他导航或虫洞过渡，且交战、弹丸和非引擎设备周期等保存阻断已清除。
3. **先提交稳定起点的 SQLite 自动快照，再开始充能和运动。** 起点提交失败，不能改变位置或启动跃迁。
4. 充能期间位置固定，船体按实际舰船转向能力对准落点；时间结束后仍须满足数据库中的角度容差。暂停冻结充能及运动。
5. 跃迁在当前星系内连续移动至安全落点；准备和运行阶段都重新检查稳定条件、当前舰船、目标存在及落点碰撞资格。
6. 到站外后速度归零、状态仍为 `FLYING`，显示操作面板并请求自动保存；**不自动进入空间站**。
7. 点停靠或使用已符合资格的 F 交互后，再进入空间站场景。

空间站本轮落点为站中心外 500 m。它处于原停靠半径 600 m 内，但停靠还需原业务服务的速度、交战和状态验证。跃迁到虫洞门附近只改变本星系位置，不支付跨区通行费用、不写跨区回执、不改变当前星系。

### 3.3 接近、环绕、停靠与停止

普通接近和环绕通过 `XJFlight.intent → simulate()` 运行，受舰船加速度、转速、速度上限与实际碰撞限制，不直接写入瞬移坐标。接近按剩余距离控制减速，进入到达容差并降低速度后停止。环绕采用起始舰船姿态确定三维轨道面，并连续追踪目标；轨道半径按目标类型从数据库读取。敌舰超出探测或死亡后清理导航。

远处点击停靠启动普通接近。到安全站距且减速完成后，Main 再调用原 `dock` 业务动作；业务服务二次核验距离、速度、交战与站点条件，成功才切换 `DOCKED` 和空间站场景。导航控制器不直接修改停靠状态。

X或停船按钮停止移动与导航，不关闭独立自动开火。明确的手动推进、转弯或滚转接管自动航行；非跃迁接管保留惯性并在当前物理步响应输入。普通鼠标移动、左键观察、缩放和单次选择不会接管。取消跃迁仍清理运动并安全停船；若位置与碰撞体相交，先恢复到经实时检查的安全采样点，不能把船停进站体。观察角度由左拖保留，仅“显示舰船”等明确相机动作恢复默认。

交战阻止跃迁和停靠，但保留接近、环绕与手动撤离。自动开火与普通战术导航并行；跃迁启动或目标失效时清理开火辅助。

## 4. HUD、设备与战斗辅助

总览提供“全部／战斗／导航”分类，距离、名称、类型排序和稳定选择；类型、距离与动作不得靠颜色单独表达。选中卡片按资格显示跃迁、接近、环绕、停止、停靠、交战和自动开火。不能执行的动作有具体原因，不能静默丢弃命令。NPC详情使用实际护盾、装甲与结构状态；查看别的对象仍展示真实开火目标与其待机原因。

底部设备栏从实际配装实例读取启用、完整性、循环剩余、冷却、电容及热量。开关指令仍走业务服务；循环消耗、倍率、时长和冷却来自原 SQLite 定义。显示状态不代表可以提前结束已付费周期，也不能跳过能源或热量条件。

自动开火只针对当前可见活敌舰，继续检查实际武器挂点射程、前向射界、视线、配装完整性、电容、热量和冷却；使用原弹丸、命中和伤害路径。选择目标或打开辅助不代表自动命中。超出范围、销毁、跨星系或开始跃迁后不能继续对旧节点开火。

v0.8.0“交战”是明确设置所选敌舰为开火目标并启动接近；自动开火开关本身保留既有接近/环绕。单击更换界面选择不自动转火；X只停移动，Z或目标卡停止开火。新动作资格与验证见33，不增加无限射界、瞬时命中或EVE式多目标锁定。

星图按原冻结数据库的 `sector_defs`、`risk_zone_defs`、`gate_endpoint_defs` 等定义绘制十星系和真实连接，展示风险、空间站、势力及产出。图形布局是示意，不能替代航门连接或成为任意跨系传送入口。

## 5. 数据库版本、运动与存档契约

### 5.1 独立规则扩展

原 `catalog.db`、旧资源清单与存档内冻结内容不变。本轮新增只读 `local_navigation_v1.db`，元数据规则版本为 `local-navigation-v1`、SQLite `user_version=1`；明确作为**独立的玩法导航扩展**，所有使用本轮导航功能的世界固定读取 v1。它不冒充旧核心规则中的已冻结行为，也不写入旧核心定义或另造 JSON 存档。

SQL 为规则来源，生成库为运行时权威；`local_navigation_v1_manifest.json` 仅记录该数据库的版本、用途和摘要，不存另一份平衡数值。规则库缺失、版本或完整性不符时显式禁用导航并报告原因，不能回退到脚本常量。未来修改导航平衡必须产生新版本并明确旧世界的兼容策略，不覆盖 v1 即声称旧存档规则未变。

### 5.2 保存与模拟边界

充能、跃迁、接近、环绕属于瞬态控制过程；当前版本不在中途保存控制器任务。活动导航中的普通手动、快速、自动保存请求延后，并向玩家说明原因。停止或到达后保存原完整舰船姿态、速度和世界进度；重启恢复稳定端点，控制器为 idle，不从途中续演一次未提交指令。

退出或返回首页时先取消导航并停止，再按原快照业务保存；源快照提交和到达保存都走真实 Store。到达回调延后至物理步完成，再校验目标、控制器代次与保存/停靠资格，防止同一物理步后半段产生伤害或设备状态变化。自动保存请求不能把“已到达”显示成“已写入数据库”；提交失败须保留可恢复的已提交快照并给出错误。

每帧仅一个运动拥有者：Main 在活动导航时调用控制器 `tick()`，不再调用一次普通 `flight.simulate()`；普通接近、环绕在控制器内调用同一物理飞行接口。规则在配置时读入，不逐帧查 SQLite。暂停不推进世界、AI、设备或导航。
