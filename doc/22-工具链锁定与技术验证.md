## 2. 下载验证与依赖保留

四个官方包均核对 SHA-256，摘要写入锁文件。Godot/插件采用官方 GitHub release asset digest，Blender 采用官方发布目录校验文件。安装前解包检查结构；Godot 和 Blender 原应用通过 `codesign --verify --deep --strict`。正式插件的逐文件摘要在 [godot-sqlite-v4.9.sha256](../code/third_party/godot-sqlite-v4.9.sha256)。

插件原生二进制未修改，只裁掉非目标平台文件并相应缩小 `.gdextension` 库登记；原始许可证和脚本保留。Mac framework 实际含 arm64/x86_64，Windows DLL 是 PE32+ x86-64。源包下载、解包和试验导出均在 `jiaoben/tmp/`，不进入正式资源。完整导出模板包约 1.28 GB，实际只安装所需桌面条目。

辅助入口：[下载校验](../jiaoben/verify_toolchain_downloads.py)、[插件整理](../jiaoben/vendor_sqlite.py)、[模板安装](../jiaoben/install_desktop_templates.py)。它们依赖本轮下载的官方元数据/包；缓存可删除，重新执行安装前应再次取得同版本官方文件，不把缓存存在视为信任依据。

## 4. 导出与本机发现的问题

Mac 使用 Godot 导出中的系统 `codesign`（值3）、identity `-` 的免费 ad-hoc 本地签名，关闭 notarization。它不需要付费 Apple 开发者证书；朋友通过网络接收后，系统首次启动仍可能要求用户允许，不能承诺等同公证应用的无提示启动。[Godot macOS 导出](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_macos.html)

本轮实际发现并修正：

1. 默认纹理导入开关导致 Mac 导出拒绝；正式工程和探针已同时启用 ETC2/ASTC 与 S3TC/BPTC，覆盖两个目标平台。
2. 内置 ad-hoc（值1）虽报告导出成功，但系统验证 framework 的封存资源失败。改用系统原生 `codesign` 后重新导出，深度严格校验通过，独立程序可运行。固定使用已经验证的值3；不以导出命令成功替代包校验。[Godot 固定版导出实现的工具枚举](https://github.com/godotengine/godot/blob/4.7.2-stable/platform/macos/export/export_plugin.cpp)
3. 首次 `--headless --editor --import --quit` 在导入后退出时崩溃。保留失败日志；采用 `--headless --editor --quit-after 180` 等待编辑器迭代结束，新的空缓存导入与后续导入均正常退出。尚未证明崩溃根因，当前可复现的导入流程已可用，不能把一次崩溃抹为未发生。

SQLite 3.51.0 落在官方 WAL-reset 风险版本范围内。因此首版固定 **DELETE + EXTRA、单一数据库拥有者**；本轮没有启用 WAL。以后若改用 WAL，必须先更新或验证已回补的原生库。[SQLite 官方说明](https://www.sqlite.org/wal.html#walreset)

## 5. 可重复执行入口

以下在工作区根目录运行。`run_godot.sh` 核对固定完整版本；其它机器可用 `GODOT_BIN` 指向已安装的同版本可执行文件。无参数会打开正式工程编辑器；当前尚无可玩主场景。

```sh
sh jiaoben/check-env.sh
sh jiaoben/run_godot.sh --headless --editor --path code --quit-after 180
/usr/local/bin/python3.14 jiaoben/prepare_godot_probe.py
sh jiaoben/run_godot.sh --headless --editor --path jiaoben/tmp/godot-sqlite-probe --quit-after 180
sh jiaoben/run_godot.sh --headless --path jiaoben/tmp/godot-sqlite-probe
/usr/local/bin/python3.14 jiaoben/prepare_progress_probe.py
sh jiaoben/run_godot.sh --headless --path jiaoben/tmp/godot-sqlite-probe --script res://progress_probe.gd
sh jiaoben/run_godot.sh --headless --path jiaoben/tmp/godot-sqlite-probe --export-release 'macOS Probe'
codesign --verify --deep --strict jiaoben/tmp/probe-export/mac/XingjiDatabaseProbe.app
jiaoben/tmp/probe-export/mac/XingjiDatabaseProbe.app/Contents/MacOS/XingjiDatabaseProbe --headless
sh jiaoben/run_godot.sh --headless --path jiaoben/tmp/godot-sqlite-probe --export-release 'Windows Probe'
```

探针准备脚本生成独立工程与导出预设；[prepare_progress_probe.py](../jiaoben/prepare_progress_probe.py) 另复制正式SQL并生成测试专用完整初始夹具，由 [progress_probe.gd](../jiaoben/probes/godot_sqlite/progress_probe.gd) 验证原生兼容。专用 app_userdata 符号链接把测试进度实际放到；若已有不同目标或真实用户目录则拒绝覆盖。正式游戏使用自己的 `user://database/`，不复用探针目录。Mac 应用试验导出到，Windows 到 `windows/`。

建模/渲染探针源文件：[Blender 导出](../jiaoben/probes/blender_export.py)、[轴向检查](../jiaoben/probes/godot_sqlite/pipeline_probe.gd)、[渲染场景](../jiaoben/probes/godot_sqlite/render_probe.tscn)。这些含测试专用固定几何/粒子数，仅用于验证技术能力，不是游戏数值源。
