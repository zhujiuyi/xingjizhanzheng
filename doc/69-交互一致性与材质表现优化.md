# 交互一致性与材质表现优化

2026-10-14。接续0.32.1视觉样式整改，按用户要求审核全部功能的同类交互与界面逻辑，并优化模型材质、几何表面和特效。本文先记录已确认问题与实施标准，完成后补实际验证及交付身份。

## 同类操作的统一规则

覆盖28个命名页面及飞行页。选择只改变当前选择，显式操作才提交；数量先校验正在编辑的文本，再更新报价/资格并提交；页面变更后旧控件不能向新世界提交；刷新保留仍有效的焦点/数量/滚动。定位和前往含义固定，禁用时说明真实阻碍；撤回/放弃等操作说明后果。各功能自己的资格、收费、数量范围和阶段约束仍由数据库与业务服务决定。

| ID | 原问题与证据 | 修复标准 |
| --- | --- | --- |
| IX-01 | 仓储先apply再检查；承运、专精、工程直接读取SpinBox缓存value，和市场/工业主列表的raw校验不同 | 共享整数解析与变化监听；非法/越界/未提交文本均有一致结果，固定单件动作不依赖别处数量 |
| IX-02 | 工程资格按固定1份；边疆补给/调度未带当前数量检查 | 使用实际输入并调用现有quantity_reason/带数量reason，提交前复查 |

## 模型与材质问题

按当前目录枚举18舰、8种矿体、站/门/残骸、机库/人物/服务机、工程/干扰器/探索障碍以及武器与辅助机。不能沿用仅9基础舰的Factory.SHIPS作为完整资产清单。当前Main通过civilization_hangar覆盖9种文明舰，不将基类9舰入口误报为实际缺失。

| ID | 已确认问题 | 实施方案 |
| --- | --- | --- |
| RV-01 | 工业shader把裸金属、漆、凹槽统一高粗糙度并压暗色彩，反射层次消失 | 独立裸金属/涂装/氧化/玻璃/陶瓷/衣料角色；分开金属度、粗糙变化与微法线 |
| RV-02 | 矿体母岩复用metallic=.75材质，晶脉高饱和强发光 | 母岩改非金属、岩粒与裂隙微结构；晶体独立较低粗糙度与克制发光 |
| RV-03 | 机库只有固定环境色和多色灯，没有有效室内反射形状 | 新机库子类使用真实静态机库六面捕捉的Cubemap，动态舰体/人物不进入捕捉；低档使用中性Sky。原生测试发现锁定引擎实时probe泄漏，已改为离线捕捉 |
| RV-04 | 38个GLB主要是纯色PBR；通用旧颜色纹理含锈迹/铆钉，法线与粗糙度缺少独立细节 | 新表现包使用尺度明确的微结构；不修改旧纹理或伪称既有模型已有完整贴图 |
| RV-05 | 文明外挂、工程、干扰器、无人机由锐边盒组成 | 视觉盒替换倒角几何副本，保持尺寸/AABB、变换及材质分面；增加真实边缘高光，不改物理结构 |
| RV-06 | 门、矿、残骸和程序模型缺少统一材质入口；material_override会盖过逐面覆盖 | 共用对象适配入口，正确处理总材质优先级，覆盖所有实际生成路径 |
| RV-07 | 爆炸、火花、引擎以发光低面数球显示，能量壳/光束轮廓明显 | 独立特效façade：柔边粒子、分层核心/晕光、衰减；动能弹头使用受光金属，不把所有物体做成自发光球 |
| RV-08 | 材质、灯光、FX容易在展示与真实世界两套入口中漂移 | 统一实际入口、记录类别/材质/几何和构图；比较受控场景与真实机库/飞行两组图 |
| RV-09 | 修改前原生矿石图确认母岩为粗大金属折面，矿脉是突出的金色长方体条，单改材质不能消除积木轮廓 | 非晶体矿石以2048三角不规则岩体替换显示网格，使用实际变形面梯度法线与岩粒，矿化纹贴于表面；初版512三角在原生图仍显大三角面，已继续修正。保留晶簇类别的晶体几何，只优化母岩。整块Model聚合AABB、根姿态、碰撞/锚点及旧GLB字节保持；逐旧Mesh的包围、表面数和拓扑允许变化并记录来源，不以隐藏旧几何伪造包围不变 |

物理依据采用Godot的金属/粗糙度工作流和反射探针；反射高光随视角和环境变化，不用提亮所有表面伪造金属感。[Godot材质说明](https://docs.godotengine.org/en/4.4/tutorials/3d/standard_material_3d.html) · [反射探针](https://docs.godotengine.org/en/4.4/classes/class_reflectionprobe.html)。这些是渲染方法依据，不是未经运行验证的效果保证。

## 资产与验证边界

`art-full-v2`及其旧manifest签名文件保持原字节，特别是runtime/visuals下已签名工厂、特效实现/节点/shader，以及被航行清单签名的station_hangar.gd。新材质/几何/特效放独立表现包，通过新rendering适配器与机库子类接入；碰撞、挂点、镜头/交互锚点、原GLB/wrapper及所有数据库数值/存档身份保持。程序视觉盒倒角允许改变视觉三角形和法线，不能改碰撞或AABB。

先保存旧版原生基线。受控材质图保持相同相机/灯光/姿态；真实机库新增反射时记录环境差异，不冒称只改材质。原生检查使用fresh UUID测试库和共享锁；校验状态/RNG、材质覆盖、碰撞/挂点、特效寿命/暂停/清理/预算、品质档位、实际界面交互与性能采样。截图、日志、临时数据留jiaoben；旧测试的10星系/旧HUD/旧hash假设不能直接当当前验收门槛。

## 实际结果

反射方案的实测修订：独立base/low/high机库进程中，仅实时ReflectionProbe的high出现7个Texture RID泄漏，日志为`hangar-lifetime-{base,low,high}.log`；与[Godot上游122498](https://github.com/godotengine/godot/issues/122498)一致。离线原生捕捉六面256×256静态房间并生成mipmap后，`hangar-lifetime-baked-high.log`退出0、无诊断。此固定LDR环境反射保留视角相关的高光，不承诺动态物体反射、实时视差或HDR照明捕获。

用户随后明确要求重做所有舰船，范围扩展为18目录舰与特殊敌舰共19套原创模型，接线和验收见[70](70-舰船造型重建.md)。旧GLB/wrapper作为兼容资源保留，实际显示改为独立`ship_v4`包；不再把仅调整旧舰材质作为舰船造型交付。
