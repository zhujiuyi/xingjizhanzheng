# 星际战舰 · EVE 参考与原创边界

版本：v0.2，第一版完整设计的研究来源。核验日期：2026-10-02。

本文用于说明第一版设定参考了哪些 EVE 机制、如何改造及哪些内容不采用。官方事实与本项目提案分列；右侧的原创设计仍需通过原型与试玩验证。完整设计范围涵盖星系分工、势力科技、工业、经济、探索、任务、战斗与成长，制作按批次推进；不能用最小原型代替完整世界蓝图。本文不代表已经实现这些功能。

## 已确认的项目边界

- 《星际战舰》是供自己和朋友私下游玩的 3D 独立客户端游戏，目标为 macOS `.app` 与 Windows `.exe`。
- 玩家操作不同样式、类型和功能的舰船，进行探索、采矿、战斗与任务活动。
- 飞行、战斗、镜头切换以及穿梭器虫洞穿越需要有可辨识的视觉表现。
- 技术栈已确认采用 Godot 4、GDScript、Forward+ 与 Blender，不使用需要收费授权的技术栈。
- 存档、读档和游戏数值由数据库承载；这些要求来自本项目，不能从参考游戏的客户端表现推断其内部实现。
- 原创世界暂命名为“断航星域”；原创势力为航路议会、深铸联合体、游弋同盟与静默遗构。它们不是 EVE 势力的替换名称，历史、目标与美术需要独立设计。
- 多星系具有不同产出与工业侧重，势力具有不同武器、防御、推进、传感和制造能力。固定跨星系主航线是“锚定虫洞传送门”，可选临时探索路线是“游离虫洞”；不存在不经门的自由跨星系飞行。权威表见 [星系与势力科技设定](12-星系与势力科技设定.md)。
- 使用高、中、低安全区和差异化 NPC 强度；等级范围、难度和危险任务预警属于本作原创数据规则，不等同于 EVE 的高安全、低安全、零安全体系。

## 机制参考与改造映射

| 主题 | 已核验的官方事实与来源 | 建议借鉴的设计关系 | 《星际战舰》的原创改造及范围削减 |
| --- | --- | --- | --- |
| 职业与活动 | EVE Academy 将探索、工业、任务战斗和玩家战斗列为不同活动方向；任务也包括战斗、采矿、配送。[EVE Academy](https://www.eveonline.com/eve-academy) | 不同活动需要不同舰船与装备；活动之间可以形成资源与需求链。 | 玩家是一名独立舰长，可在探索、资源生产、护航和战斗间切换。首版以任务驱动的小型闭环串联这些活动，不建设完整 MMO 职业生态。 |
| 区域风险 | EVE 的星系安全类别区分高安全、低安全与零安全，安全类别参与游戏机制。[System Security](https://developers.eveonline.com/docs/guides/system-security/) | 出航前需要权衡路线、风险与预期收益。 | 使用原创“高安全、中安全、低安全”及独立的发现、资源与航道稳定度属性。风险来自 NPC 等级、战术、环境和撤离难度；不直接搬用安全数值阈值、执法计时器或主权规则。 |
| 星区内与星区间出行 | EVE 官方设定区分星系内跃迁、星门出行与虫洞出行；星门使没有跳跃引擎的舰船能够进行星际旅行。[Ship Technology](https://universe.eveonline.com/lore/ship-technology) | 战术移动、长距离赶路与跨区旅行承担不同节奏与风险。 | 星区内采用常规飞行与受限巡航；跨星系固定主航线采用锚定虫洞传送门，游离虫洞作为可选临时路线。星区分批加载，不以连续飞行绕过门网络。 |
| 虫洞限制 | EVE 虫洞是随机、短寿命的星系连接，需要扫描发现；单次通过质量与累计通过质量均可能受限，寿命或质量耗尽会导致坍塌。[Wormholes](https://support.eveonline.com/hc/en-us/articles/203209772-Wormholes) | 通道不是永久免费的捷径；侦察、船型与返程准备具有价值。 | 原创虫洞由断航星域的“裂隙”产生，扫描后取得临时航道信息；通道设通行等级和稳定度。首版采用清楚的容量提示与任务可控的关闭时机，不要求玩家掌握隐蔽的质量计算。 |
| 扫描探索 | EVE 区分可直接定位的异常与需要探针定位的宇宙信号；扫描工具用于查明隐藏地点。[Scanning](https://support.eveonline.com/hc/en-us/articles/203209902-Scanning) | “看见疑似信号”与“获得可靠位置”分开，专业探索船能缩短调查过程。 | 采用方向扫描、靠近复扫、识别信号、确认导航点的流程。首版不复制完整三维探针阵列操作；保留信号强度、干扰、扫描距离与发现记录。 |
| 采矿、加工与制造 | EVE 矿石可加工为制造材料；不同地点的资源不同，专用采矿舰拥有采集与矿舱优势。[Introduction to Mining](https://support.eveonline.com/hc/en-us/articles/23655785488668-Introduction-to-Mining) | 采矿是制造和换装的来源，不只是独立刷钱；矿种分布使探索与运输有意义。 | 使用原创矿种、材料与制造配方；首版建立少量矿石到舰船模块的链条。矿舱、采集耗能与返航风险保留，月矿、气体、冰矿及复杂工业工序按实际开发能力后置。 |
| 运输与护航 | EVE 官方舰船设定将工业舰定位为星际运输工具，区别于各级战斗舰。[Ship Technology](https://universe.eveonline.com/lore/ship-technology) | 高运量通常意味着较差机动或自卫能力，运输能产生护航需求。 | 原创运输舰重视货舱、装卸和航程，战斗舰重视武器与防御；首版以 NPC 配送、护航合同验证分工，不要求全服市场和玩家物流网络。 |
| 舰种与能力 | EVE 舰船包含小型护卫舰、驱逐舰、多用途巡洋舰、工业舰和更大型战舰，各有用途；巡洋舰可承担多种专业角色。[Ship Technology](https://universe.eveonline.com/lore/ship-technology) | 舰船差异应同时体现在体量、操控、装载、配装与任务能力。 | 原创舰系按穿梭、探索、采矿、运输、护卫和重型战斗等角色组织。首版先实现少数能力差异明显的舰体，大型舰种保留为后续内容；不把更大的船简单设计为全方面更强。 |
| 模块配装 | EVE 配装受槽位、武器挂点、电网与 CPU 等条件限制，可查看配装后的属性。[Fitting Window](https://support.eveonline.com/hc/en-us/articles/213287845-Fitting-Window) | 舰体提供基础能力，模块改变用途，但装配容量限制迫使玩家取舍。 | 使用原创的武器、设备、防御与核心槽，加上功率、算力和质量预算。安装时即时显示速度、耗能与防御变化；首版限制模块数量和修正关系，避免繁杂叠加规则。 |
| 防御与能量 | EVE 配装属性包括护盾、装甲、结构及各层抗性，并展示电容容量、回充与模块耗能。[Ship Attributes](https://support.eveonline.com/hc/en-us/articles/213287965-Ship-Attributes-in-the-Fitting-Window) | 生存与输出依赖多种资源，不能只比较一个生命值或伤害值。 | 使用护盾、装甲、舰体三层状态及能源储备；武器、推进、扫描与护盾修复争用能源。首版伤害类别、抗性种类及主动模块保持少量，先让取舍和界面提示清楚。 |
| 战斗与损失 | EVE 的击毁记录涵盖被玩家或 NPC 击毁的舰船；官方保险说明区分船体与模块、货物等损失。[Killmails](https://support.eveonline.com/hc/en-us/articles/11730655033884-Killmails)、[Insurance](https://support.eveonline.com/hc/en-us/articles/212726885-Insurance) | 舰船与货物的损失赋予返航、撤离和备用舰价值。 | 第一版提案采用可修复损伤、部分货物风险和脱离战场机制；永久损失及朋友间 PvP 的惩罚强度待试玩决定。不得把 EVE 的高损失机制直接当作已确认需求。 |
| 成长与经济 | EVE Academy 介绍了按时间获得技能点、不同账号状态与游戏货币的体系。[EVE Academy](https://www.eveonline.com/eve-academy) | 解锁内容可以引导玩家逐步学习新模块与新舰种。 | 使用任务、探索资料和资源投入来解锁内容；不采用订阅状态、付费货币、现实时间训练或数百项技能作为首版门槛。 |
| 蓝图与研究 | EVE 蓝图体系区分不同类型及用途，制造、研究、复制和发明围绕蓝图组织。[Blueprints](https://support.eveonline.com/hc/en-us/articles/203269951-Blueprints) | 科技来源、制造许可和实际物资是不同条件，探索可以产生工业研究价值。 | 原创蓝图、资料和制造许可解锁专业科技；按阶段开放研究与先进配方。先不复制完整原件/拷贝/发明规则和精确效率公式。 |
| 制造设施与生产 | EVE 制造将材料、组件和蓝图转换为新物品，并受到材料位置、设施与成本等条件影响。[Manufacturing](https://support.eveonline.com/hc/en-us/articles/203210292-Manufacturing) | 原料、设施与成品的空间位置形成运输需求，制造并非只有一张配方。 | 不同星系有特色工艺和服务；蓝图、材料、队列和成品交付形成完整工业链。早期可以即时加工，完整设计保留生产订单和跨区供应。 |
| 声望与服务 | EVE 的 NPC 声望影响任务代理可用性，并可因任务和阵营行为变化。[Standings](https://support.eveonline.com/hc/en-us/articles/203217152-Standings) | 玩家行为可改变势力关系与任务、商店或服务资格。 | 原创关系和贡献解锁合同与科技；提前展示行为后果。基础通行、补给和返程保留恢复途径，不照搬声望门槛、损失公式或拒绝任务惩罚。 |
| 势力兑换与特色物品 | EVE 的忠诚点可由活动取得，并用于相应组织的特色物品和服务兑换。[Loyalty Points](https://support.eveonline.com/hc/en-us/articles/14141831188636-Loyalty-Points) | 不同势力奖励有用途差异，做什么任务影响能够获得什么产品。 | 使用贡献、任务许可与研究进度表达资格，货币统一为航路信用点；跨势力采购、贸易与代替配方防止特色科技形成永久进度锁。 |
| 市场与订单 | EVE 市场用买单、卖单和撮合规则组织交易，物品与订单具有地点条件。[Buy and Sell Orders](https://support.eveonline.com/hc/en-us/articles/203218932-Buy-and-Sell-Orders) | 地方库存、需求与生产差异形成贸易路线，价格信息具有价值。 | 先有可查询的 NPC 库存、价格、补货与采购订单，再按实际需要开放有限区域供需；不先建设万人撮合市场或全服实时金融系统。 |
| 残骸与回收 | EVE 回收模块或无人机可从可回收残骸中取得组件，回收与拾取残骸中的货物是不同操作。[Salvaging](https://support.eveonline.com/hc/en-us/articles/213014209-Salvaging) | 战斗产物进入制造链，探索、战斗与工业相互支持。 | 区分战利品货物和拆解产物；残骸有有限资源，领取和回收状态持久化。归属与朋友协作规则明确，首轮不复制复杂偷窃与执法计时体系。 |
| 协作目标 | EVE 团体项目可围绕交货、制造、扫描、采矿、回收、击毁与远程修理等活动分配贡献与奖励。[Corporation Projects](https://support.eveonline.com/hc/en-us/articles/9583433729308-Corporation-Projects) | 不同角色对共同目标提供不同贡献，支援和工业可与作战一样获得明确回报。 | 原创任务和合作目标承认护航、修理、运货、扫描与作业贡献；单人可由 NPC 协作完成。朋友联机的权威和人数另行确定，不以大型联盟政治作为前提。 |

上述映射是目前有官方证据的研究目录，不声称穷尽 EVE 的全部机制。完整活动设计还需检查武器与射程、锁定与电子战、无人机、热量、支援、基地服务、任务链、损失恢复、区域事件和成长之间的关系；对应本项目方案由 [玩法设定](09-玩法设定.md) 及活动系统文档维护，按成熟机制逐项评估后分期实施。

## 穿梭器与虫洞的定义

EVE 的穿梭艇、星系内跃迁、星门和虫洞不能混成同一个概念。官方材料支持“不同出行机制并存”以及“虫洞具有发现和通行条件”，并不说明所有舰船都由穿梭艇带着穿越，也不说明穿梭艇负责生成虫洞。[Ship Technology](https://universe.eveonline.com/lore/ship-technology)、[Wormholes](https://support.eveonline.com/hc/en-us/articles/203209772-Wormholes)

本项目把“穿梭器”定义为**玩家可驾驶的轻型航行器**，擅长侦察裂隙、校准出口和快速通行。其他舰船可否通过，由门或航道等级、舰船规模与已安装的通行设备决定。固定主航线经锚定虫洞传送门，游离虫洞可选；穿梭器不会创造任意出口。穿梭器如何帮助重型舰船通行、是否搭载于大舰内部属于本项目待验证的设定，不是 EVE 官方事实。

虫洞穿越的蓄能、入口旋涡、隧道星光、出口闪光和镜头回位是本项目的演出设计。演出应服务于通行状态与星区加载，不能替代实际航道判定、资源扣除、保存与失败恢复。

## 舰船样式的原创方法

参考 EVE 的重点是“角色能从舰船外观与操作中被感知”。本文不提供原舰轮廓复刻、专有舰名替换或 EVE 美术资源使用方案。原创设计先从用途出发：

| 原创角色 | 建议轮廓与可见设备 | 要表达的操作感 |
| --- | --- | --- |
| 穿梭器 | 紧凑主舱、外置稳定环、小型定向推进器；艏部有裂隙校准组件 | 快速转向、低载荷，穿越前设备有可见响应 |
| 探索舰 | 清晰的传感器桅杆、可展开扫描翼、较小武装区 | 观察与隐蔽优先，扫描过程可读 |
| 采矿舰 | 多臂采集架、矿仓、输送管路，工作侧与推进侧分明 | 作业效率高，采集中机动受限 |
| 运输舰 | 大体积货舱、标准化货箱固定点、集中的推进组 | 载重明显，满载与空载操控有差别 |
| 护卫舰 | 紧凑装甲、可识别的武器轴线、宽分布姿态喷口 | 中近距离战斗，操控反应明确 |
| 重型战舰 | 厚重中心结构、大型武器基座、明显的能源与散热部件 | 加速和转向较慢，攻击有准备与释放过程 |

航路议会、深铸联合体与游弋同盟的样式区别需要由各自的生产条件、组织目标与舰船用途产生。静默遗构的视觉应来自其原创技术与运行方式；不指定其与 EVE 某个势力一一对应。

## 第一版不引入的范围

- 全服持久世界、千舰会战、领土主权争夺和大型联盟政治。
- 玩家控制整个市场价格的经济模拟、跨服交易、现实货币兑换或付费成长。
- 离线数天训练技能、复杂多账号经营及长期等待作为主要成长方式。
- 完整复制的装配分类、抗性矩阵、舰船族谱、虫洞编号与精确数值。
- EVE 的专有世界、角色、阵营名称、故事文本、音效、模型、舰船外形与界面布局。

这些边界用于控制开发规模，不能将完整设计收缩为只实现少量示例。原创制造、贸易、研究、势力关系、区域活动与舰队协作纳入完整蓝图，按分期落实；联机人数、PvP 开关和永久损失仍以本项目设定与技术文档为准。

## 数据与后续设计的约束

参考机制进入实现前，应转化为本项目的数据库定义，例如舰种与舰体、模块、槽位规则、伤害类别、矿石、配方、区域风险、任务和解锁条件。玩家当前舰船、货物、损伤、发现记录和任务进度属于存档状态，同样通过数据库持久化。

不导入 EVE 的数据表、舰船数值或世界数据库作为本游戏内容。能力与损失规则先在文档中提出，再由原型验证后形成自己的数值版本；素材、场景与着色器仍按工程职责存放，不把数据库要求扩展成所有资源都必须塞入数据库。

本文来源均为 EVE 或 CCP 官方站点，正文以概述为主，不大段引用。来源描述的是核验日期看到的机制；后续若依赖具体行为，需再查官方说明和实际版本。本文不对任何复用方式作法律结论。
