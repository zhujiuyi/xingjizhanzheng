# 星际战舰 · 技术栈与空间玩法建议

日期：2026-10-03 更新。用户已确认技术栈；工具链已安装并通过数据库/渲染/导出探针，见 [22](22-工具链锁定与技术验证.md)。操控与正式游戏效果尚需编码及试玩，首版可执行参数和资源接口见15、19–21。

## 选型结论

采用 **Godot 4 标准版 + 有类型标注的 GDScript + Forward+ 渲染 + Blender**。游戏逻辑、界面、空间音频、粒子和着色器优先使用引擎内置能力；模型使用 Blender 制作，以 glTF / GLB 导入。安装时核验当前稳定版本，并结合数据库扩展的兼容要求固定编辑器、扩展与导出模板版本。

这是结合项目规模和开发成本作出的工程建议。官方文档已确认相机、粒子、着色器及桌面导出能力；具体画面品质、帧率和联机表现尚未经本项目实测。

## 已确认约束

- 3D 星际探索、采矿与战斗，操作不同类型、功能和外观的舰船。
- 提供 macOS `.app` 与 Windows `.exe` 独立客户端。
- 只供自己和朋友玩，不公开发行；不安排付费发行证书或公证服务。
- 控制开发成本，不采用需要收费授权的技术栈。
- 需要考虑飞行操作、飞行视角、穿梭器虫洞穿越、舰船战斗特效与视角转换。
- 朋友电脑主要是 Apple Silicon Mac 或近几年带独显的 Windows 电脑。
- 保存、读取存档及所有游戏数值必须使用数据库；多星系、势力科技差异、安全区与 NPC 等级进入整体设计。
- 当前开发机实测为 Apple M1 Pro，16 核 GPU、32 GiB 内存。这支持优先尝试桌面渲染方案，但不代表实际游戏性能已验证。

## 建议的技术组合

| 职责 | 选择 | 原因与范围 |
| --- | --- | --- |
| 游戏引擎与编辑器 | Godot 4 标准版 | MIT，免费使用，无引擎销售分成；提供场景、输入、物理、界面、音频和导出工具 |
| 玩法代码 | 有类型标注的 GDScript | 与引擎节点和资源直接配合，缩短原型迭代；先不引入 .NET 或原生编译工具链 |
| 3D 渲染 | Forward+ 优先验证 | 面向目标桌面硬件，支持所需粒子拖尾与后处理；实际默认画质由样例决定 |
| 原画、模型与资源 | Blender + 自制/程序化资源 | Blender 无软件授权费；先做可辨认的舰船轮廓，再细化材质和细节 |
| 模型交换 | glTF / GLB | 保留 Blender 源文件，明确导出模型边界；减少游戏导入对建模软件的隐式依赖 |
| 特效 | Godot Shader、GPUParticles3D、发光材质 | 喷焰、弹道、护盾、爆炸、虫洞和跳跃效果按同一管线制作 |
| 界面与音频 | Godot Control、内置音频总线与 3D 音源 | 先不依赖付费 UI、音频中间件或素材生成服务 |
| 版本与发布 | Git、Godot 标准导出模板 | 在 Mac 导出两个平台的原型包；Windows 运行另在 Windows 实测 |
| 数值与持久化 | SQLite + 免费 Godot 数据库扩展 | 配置数据库维护游戏数值，进度数据库管理事务化存读档；扩展与平台二进制兼容性须实测 |
| 联网（如确认需要） | Godot 高层多人 API + ENet | 可由一名玩家充当房主；玩家数量、同步方式和网络接入仍需另定 |

Godot 使用 MIT 许可，游戏可保持自己的许可；随客户端保留引擎及相关第三方许可说明。Blender 的 GPL 约束软件本身，不要求用它制作的模型或游戏公开源码。[Godot 许可](https://godotengine.org/license/)、[Blender 许可](https://www.blender.org/about/license/)

软件授权费可以为零；开发时间、硬件、已有 AI 工具用量或将来的托管费用仍是独立成本。新增资源和插件先核验许可证，不将收费云服务作为构建或运行的必要依赖。

## 舰船操作与视角

以下保留玩法方向与选型理由；首版具体输入、动作和恢复规则现以 [实现契约](17-首版行为与实现契约.md) 为默认基线，最终手感通过样例调整：

| 场景 | 操作与镜头建议 |
| --- | --- |
| 日常飞行 | 第三人称跟随为默认；鼠标自由环绕、滚轮缩放，便于观察舰船与周围环境 |
| 战斗 | 可锁定目标，通过镜头构图尽量同时呈现己舰与敌舰；手动环绕仍可用 |
| 船头观察 | 提供前向视角；完整可操作驾驶舱后续按美术工作量决定 |
| 战术观察 | 拉远观察局部战场；星图作为独立导航界面，避免依靠极远相机展示整个宇宙 |
| 虫洞穿越 | 临时进入穿梭镜头序列，穿越后恢复原来的玩家镜头模式 |

飞行优先采用可调惯性、推进、转向与辅助稳定的操作模型。小型穿梭器灵活，大型战舰通过质量感、加速度和转向速度体现差异；是否采用完整六自由度及具体鼠标控制方案，在操控样例中比较。

相机与舰船操控分离，集中管理跟随、环绕、战斗和穿越状态。切换时平滑改变位置、朝向和视野角，保持同一舰船运动状态；震动和视野变化提供强度设置。默认使用一个主游戏相机，驾驶舱监视器等确需第二画面的功能再增加独立视口。

Godot 的 Camera3D 与 SpringArm3D 可实现跟随、环绕和碰撞避让；平滑切换由插值或 Tween 编排。[官方第三人称镜头示例](https://docs.godotengine.org/en/stable/tutorials/3d/spring_arm.html)、[Camera3D](https://docs.godotengine.org/en/stable/classes/class_camera3d.html)、[Tween](https://docs.godotengine.org/en/stable/classes/class_tween.html)

## 虫洞与战斗效果

以下效果组合属于制作建议，需开发后检查观感与性能：

| 表现 | 制作方式 |
| --- | --- |
| 引擎喷焰 | 发光喷口、粒子喷流和拖尾；强度随推进状态变化 |
| 虫洞入口 | 旋涡网格与噪声着色器、发光边缘、局部粒子和空间音效 |
| 穿越过程 | 蓄能 → 进入 → 隧道/星光拉伸 → 出口；适度屏幕扭曲与视野变化掩护目标星区加载 |
| 激光与炮弹 | 发光光束或投射物、轨迹、命中闪光与声音；命中判定独立于视觉效果 |
| 护盾命中 | 护盾表面局部波纹或闪光，表现受击方向 |
| 爆炸与受损 | 分层粒子、少量碎片、短暂闪光和镜头反馈；按距离简化或关闭细节 |

GPU 粒子拖尾、Glow 和屏幕读取着色器支持这些组合的基础能力。屏幕纹理在透明物体绘制前复制，扭曲不能默认正确合成全部透明粒子；虫洞和多层爆炸需检查绘制顺序，必要时使用独立视口或调整合成方式。[GPUParticles3D](https://docs.godotengine.org/en/stable/classes/class_gpuparticles3d.html)、[屏幕读取着色器](https://docs.godotengine.org/en/stable/tutorials/shaders/screen-reading_shaders.html)

## 宇宙组织与性能

建议采用 **星图 + 分星区场景 + 虫洞/跳跃衔接**。当前星区使用靠近原点的局部坐标；全局记录星区标识与连接关系。穿越时加载目标星区并释放不再需要的内容，不把真实天文距离直接写入单个 3D 世界。这能降低坐标精度、加载和内容制作负担。[Godot 大世界坐标说明](https://docs.godotengine.org/en/stable/tutorials/physics/large_world_coordinates.html)

用户已明确跨星系需通过特定虫洞传送门：固定锚定虫洞门是主航线，游离虫洞是可探索的附加通路。星系、安全区、势力、产出、NPC 和连接定义入库，整体规则见 [世界观](07-世界观设定.md) 与 [星系科技](12-星系与势力科技设定.md)。

主样例先验证 Forward+。如果实测不合适，再比较 Mobile 渲染器或降低效果预算；Mobile 也能用于桌面。Compatibility 不支持 GPU 粒子拖尾，切换它需要准备效果替代并复测，不能视作相同画面的免费性能开关。当前官方稳定版表格显示三个渲染器均支持 Glow。[渲染器功能比较](https://docs.godotengine.org/en/stable/tutorials/rendering/renderers.html)

- 画面建议走科幻半写实方向，先靠舰船轮廓、金属材质、灯光和武器辨识度建立效果。
- 粒子数量、透明叠层、动态灯光、阴影和屏幕扭曲分别设预算，不让每发炮弹都产生带阴影光源。
- 体积雾等高级效果作为可选增强，核心虫洞与战斗演出不依赖它们。
- 建议以 1080p、60 FPS 作为首轮验证目标；这是待验收目标，不是当前性能结论。原生 Retina 分辨率另测。

## 朋友试玩与联机边界

私下分享客户端不需要购买公开发行用证书。macOS 导出可用 Godot 内置 ad-hoc 签名并关闭公证；朋友首次打开下载包可能仍需在系统设置中允许打开。[macOS 导出](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_macos.html)

用户已确认先做单人闭环，保留联机数据与接口。后续如开放同场联机，可验证朋友开房的 ENet 方案；局域网不需要付费后端，互联网直连则受 NAT、UDP 端口和公网条件影响。是否需要虚拟局域网、中继或托管服务器，届时按实际接入条件决定。[高层多人 API](https://docs.godotengine.org/en/stable/tutorials/networking/high_level_multiplayer.html)

## 第一轮验证与后续行动

按已有安装授权核验并安装 Godot、匹配导出模板、SQLite 扩展及 Blender；正式工程放 `code/`，样例检查、截图、日志和临时导出放 `jiaoben/`。

建议先验证一艘战舰、一艘穿梭器、一个敌方目标和两个简化星区，覆盖：

1. 操控与第三人称、自由环绕、战斗视角的切换。
2. 从一个星区穿过虫洞到达另一个星区，并恢复镜头。
3. 喷焰、发射、命中、护盾和爆炸的完整表现。
4. 开发机与朋友目标电脑的帧率、内存和输入体验。
5. 两平台导出与真实启动，确认客户端可独立运行。
6. 配置数据库加载、原子保存、退出后读取、奖励与库存一致性、失败回滚和版本迁移。

这些通过后再扩充采矿、任务、舰船配置及联网内容。Unity 方案继续保留为历史备选；当前严格避免收费授权的选型建议以本文件为准。

## 数据库约束

数据库是存档和游戏数值的权威来源：舰船/装备属性、战斗公式系数、任务奖励、资源产率、NPC、安全区、势力科技、门容量、配方和价格均入库。内存可以缓存数据库内容，不能在脚本常量、JSON 或 Godot Resource 中维护另一套权威数值。

SQLite 以数据库文件落盘，但使用关系表、查询、约束、事务、版本和备份管理，不等同于直接序列化文件。模型、材质、音频与场景继续作为资源文件，数据库引用其标识。SQLite 扩展属于原生依赖，必须在 Mac 与 Windows 分别验证加载，详见 [数据库与存读档技术方案](10-数据库与存读档技术方案.md)。
