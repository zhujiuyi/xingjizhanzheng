# 教学采矿保障与矿点情报

v0.8.1；2026-10-03；源码采矿专项、真实存读档、原生界面及实际Mac Release检查通过。交付构建为`0.8.1-21368d9d-20261003-192837`，源身份和验证见[26](26-开发阶段与交付记录.md)。Windows 实际包此后已交付并原生验收；历史T2通关不能替代本轮保障检查。

## 1. 问题与范围

矿点交互预览原先查询不存在的 `resource_node_state`，实际持久表为 `resource_state`；有矿也可能被误报耗尽。本轮统一从实际资源DTO和当前世界冻结定义读取矿点情报，并使远距离选中矿点时可以查看余额、容量、教学预留和再生倒计时。查看信息不代替实际采集资格。

另补齐T2的有限保障：真实矿池已空、教学样本损失或误归还借船时，可以继续当前教学任务；普通合同和自有采矿仍使用有限共享矿池。本轮不调整船、模块、价格、任务奖励、矿池容量或常规再生数值，不创建独立任务矿场、普通库存补发或额外信用点。

## 2. 数据库权威与预留计算

运行输入来自当前世界冻结SQLite catalog，运行结果保存在SQLite进度快照。以下是当前定义的核验值，不是第二套配置：

| 数据 | 权威定义 | 当前值 |
| --- | --- | ---: |
| T2指定采集矿点/物品 | `mission_objective_defs` 的 `collect` | `node_echo_ferrosilicate` / `ore_ferrosilicate` |
| T2采集/交付数量 | `mission_objective_defs.required_count` | 各150单位 |
| 教学借船有效样本配额 | `loan_service_defs.operation_quota_units` | 150单位 |
| 铁硅矿池容量/常规再生 | `resource_node_defs.capacity_units/respawn_s` | 3000单位 / 1200世界秒 |
| 普通采矿合同借船累计额度 | `loan_service_defs.operation_quota_units` | 600单位/attempt |

预留只适用于非重复教学任务中同时存在指定矿点采集、对应物品交付和 `gathered_policy_id=mission_bound` 借船的定义。本轮符合条件的内容是T2；普通采矿、物资合同和主线不获得教学补矿。

以数据库交付数量为 `R`、当前有效绑定样本数量为 `B`，缺额为 `D=max(0,R-B)`。`B`只统计本活跃教学实例、对应物品、玩家所有的有效绑定堆叠；包括玩家其他存活舰船和各站仓库中的样本。残骸、已毁或已归还舰船中的对象不计入。移动或拆分堆叠保留任务绑定，转仓本身不增加缺额，也不能凭借当前船舱为空重复补样。

在T2尚未一次性结算完成时，共享矿池持续保护 `min(当前余额,D)`。接取前和弃约后的 `B`为0，所以当前定义至多保护150单位；新档满池时普通采矿最多先使用2850单位。弃约清理旧绑定资产后仍保留教学保护，重接不会把此前补入的矿转为可出售的普通矿。T2成功交付、奖励已记账后解除保护。

主动补足只发生于 `active/ready` 教学实例：接任务、运行状态建立/旧档恢复、借船领取或补领，以及采矿业务启动时重新核对。如果矿池余额不足 `D`，只补到 `min(D,数据库容量)`，同时清除本次空池再生倒计时；已有足够余额时不补。它不是把3000整池恢复。对应教学借船的补采额度只恢复实际缺额所需余量，并始终受数据库150上限和有效样本数量限制；普通600累计配额不因损失、换船或读取存档恢复。

所有采集仍真实扣除同一 `resource_state.remaining_units`。普通自有舰和普通借船只能采当前余额扣除教学预留后的部分；匹配本教学实例与借船服务的舰船才能采预留部分，产出上限同时检查缺额、借船额度、容积、载重和实际周期产出。教学借船不能改采导能晶体或其他非任务矿点以消耗/补领教学额度。

## 3. 损失、转仓与结算

| 情况 | 恢复与限制 |
| --- | --- |
| 矿点真实耗尽，T2缺样 | 只保障数据库定义的当前缺额；须用对应借船真实完成采集周期，不直接给样本 |
| 样本转到回声仓库或另一艘存活舰船 | 仍计入有效样本；需取回并送至锚港交接，不能把远方样本当丢失补发 |
| 舰船损失，样本失效 | 保留本attempt及历史collect证明；失效样本不进入普通残骸，按合同补领后采未交付缺额 |
| 主动归还/受控换发借船 | 旧借船及其绑定对象先清理；当前教学未结束时可领取对应借船并补采缺额，不能保存旧对象再领取新份 |
| 弃约后重接 | 旧attempt样本失效、新实例重做有序目标；有限矿量持续保护，不转成普通商品；原已结算奖励不再领取 |
| 普通合同货物或普通借船损失 | 不教学补矿、不恢复600累计额度；按原合同通过实际残骸、购买或自有采集补货，历史采集要求仍须满足 |

T2交接仍只接受当前实例的实际绑定铁硅样本，交付来源为交接站仓库及当前受控舰船货舱；全世界有效样本统计用于防重复补样，不意味着远方仓库自动物流。普通购买库存和历史采集计数不能替代绑定交付物。已完成collect证明保留，补样不会再推进已完成目标或增加奖励；缺样时任务可保持active/ready，仍须带实物返航。

教学样本保持 `mission_bound`，不能出售、拆解、投入普通制造或兑换普通合同收入。原子交付、任务永久完成标志、实例领奖账本和action去重继续适用。持续预留、限定产物和一次性结算共同防止接取/弃约、损失/补领循环把教学补给商品化。

真实SQLite保存检查另发现样本来源写法违反既有约束：`001_core.sql` 要求 `origin_kind=mission_bound` 当且仅当任务绑定存在，`origin_kind=loan` 当且仅当借船绑定存在；两种来源互斥。采集样本只写 `mission_bound` 与当前 `bound_mission_instance_id`，不同时写 `loan_id`；借船额度继续由对应 `loan_state` 管理，借船船体/设备/补给保留各自来源。归还、弃约和受控换发按借船ID清借用对象，并按本任务实例清全部绑定样本，包括已转仓或转船的样本，避免去掉样本loan字段后漏清旧物。此次修正沿用现有DDL、来源检查及冻结定义，不新增迁移或放宽数据库约束；本轮临时SQLite保存、重开及转仓清理已通过，实际覆盖见第5节。

转仓、归还再重领的保存回归还发现旧实现为Returned合同另建loan行，违反既有 `(player_id,loan_service_id,mission_instance_id)` 唯一约束，并在内存重置普通600额度。修正后，同attempt、同服务的重领复用原 `loan_id` 和唯一loan行，追加 `issuance_count/loan_issue_state` 发行历史、创建新的船实例，保留已归还/已毁的旧记录。普通配额保留原remaining；教学仅在旧样本清理后按有效缺额恢复，仍不超过数据库150上限。Returned合同也保留并检查 `replacement_remaining_s`，不能先归还再领取绕过损毁换发冷却。新attempt按原受理规则创建新合同，不以重领伪造新的attempt或领奖资格；本轮已真实封存并查询普通重领后的唯一SQL行、额度0和追加发行历史，损毁冷却规则为源码实现事实，不将本专项解释为自然船毁试玩。

每个采集头启动新周期前检查至少能产出一个单位；双采集头逐个重新检查，第一支已填满货舱或满足任务后第二支不再支付无产出周期。周期末仍重新检查余额、容量、额度及目标资格；已支付周期的中断不返还原成本。

最后一单位采空时，已完成采集头在移出活动周期表的同一结算步骤将 `active_remaining_s` 置0、`cycle_paid` 置false，保留原冷却；随后停止采矿并登记常规再生计时。修正原先已移出周期表却遗留“未完成作业”的状态，允许在没有其他交战、弹丸或作业阻碍时立即捕获并封存SQLite快照。采矿停止提示或样本已入舱不能代替实际COMMIT成功；本轮要求单单位采空及完整T2样本都真实保存、重开核对。

## 4. 矿点界面与时间

当前星系的已知矿点可以从总览选中，远距离查看资源名称、实际剩余/容量、百分比和教学预留；左侧任务/作业提示与右侧选中卡使用同一份资源状态。F或采矿按钮只在距离、模块兼容、权限、视线、舱容、载重和可采额度满足时执行。接近/跃迁只是导航，不凭到点直接发矿。

真正余额为0时显示耗尽及世界时间再生倒计时；余额全部属于教学预留时，说明教学预留或样本已足够，不伪装成普通空池。常规采空后仍按定义1200世界秒再生；暂停和关闭游戏不推进，不按系统墙钟计算。教学接取前/弃约后只保护已有余额，不主动填矿；有预留余额的矿点不能按普通耗尽倒计时理解。

预留由当前任务、借船和堆叠DTO推导，实际补足写回现有资源余额和借船额度；它们随完整快照进入SQLite，不引入脚本平衡常量、另一个JSON/Resource存档或独立无限资源池。继续/读取后按同一已提交状态重新计算，重复检查有足够余额时不再加矿。

## 5. 实现入口与验收边界

- `code/runtime/resource_status.gd`：只读情报、有效样本计数和持续有限预留计算。
- `code/runtime/interaction_context.gd`：实际 `resource_state` 查询及执行前资格预览。
- `code/runtime/gameplay/work.gd`：教学缺额补足、匹配借船限制、真实扣矿和周期前/期末检查。
- `code/runtime/gameplay.gd`、`gameplay/missions.gd`：运行建立、受理和借船补领时保障衔接；普通再生和原领奖逻辑保留。
- `code/runtime/ui.gd`、`ui/overview_panel.gd`、`ui/star_chart.gd`：远距离矿点信息、任务及采集反馈和星图情报。
