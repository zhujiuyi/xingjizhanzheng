# 资产与业务列表界面

2026-10-04。用户要求同类舰体、物品与业务界面改成列表，包含图片、描述、单位、单价及最后一列操作。v0.8.4源码、123项图片资源及专项运行已验收；实际发布包下一步单独核验。最终版本、提交、检查结果及客户端身份登记在 [26](26-开发阶段与交付记录.md)，本文不将源码改动当作实际包通过。

## 1. 覆盖范围

业务页共用 `code/runtime/ui/business_list.gd`，每个页面使用一个列表，按内容添加分区标题。一行表示一个真实资产实例或业务定义，沿用原有数据库ID及请求目标。

| 页面 | 列表内容 | 末列操作 |
| --- | --- | --- |
| 舰队与借船 | 可用舰体、任务舰领取与换发、有效借船归还 | 切换驾驶、出售舰体、领取/换领、归还并换舰 |
| 仓库与货舱 | 本站仓库和当前舰货舱/矿舱的堆叠物资及独立设备 | 转入仓库、货舱或矿舱；用途受限物资保留限制 |
| 舰船配装 | 当前舰已装模块、空挂点、本地可安装设备 | 卸下、启用/关闭、安装到指定适配空槽 |
| 站点市场 | 购买物资、购买裸舰、出售本地资产三个筛选 | 购买或出售当前行资产 |
| 工业与回收 | 配方制造/提炼、船坞制造、普通设备拆解 | 按选定批数生产舰体或物品、拆解独立设备 |
| 任务与合同 | 既有本地/可接取/进行中/全部筛选及分页 | 接取/重新接取、定位目标、交付、放弃 |
| 科技与设施 | 对应势力研究及本站个人设施 | 完成研究、建造设施 |

空间站3D机库与NPC服务、暂停和存档卡片、星图及飞行HUD继续采用各自适合的结构。空配装槽使用通用挂点图示，不显示虚构设备；配装页面将可安装设备单独成行，安装按钮保留精确槽型及槽序号。

## 2. 列语义

从左至右为：**图片 → 名称/描述 → 单位 → 数量 → 单价/服务费 → 总价/信用点 → 状态/库存 → 操作**。页面可以调整数量与单价的表头，单位和金额含义须明确。

| 字段 | 显示规则 |
| --- | --- |
| 图片 | 根据资产类别和真实定义ID选择正式缩略图；同一舰型或物品实例共用对应图片 |
| 名称/描述 | 名称来自冻结定义；物品描述使用实际类别、单位质量/容积及模块供能、算力、作用距离、周期。舰体标明未配装的基准速度、舱容与防护，实例耐久、品质、来源和当前位置另行描述 |
| 单位 | 舰体为艘、设备为件、原矿/材料为单位、弹药为发、组件/消耗品为件、工业为批、合同为份、研究为项、设施为座、空挂点为槽 |
| 数量 | 市场与工业显示本次选定成交量/批数；舰体交易及按实例出售/拆解设备固定为1；设备购买可一次买多件；仓储显示实际持有量，不混淆持有量与顶部搬运数量 |
| 单价/服务费 | 市场为实际含税买价或扣费后的实收卖价；工业为每批服务费；借船、研究、设施及拆解为当前服务费用 |
| 总价/信用点 | 市场为本次实际含税支出或实际实收；工业为选定批数服务费；任务明确写“奖励”，不冒充交易总价 |
| 状态/库存 | 真实站点库存、本地持有量、当前位置、任务状态或阻碍原因；金额列不再混入整段限制说明 |
| 操作 | 当前行的真实业务请求；不可执行时禁用，状态说明原因，不把点击列表等同于成交 |

仓储、配装、空挂点、借船归还等无交易报价的行显示 **“—”**。无本地交易报价也不把定义中的参考买卖价格或业务报价缺省值当作当前成交价格。未知或缺失定义不能通过另写平衡常量补出描述。

## 3. 报价与数据库边界

所有游戏定义、数量、持久状态和资产权限仍由SQLite权威数据提供，遵守 [10](10-数据库与存读档技术方案.md)。列表不增加数据库结构或另一套价格、装备参数、存档格式。

市场物品单价使用实际 `economy.quote(item_id, 1, selling)`，总价使用 `quote(item_id, selected_quantity, selling)`；舰体使用 `quote_ship`。工业每批费用使用 `quote_manufacture(recipe_id, 1)`，批量费用使用 `quote_manufacture(recipe_id, selected_batches)`。单价与总价分别计算，不能用已舍入单价乘数量代替总价：税费、声望优惠和设施优惠仍按原业务执行整数舍入。

服务费用取已有冻结服务定义或数据库规则。研究与设施明确展示投入材料；制造说明每批材料与产出，选择多批时按实际批数校验材料。拆解仍按合法来源账本及原回收规则执行，不能用图片或界面描述创建可回收来源。

列表按钮保留原 `action / target / quantity / extra` 信号。堆叠购买、出售、搬运和制造读取当前操作数量；舰体、单件设备出售/拆解、借船、研究、设施等请求仍按原固定数量执行；物资购买包括多件设备，保持选定数量。最后一列不跳过业务层的资金、库存、容积、科技、材料、来源和站点资格校验。

本轮同时收紧已查明的界面资格遗漏：当前驾驶舰要求先换舰再出售，说明不再声称自动切换；借船按当前任务实例查找记录，避免历史归还记录遮住当前有效借船；站点服务、制造/研究材料与资金、配装科技与容量、拆解出处等显示实际限制原因。保障、任务绑定与借用资产沿用原限制，不因列表化开放交易或拆解。

## 4. 图片来源与资源边界

图片入口为 `code/runtime/ui/item_portraits.gd`；正式资源放在 `code/assets/business_v11/`，映射与来源记录在该目录的 `manifest.json`。该映射只保存资源路径和美术来源，不保存权威价格、数量、功率或玩家进度。

舰体缩略图使用项目现有原创 `ship_v3` 正式GLB与既有PBR材质，在Godot中离线捕捉为PNG；物品、模块、科技、设施与合同图标使用项目绘制的SVG几何形象。九类舰体图像生成完成及摘要核验须单独验收，不以资源映射已存在代表图片已捕捉成功。未复制EVE或其他游戏的模型、贴图、界面图片。

已知资产按具体定义ID查找图片；未知ID使用对应类别的明确通用图示，未知舰体不冒充任何具体舰型。客户端加载预制PNG/SVG并共用Texture2D缓存，列表不逐帧生成3D预览。生成脚本、渲染器和中间产物放在 `jiaoben/`，正式图片随工程交付。

## 5. 数量、滚动与焦点

操作数量采用顶部短SpinBox工具行，说明物资购买和堆叠数量、制造批数与固定单件交易的区别。修改数量只更新现有报价、数量及状态Label和按钮禁用状态，不重建整页、列表行或图片节点；用户正在阅读的位置及输入焦点保持。

业务页继续使用 `PageScroll` 纵向滚动。各行与表头共享相同列宽；内容超出窗口可用宽度时，列表上方显示横向滑条和提示，列表末尾也保留原生横向滑条，保留完整的数量、价格、状态及操作列。不是通过隐藏操作列或把单位塞回名称来适应小窗口。

按钮使用统一小尺寸样式，并允许必要文字换行。Tab定位下一操作时，共用组件向祖先滚动容器请求露出当前控件，兼顾纵向行位置和横向操作列；大窗口、小窗口与高缩放的实际可见性仍须原生实测。数量输入继续使用已有文本焦点保护，不触发舰船操控。业务完成后按原页面刷新流程更新状态，并恢复既有纵向滚动位置。
