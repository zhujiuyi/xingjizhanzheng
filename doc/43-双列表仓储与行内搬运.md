# 双列表仓储与行内搬运

v0.12.0；2026-10-04。按用户截图反馈重做仓库页：不再用同一张带价格列的长表混合船舱与仓库，也不再从顶部全局数量决定搬运。本页采用专属双列表；其它市场、工业、配装等业务仍保留各自原界面。交付身份与结果见[26](26-开发阶段与交付记录.md)。

## 已实现的界面

| 位置 | 内容与操作 |
| --- | --- |
| 左侧“当前舰船货舱” | 仅当前控制舰的货舱与矿舱，所在舱室明确标注；每行独立数量与“存入本站”，方向为当前空间站仓库 |
| 右侧“空间站仓库” | 当前玩家本世界所有已有站点仓库货物；当前站全部物品置顶，每行独立数量与“装入货舱”，方向为当前舰普通货舱 |
| 右侧异地货物 | 排在全部当前站货物之后，所属空间站列显示真实站名，整行和文字置灰；没有数量编辑或搬运按钮，说明需前往该站 |

两侧各自滚动，高缩放仍保持左右归属，不折叠成混合长表。物品图片、名称、持有量与单位、舱室/站名保持可见；独立设备保留实际耐久和品质，密封打捞包仍能搬运。其它停泊舰的货物、已安装槽位和残骸内容不混入当前货舱。

每个本地堆叠行独立记录搬运量，输入上限为真实持有量与数据库业务数量上限；点击先提交尚未按Enter的本行文本，再检查实际转移资格。单件设备和密封包固定1。编辑一行不改变另一行或市场/工业的`quantity_value`；实际搬运后保留未操作行的输入和两侧滚动，本行按剩余量钳制，全部移走则行消失。

保障、借用、任务绑定物资仍显示来源和限制，不能从此页手动搬运。矿舱货物能卸入本站；本站仓库向当前普通货舱装货，避免同一行出现多种方向按钮。打捞鉴定仍在独立鉴定页，不因搬运改变已经封存的奖励。

## 实际转移与只读资格

`Inventory.quote_transfer(kind, asset_id, quantity, destination)`只读取当前typed状态和冻结定义，复用实际`accessible/room/metrics/can_hold`，检查停靠、本站仓库服务、所有权、真实持有量、目标舱容及全舰载荷。返回可否、原因和真实可搬上限；不会自动减少用户请求量、创建仓库、消耗物品、修改错误状态或写SQL。

UI在数量变化、点击前读取新资格；Main在仓库页对搬运命令再次核验，再沿既有`move_stack/move_item/move_salvage`消费路径执行。拒绝保留原资产和进度。远站和其它舰仍由实际容器访问规则拒绝，不只依赖按钮颜色。

不修改底层允许教学样品搬仓的历史内部流程；原任务绑定来源、借船回收和残骸规则保留。新报价用于仓库页面权限，不能把UI限制误当作修改整个库存政策。

仓库行按真实stack/item/package ID分别显示，不合并不同来源、任务或借船的同名物品。只读取本世界当前玩家的已有仓库记录，不创建远站容器展示虚假空库存。当前站目的容器也按玩家所有权选择。

回调绑定面板实例、RuntimeState对象、world/session/epoch、当前站和当前舰；离开页面、刷新、读档、换站、换舰或换世界后旧按钮不再发送请求。不同世界允许合法重复`starting-*`初始物品ID，隔离依据完整世界/状态/面板上下文，而非错误地要求物品裸ID全局唯一。
