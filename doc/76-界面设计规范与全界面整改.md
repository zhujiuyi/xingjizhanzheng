# 界面设计规范与全界面整改

2026-10-16。本文从用户提供的两张参考截图归纳出一套界面规范，并据此对全部 28 个页面做整改。**规范是本文的主体**，整改清单是规范的落地。

## 一、来源与判定方法

参考图给的是**观感**，不是可直接照搬的布局：它是手机端、信息量小、中心常驻大雷达；本项目是桌面端、28 页、第三人称看舰船。因此只提取**可跨形态成立的结构规则**，逐条说明它在本项目的落点与代价。用户已确认三项取舍：整改覆盖全部界面（飞行 HUD 深改，其余按规则统一）、全面采用环形仪表、雷达保持按键展开。

每条规范标明现状判定，分三类：

| 判定 | 含义 | 处理 |
| --- | --- | --- |
| **已满足** | 现有实现已符合 | 本轮不动，避免把正确的东西重做 |
| **半套** | 语言存在但只覆盖一部分控件 | 补齐到全部同类控件 |
| **缺失** | 需要新建 | 按规范实现 |

判定依据是 v0.36.0 正式包 `verification/ui-completion-final/actual/ui-quality-after-nat-617e982d/` 的 179 张实际截图与 `code/runtime/` 源码，不以参考图的观感代替实测。

## 二、规范

### 规范 1 · 形状语言：圆承载连续量，方承载离散项

| 内容类型 | 形状 | 落点 |
| --- | --- | --- |
| 连续量 | 圆 / 弧 | 速度、电容、热量、护盾装甲结构、冷却剩余、占用率、距离环 |
| 离散项 | 直角矩形 | 列表行、卡片、按钮、输入框、标签、表格 |
| 符号 | 圆形外框 + 内嵌图形 | 导航入口、设备槽、目标 |

**禁止**用矩形周长描线表达进度。当前 `equipment_bar.SlotRing` 正是沿磁贴矩形周长描线，这是本规范要消除的写法。

现状：**半套**。`navigation_hud.Radar` 与 `ui_theme.Dial` 已经是圆；设备槽是矩形；仪表是横条。

### 规范 2 · 环形即进度

进度不另开控件，画在它所属对象的轮廓上。

| 项 | 值 |
| --- | --- |
| 起点 | 正上方（−90°），顺时针 |
| 底弧 | 全量，`BORDER` 40% 不透明度 |
| 前景弧 | 当前值，取该对象的语义色 |
| 线宽 | 常规 3px、紧凑 2px |
| 超出 100% | 钳制在满弧并改 `WARN` |
| 数值 | 环内两行（规范 3），或环旁一行 |

现状：**半套**。`Dial` 三环已符合；设备槽的冷却环沿矩形周长（规范 1 禁止）；电容/热量/载荷是 `ProgressBar` 横条。

### 规范 3 · 两行数据：大数值 + 弱化小单位

一个「数值 + 单位」的组合必须分两行：数值用 `SIZE_PAGE`(20) 或 `SIZE_SECTION`(15)，单位用 `SIZE_NOTE`(11) + `MUTED`。

| 场景 | 做法 | 例 |
| --- | --- | --- |
| 仪表、状态带、卡片主数值 | 两行 | `650` / `m`；`0.019` / `AU` |
| 表格行内 | 保持一行右对齐 | 表格行高固定，拆行会失控 |
| 列表卡片次要信息 | 保持一行 | 名称、状态 |

`XJSpaceUnits.speed()` 等返回 `"0.0 m/s"` 单串，需要拆分数值段与单位段；拆分只改呈现，换算与排序仍用真实数值。

现状：**半套**。目标总览已把距离数字与弱化单位分列；仪表、舞台底栏状态带、卡片主数值仍是单行。

### 规范 4 · 面板是衬底不是容器

| 场景 | 做法 |
| --- | --- |
| 浮在 3D 场景上的面板 | 无描边、无标题栏；`COAL` 60% 衬底 + 8–10px 内距 |
| 不透明页面上的面板 | 保留细边界——背后没有场景，边界承担分组 |

**禁止**面板内再套面板形成双层边框。区块标题用 `SIZE_SECTION`(15) Medium + `TEXT`，不加底板、不加大字号。

现状：**半套**。`hud_panel()` 带 `BORDER` 描边与内距，被舞台三区、站内枢纽、飞行 HUD 共用；`plate()` / `panel_style()` 用于不透明页，正确，不动。

**本条的杠杆**：改 `hud_panel()` 一处，所有浮在场景上的面板同时符合。

### 规范 5 · 图标与读数成对

导航/入口类图标按钮：圆形外框 34px（紧凑 28px），内嵌图标 18px。**有真实计数的加一行 11px 读数，没有的不编造数字**。

现状：**缺失**。飞行左侧竖排键是「图标 + 文字标签」，没有读数；站内枢纽的服务行是矩形行。

### 规范 6 · 对象的两种视图

| 目标数 | 视图 |
| --- | --- |
| ≤ 4 | 顶部一排圆形头像（头像 44px + 下方两行距离） |
| > 4 | 右侧列表（距离在上、名称在下、类型图标在左、状态在右） |

两种视图**不得同时出现**。距离/名称/类型三列的对齐契约在列表视图中保持不变。

现状：**缺失**（只有列表视图）。

### 规范 7 · 中心留白

屏幕中心 ±(80×60) 区域不得有任何 HUD 控件。已有断言 `critical_frame_outside_viewport` 守护。

现状：**已满足**。

### 规范 8 · 颜色语义

| token | 语义 | 禁止 |
| --- | --- | --- |
| `AMBER` 琥珀 | 当前 / 已选中；唯一主操作 | 用作系列色 |
| `ICE` 青 | 次数据、友方 | — |
| `WARN` 暖橙 | 预警、暴露、缺料、受限、负向收益 | — |
| `GAIN` 青绿 | 正向收益、修复、友方增益 | — |
| `DANGER` 红 | 不可逆操作、敌对、实际故障 | 用于普通删除 |
| `TEXT` / `MUTED` | 标签与说明 | — |

**颜色不得单独承载状态**，必须同时有形状或文字。热量三态、暴露、锁定都已有独立形状与措辞。

现状：**已满足**（第 74 轮已收窄）。

### 规范 9 · 字阶与字重

沿用第 74 轮的六档，不新增档位。

| 角色 | 字号 / 字重 | 用途 |
| --- | --- | --- |
| display | 28 Medium | 标题页 |
| page | 20 Medium | 页标题、仪表主数值 |
| section | 15 Medium | 区块标题 |
| body | 13 Regular | 正文 |
| data | 13 Regular | 表格数值（等宽数字 + 右对齐） |
| note | 11 Regular | 单位、说明、读数 |

现状：**已满足**。

### 规范 10 · 间距栅格

4px 基准。`GAP = 8`、`SECTION_GAP = 16`；环间距 7px；面板内距 8（紧凑）/ 10（常规）；图标与读数间距 2px。

现状：**半套**。主题常量已存在，但各面板有硬编码的 3/5/6/12/14 等值。

### 规范 11 · 状态表达

| 状态 | 做法 |
| --- | --- |
| 空 | 一块说明 + 一个真实可用的下一步；区分「没有定义」与「已经完成」 |
| 禁用 | 置灰 + tooltip 写真实原因，**不隐藏** |
| 加载 | 真实进度；不用假动画占位 |
| 故障 | `DANGER` + 具体原因 |

现状：**已满足**（第 75 轮已建立）。

### 规范 12 · 控件预算

一屏同时出现的独立控件组 ≤ 6；一处上下文只允许一个主按钮；纯「详情」按钮删除，改为整行可选中。

现状：**已满足**（第 73/74 轮已收敛）。

### 规范 13 · 响应式

断点 950px（既有 `compact`）。四种验收尺寸下所有主路径可达；640×360 逻辑画布下不得依赖横向滚动完成主操作。

现状：**已满足**（第 75 轮已整改）。

## 五、边界

**不动**：数据库数值与阈值、存档格式与迁移、业务资格与目录能力判定、交易/数量/焦点/滚动契约、`_service_pages` 的场景过滤、第 72/74/75 轮已关闭结论（无常驻侧栏、舞台三区几何、按来路返回、紧凑交易行、空态与折叠、F6 键盘焦点）。

**保留的既有契约**（新实现必须继续满足，不得为改样式而放宽）：节点名 `EquipmentRow` / `Module_*` / `InfoRow_*` / `InfoSelect_*` / `DistanceCell` / `Service*` / `flight_dock` / `target_panel` / `navigation` / `flight_header`；`module_buttons` / `module_labels` / `module_progress` / `entry_rows` 等字典接口；`SlotRing.value` / `max_value` 语义；`thermal` 三态可辨性；`PanelHome` / `PanelClose` 存在性。

**必须同步改的断言**（改到新行为，不是放宽）：热量由比对 `thermal.fill` 改为比对弧色，三态仍须逐状态可辨；设备槽由矩形内接改为圆内接，`_check_equipment_row_fit` 的最坏 17 槽预算重算。

## 实施记录

按上表顺序补记。

### 步骤 1：主题词汇已建立

- `hud_panel()` 去描边，改 `COAL` 68% 衬底（规范 4）。**这一处改动同时作用于舞台三区、站内枢纽与飞行 HUD 的全部浮层**，是本轮覆盖面最广的单点。
- 新增共享几何 `RING_START`/`RING_SWEEP`/`RING_WIDTH`/`RING_BACKING`/`RING_STEP` 与 `draw_arc_meter()`：底弧与前景弧一处发出，起止角、方向与线宽不再由各控件各自决定。
- 新增 `split_value_unit()` 与 `draw_value_unit()`（规范 3）。
- 新增 `draw_portrait()`：把纹理画成 UV 沿圆周的多边形来裁剪成圆形。**不引入遮罩贴图、不引入着色器**，因此表现资源清单与构建校验都不受影响；纹理取中心正方形，非方形头像不会被拉伸。
- 新增 `RingMeter`（N 环 + 两行读数）、`CircularSlot`（圆盘 + 圆形头像 + 外圈弧 + 空槽内环）、`PortraitMarker`（圆形头像 + 两行距离 + 选中外环）。
- `Dial` 改用共享几何。**速度表保留底部开口的仪表形态**（1.3π 扫掠）而不是改成整圈：它是仪表不是进度环，数字要坐在开口里；这是规范 2 中唯一的一处显式例外，已在代码注释中写明。

**实测**：源码无头全页复查 28 页 0 发现；原生全页复查 **28 页 / 179 图 / 0 布局发现**通过。逐张看 `flight-1440x900` 与 `station-1440x900`：描边消失后浮层读作衬底而非窗口，站内机库明亮背景上的 13px 说明文字仍可读，68% 衬底成立。

**本步未做**：`navigation`（飞行左侧竖排键）与页头状态条使用各自的 `flat()` 样式盒而非 `hud_panel()`，因此仍带描边，留到步骤 5 一并处理。

### 步骤 2：飞行设备槽圆形化

`SlotRing`（沿磁贴矩形周长描线）删除，改用共享弧几何。每个槽现在是：暗圆盘 + `draw_portrait` 裁剪的圆形头像 + 外圈。

**按钮本身不再有表面。** 第一次渲染出来发现圆形槽外面套着一个方形磁贴——那是 Button 自己的样式盒。槽的形状规则要求去掉它：按钮只剩命中区域，状态改由**外圈颜色**表达（启用 = `ICE` 75%，关闭 = 弱 `BORDER`），悬停与按下是**只在指针进入时出现**的极淡填充。这条是被 `ui_quality_audit` 的「控件必须能区分 normal/hover/pressed/disabled」抓出来的：把六态做成同一个透明样式盒之后，控件就没法表示自己被按过了——那已经不是交互控件，是装饰。

**几何按 Label 的真实下限定，不按好看的数值定。** 第一版给了 13px 的槽位名条带，实测 Label 的高度下限是字体的行高（10px 字体 → 15px），于是名字向下溢出磁贴 2px，在四种尺寸上全部失败。现在条带就是行高：

| | 圆直径 | 名条带 | 磁贴 | 单行容量 | 最坏 17 槽 |
| --- | ---: | ---: | ---: | ---: | --- |
| 常规 | 31 | 15 | 31×46 | 19（656px 行内） | 1 行 |
| 紧凑 | 22 | 14 | 22×36 | 14（360px 行内） | 2 行 = 75px ≤ 76px |

「空槽 ×N」改用无边框 chip：它是一格代表多个插槽的聚合计数，保持矩形合理，但不再带回描边。

**验收**：`ui_completion_v64` 在四种尺寸下 **1747 项 / 0 失败**，含 17 槽满装的逐磁贴几何、状态与标题不重叠、冷却环的真实剩余秒数与目录周期、无横向滚动。全页原生复查 **28 页 / 179 图 / 0 布局发现**。

**一处必须记下的非确定性**：`ui_completion_v64` 有一次运行在「native keyboard reaches exact related destination operations/projects/research」等 5 项失败，**代码未改、紧接着重跑即 1747 项全通过**。失败集中在相关功能菜单的 PopupMenu 键盘遍历（`native_key` 逐帧投递按键），与设备槽无关。按项目惯例记下原始证据，不计为通过证据也不当作回归。

### 步骤 3：飞行仪表环形化

**先发现的是一处重复，不是一处样式问题**：读 `_update_instrument` 时看到 `dial.ratios` 取的就是 `ship.shield/armor/hull`，而左边那一列横条画的还是这三个值——同一组数据在同一个面板里画了两遍。所以这一步不是"把 6 条横条改成 6 个环"，而是先消掉重复。

改后：`dial` 用三个同心环画护盾/装甲/结构，左右两列只负责**命名**；电容/热量/载荷各自一个弧。横条从 6 条降到 0 条。

**两类值用了两种环形，这是有意的**：

| 组 | 关系 | 形状 |
| --- | --- | --- |
| 护盾 / 装甲 / 结构 | 真正的嵌套层（装甲在护盾之后） | 同心环 |
| 电容 / 热量 / 载荷 | 各自独立的预算 | 各自一条弧，紧贴自己的名称 |

6 条横条把两组说成同一类东西；把资源也做成一个三层同心环，等于反过来又说错一次。

**第一版渲染出来是错的，看图才发现**：资源做成一个三环仪表放在图例上方，结果那个环与它描述的三个数字**没有任何视觉关联**，看起来像一块装饰。改为每行一个弧、紧贴自己的名称之后，对应关系一眼可见。

**一处几何陷阱**：`clip_text = true` 的 Label 不申报宽度（最小宽度 1px）。第一版把仪表与图例并排放进 HBox，图例立刻塌成 1 像素宽，`label_fits` 全线失败。图例必须占一列固定宽度。

`energy_bar` / `heat_bar` 现在直接指向弧自己持有的 `Ring` 对象，**读数与弧是同一个对象**，不可能对不上。

**同步改的断言**：热量三态从比对 `heat_bar.get_theme_stylebox("fill").bg_color` 改为比对 `heat_bar.color`。要求没有放宽——仍是三个状态、三种可辨视觉、各自可读。

**验收**：全页原生复查 **28 页 / 179 图 / 0 布局发现**；`ui_completion_v64` **1747 项 / 0 失败**（重跑确认，首跑 1 项为上述键盘遍历非确定性）；`fitting-world` 通过。逐张看 `flight-1440x900` 与 `flight-1280x720-200pct`：常规下六个值各有弧，紧凑下载荷按既有约定隐藏。

**顺带记录一处与本轮无关的既有失效**：`hud_layout_v9` 引用 `equipment_bar.scroll`，该属性在更早一轮（设备条改 `HFlowContainer`）就已删除；该套件不在交付验收集内，其 runner 也硬编码 macOS `CoreAudio`。
