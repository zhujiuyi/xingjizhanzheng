## 1. 单位、表示与边界

| 类别 | 统一单位与表示 | 边界 |
| --- | --- | --- |
| 空间与运动 | 米 m、秒 s、米每秒 m/s、米每二次方秒 m/s²；数据库使用有限 REAL | 速度、加速度和持续时间非负；位置以星区局部坐标保存 |
| 质量 | kg，有限 REAL | 船体、安装装备与货物分别计量；不把物品数量直接解释为 kg |
| 角度 | rad 与 rad/s，界面可显示度与度每秒 | `deg = rad × 180/π`；姿态用规范化四元数，不混用角度顺序 |
| 容积 | 最小整数单位 L，`1 m³ = 1000 L` | 容器容量、单件物品体积及占用为整数；界面显示 m³ |
| 物品数量 | `quantity` 为整数件/单位 | 各物品定义一单位的质量与体积；交易、配方、矿量不使用浮点数量 |
| 货币 | 航路信用点 `currency_route_credit`，整数最小单位 | 不存在现实付费转换；余额与费用不得为负 |
| 防护 | HP，计算与状态可用 REAL | 三层状态分别在 `[0, max]`；伤害不倒灌为治疗 |
| 运行能源 | EU，游戏能源单位 | 与安装预算区分；`0 <= energy <= energy_max` |
| 热量 | HU，游戏热量单位 | `0 <= heat <= heat_max`；不是绝对温度 |
| 安装预算 | PU 功率预算、CU 算力预算，整数 | 不是现实电功率或 CPU 频率，不与 EU/s 作物理换算 |
| 抗性与倍率 | 抗性为 0–1 的比例；价格/曲线可用整数基点 | `10000 bp = 1`；抗性上限 0.75，默认不允许负抗性 |
| 时间推进 | 权威模拟 60 tick/s，`dt = 1/60 s` | 暂停或退出不推进世界时间；图形帧率不影响经济、伤害或资源产出 |

输入、缓存、保存与读档均拒绝 NaN、无穷、非法 ID、负库存和超界状态。HP 与能源的数值表示允许浮点计算，但经济使用整数；费用向上取整、收入向下取整。所有容量、费率、阈值和规则参数均由数据库给出，代码实现通用公式。

每件矿石的质量代表本项目的一个标准交易单位，资源目录不是现实采矿物理模型。制造表描述关键物料和服务投入，不声称精确模拟全部制造过程的质量守恒。

### 2.1 质量与操作派生

`M = dry_mass + installed_mass + sum(quantity × item_mass)`；必须同时满足安装质量、载荷、各舱容积及配装预算。

令 `f = dry_mass / M`，合法状态中 `0 < f <= 1`：

- `acceleration = base_acceleration × f × engine_acceleration_factor`
- `turn_rate = base_turn_rate × sqrt(f) × engine_turn_factor`
- `max_speed = base_speed × sqrt(f) × engine_speed_factor`
- 制动加速度取当前有效前向加速度的 1.4 倍；横移为 0.6 倍，倒车为 0.5 倍。输入方向向量规范化，不通过同时按多个方向获得更大推力。

没有启用姿态引擎时三个引擎倍率均为 1；能源归零仍保留裸船基本推进、转向和制动，不能让玩家因耗尽能源失去所有行动能力。升级推进设备耗能后才能提供其额外倍率。数值表达惯性与操控差异，不预先锁定鼠标控制方式或完整六自由度默认键位。

局部巡航候选上限为有效常规航速的 3 倍，额外消耗 4 EU/s 与 3 HU/s；只在非交战条件允许，巡航中不能开火或作业。它不跨星系，不代替门。此项需操控样例验证，首轮可以只开放常规飞行。

### 3.3 配装与叠加

- 针锋动能炮与采集头可分别占多个合法挂点；曜线热束与破浪脉冲首版各限一件。每个实例独立消耗、冷却和输出，多武器并不免除弹药成本。各限装组读取数据库定义。
- 引擎、扫描、护盾、支援每组限一件；两种装甲合并为同一限装组，不可利用不同 ID 同时叠甲。
- HP 上限的平加先相加；抗性以基础值加合法平加修正后钳制到 0–0.75；不同作用族的倍率相乘，同族只取最高合法倍率。加法、乘法、限装与效果族必须有明确数据定义。
- 初始标准 `quality` 不随机增益，属性倍率为 1。模块耐久范围 0–100，0 时禁用；本版尚未确定磨损概率，不隐式每次启动扣耐久。
- 站点安装增加上限不会免费治愈已有伤害；当前 HP 不增加，只钳制到新的最大值。新造/教学实例初始化为其合法配装最大状态。
- 势力倾向已经体现在定义，不能读到势力字段后再自动乘一次隐藏全套奖励。

## 4. 伤害、防御与激活顺序

三伤害 ID 固定为 `kinetic`、`thermal`、`pulse`。四首舰裸船统一抗性基线：

| 防御层 | kinetic | thermal | pulse |
| --- | --- | --- | --- |
| shield | 0.20 | 0.10 | 0 |
| armor | 0.15 | 0.15 | 0.05 |
| hull | 0.05 | 0.05 | 0.05 |

### 4.1 层间溢出

对当前原始伤害向量 `D = (K,T,P)` 和当前层抗性 `r`，计算 `q = Σ(D_i × (1−r_i))`。

1. `q = 0` 时终止，无伤害。
2. 若 `q <= 当前层HP`，扣除 `q`，该次伤害全部被本层消耗。
3. 否则令 `a = 当前层HP/q`，本层置零，将剩余**原始**向量改为 `D_i × (1−a)`；到下一层重新按该层抗性计算。
4. 次序为 shield → armor → hull；hull 到零即销毁，剩余量不变成其他奖励或修复。

混合伤害按向量同比例消耗原始份额，避免先算动能再算脉冲造成顺序偏差。同 tick 对同目标命中的原始伤害先汇总为向量；必要击毁归属按贡献记录处理，不改变层间算法。

算例：动能原始 50，shield 剩 10/动能抗性 0.5，armor 剩 12/抗性 0.2，hull 剩 20/抗性 0。盾消耗原始 20，余 30；甲消耗原始 15，余 15；结构损失 15，最终为盾 0、甲 0、结构 5。不能把第一层已减抗的 15 点 HP 伤害直接传给下一层再减抗。

### 4.2 每个模拟 tick 的顺序

1. 接收经过校验、具有顺序号的输入；回充能源、被动盾和冷却，递减计时器。
2. 按 `activation_priority → slot_index → instance_id` 排序准备激活。优先级：引擎 10、护盾/支援 20、武器 30、装备扫描 40、内置扫描 45、工业 50。
3. 对每次激活在同一拥有者资源账本预约能源、热量、弹药/材料；不足则拒绝该次，不让两个模块各自花掉同一份能源。优先级可作为玩家配置，但不得在同 tick 中绕过已经预约的消耗。
4. 武器激活产生射击，命中时间由弹道/照射判定；工业、扫描和维修启动时付费、完成周期时产生结果。作业中断不发未完成产物，也不返已经消耗的能源与耗材。
5. 汇总有效命中并结算伤害和销毁，再向存活目标应用完成的修复；同 tick 被击毁者不能被随后修复复活。
6. 按稳定顺序结算矿量、扫描、交付与其他业务变更；保存请求只在业务一致的稳定边界捕获快照。

预测 `heat + activation_heat > heat_max` 时拒绝并进入过热锁，降至最大热量的 50% 解除；达到 80% 仅预警，不附带隐藏降伤。能源或弹药不足只拒绝相应设备，不能自动出售货物或破坏船体。取消矿业、支援或扫描周期的具体状态和保存边界遵循行为接口及数据库方案。

## 5. 扫描、采矿与资源恢复

全舰内置基础扫描，无装备或研究前置：距离 500 m，每 1 s 周期消耗 2 EU、产生 1 HU，输出船体基础扫描强度。远标阵列改为 3000 m 与强度 +15，并取代内置输出。

扫描需要进度为 `threshold × difficulty`。普通信号 threshold 300，教学 T1 校门信号单独定义为 80；难度倍率为常见 1、隐藏 2、高级 4。

`rate = (ship_strength + active_module_bonus) × proximity / interference`；`proximity = max(0.25, min(1, 1.75−1.5×distance/range))`；干扰系数下限 1，超出范围不推进。首版周期输出 `rate × cycle_seconds`，完成时登记一次发现记录；不是每次扫描成功都无限发现金。

雨燕在范围近半段的教学 T1 信号用内置扫描约 10 s 完成；提灯装备阵列时普通信号近半段为 `ceil(300/35) = 9` 个 1 s 周期。这是理想算例，进入距离、干扰和操作会改变实际耗时。

铁砧每个筛光头周期产出 `floor(8×1.5)=12` 单位，双头名义 6 单位/s；其他有合法作业槽的船为每头 8 单位/4 s。完成周期时取以下整数最小值：名义产出、矿点剩余、合法接收容器的剩余体积可容数量、最大载荷允许数量。同 tick 多头按槽索引处理；矿点扣除与库存增加作为一次一致业务结果。

高安全基础矿点草案：铁硅 3000 单位/点，导能 600 单位/点；枯竭后等待世界时间 1200 s 按定义再生。特殊地点、稀有产出与刷新数量另定义；首次发现、资源剩余、枯竭时间和生成状态均保存，读档和进出场景不重置。

## 7. 交易、维修与经济闭环

站点交易费用为 2%。买入 `ceil(ask × quantity × (1 + fee))`，卖出 `floor(bid × quantity × (1 − fee))`。计算实际报价时先应用声望价格修正：最大购买折扣 5%，最大售出增益 5%；服务费不享此商品折扣。本版高安全基准站先用固定价与实际库存，C 阶段再定义地方供需变化。

不得只检查“直接买成品部件→制造→出售”。必须递归比较从市场购买原矿、逐级制作、整数批次、服务费、最优采购/制作组合和最大声望折扣后的成本。制造成本低于购买成品可以形成用途；**同站无行动成本的递归制作→立即 NPC 回收不得为正收益**。自采材料、运输或合同产生的劳动收益可为正。

能源补充和停靠护盾恢复免费，但不是可售出的物品；armor 修理按实际修复 HP 收取每 HP 1 信用点，hull 每 HP 2 信用点，并消耗 `ceil(修复hull/100)` 单位结构料。最低报价先显示，修理前检查材料和信用点；模块维护为每点耐久 1 信用点。外场维修的材料、射程和风险不同于站点服务，不能由外场 armor 修复自动增加 hull。

首轮动作与持久化阈值也属于数据库参数，不能在脚本另设默认值：

| 参数 ID | 基线 | 语义 |
| --- | --- | --- |
| `combat_exit_delay_s` | 15 s | 最近一次主动敌对攻击或成为有效敌对攻击目标后的脱战等待，未命中也算攻击尝试；按世界时间计算 |
| `dock_radius_m` / `dock_max_speed_mps` | 600 m / 20 m/s | 以站点交互锚点距离和实际速度核验，还必须满足非交战及服务权限 |
| `wreck_pickup_radius_m` | 100 m | 以残骸交互锚点距离核验，仍须检查货舱和载荷 |
| `wreck_cargo_recovery_ratio` | 0.5 | 船毁时普通货物逐合格堆叠向下取整进入唯一残骸；安装模块和绑定资产不按此比例兑现 |
| `save_wait_prompt_s` | 10 s | 保存延后达到该 UI 实际等待时长后提示继续等待或取消；暂停世界也不能阻止提示 |
| `autosave_interval_s` | 120 世界秒 | 定时自动保存请求间隔，仍经稳定边界与队列；不强行在战斗中提交 |

敌对攻击指经过权威校验、针对敌对实体的攻击尝试；对空乱开火不反复重置其他实体状态。B 不保存半程战斗，因此脱战后仍须清理在途攻击、结束交互周期，才能捕获稳定快照。残骸中的普通货物按物品 ID、来源及其他兼容堆叠属性先归并再取整，避免临时拆栈改变损失结果。

基础原矿供给与服务可补货：教学保障服务不因玩家声望关闭；常规 NPC 商品草案每世界 300 s 补充到定义库存目标，补货量有上限并持久化。首轮 catalog 已登记价格与补货周期，逐站点商品库存目标、补货上限和开放条件需在 B 交易功能前建表入库，不能默认为无限库存。高阶特色商品的库存和供给由星系服务单独定义。

经济目标先用于测量：基础任务净收益应覆盖一次合理出航的弹药和修理，采矿与运输收益需要计入航行和风险；价格、任务报酬及制造费共同调参。不得把名义采矿产率直接当成实际每分钟赚钱速度。

### 9.1 可重复算例与待测目标

静止、完全命中、无主动修复/被动回充的算例：游隼双针锋名义 56.667 原始 DPS。L3 掠袭敌为 224/252/308 HP，面对动能的原始有效 HP 为 `224/0.8 + 252/0.85 + 308/0.95 ≈ 900.681`，连续 TTK 约 15.894 s。若第一次双联齐射发生在 t=0，共需 14 次齐射，最后一次 t=15.6 s；实际弹道飞行与未命中会延后击毁。

L6 重装敌动能有效 HP 约 2578.328，双针锋连续 TTK 约 45.50 s；它的脉冲 DPS 为 38.4，默认游隼面对脉冲有效 HP 约 868.421，反向连续 TTK 约 22.615 s。不计修理的默认单挑不成立，应预警并鼓励撤离或改变方案。

热量与能源也需计算：一件曜线满速运行耗 20 EU/s、16 HU/s；游隼若同时使用引擎和护盾，需求约 30 EU/s 与 21 HU/s，高于回充 14 与冷却 12，不能只比较其 56 DPS 就认定持续最优。针锋弹药与射程有优势但有补给成本，脉冲可形成不同的能量/冷却取舍。

以上只是数学基准，未包含几何、锁定、转向、命中和玩家操作。后续记录实际 TTK 分布、命中率、过热/枯能时间、返航损失与任务净收益，再调整数值；不将理论算例标为游戏平衡已通过。

## 11. 全体系扩展的预算方法

本轮只有四首舰与十代表模块有完整基线；不能宣称驱逐、巡洋、战列、运输与支援等九类舰船均已具体调参。后续以角色模板和预算建立候选，再实测：

- 战斗舰增大时同时扩大有效 HP、供能和武器预算，降低机动并增加补给/通行门槛；不同时提高所有射界和追踪。
- 工业/运输以载荷、舱容、作业效率和交付收益为预算，同时维持撤离与防御短板；稀有材料必须存在贸易或代用来源。
- 支援以每秒有效修复/供能、作用距离、自身耗能与耗材成本衡量；必须在 NPC/单人任务中有可验证用途。
- 科技 II/III 的新增功能应至少对应一项容量、能耗、热量、质量、射程或维护代价，不把代际作为统一乘数。阵营修正作为已登记效果族参与预算。
- 区域供需、研究、生产时间、事件奖励与声望门槛在 C/D 分别版本化；零成本、无代价的循环依赖和买卖套利属于内容构建拒绝项。

## 12. 构建校验与后续平衡验收

数值库构建应检查：固定 ID 与引用、单位和合法值、默认配装与安装/载荷预算、所有基础解锁可达、配方依赖无环、矿量与货物整数一致、教程满载双向通过、抗性层溢出、并发能源预约、NPC 曲线区间、同站递归制造/回收无套利及保存所需参数完整。

静态/模拟检查通过只说明这些关系在所用模型内成立，不能代替游戏试玩。A 阶段核验引擎与数据库接入；B 阶段测四舰的操控、任务、视角和飞行/战斗/虫洞；C/D 按完整蓝图扩充内容和调优。每次修改输出、成本或速度，应同步数据库内容版本和相应测试，旧存档保持冻结定义或明确迁移。

本文件已落库的配置以正式 catalog 为运行时权威；C/D 候选必须在对应功能开放前补齐正式条目。不把 Markdown 表格当作运行时配置，也不把研究脚本当作已完成的 Godot 游戏逻辑。
