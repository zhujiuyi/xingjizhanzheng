# 星际战舰 · 指令式操舰与运动重影修正

日期：2026-10-03。版本：**v0.8.0**。状态：源码及原生验收已完成，实际桌面包待独立构建与验证；不以v0.7.0结果证明新版通过。实际构建身份、提交和交付状态统一登记在 [26](26-开发阶段与交付记录.md)。

## 1. 范围与确认需求

原方案把普通相对鼠标移动用于操舰、Alt切换指针、左键发射武器；与总览导航并行时，观察、选择、操舰容易混淆。用户最新要求明确覆盖过渡讨论中的右键观察和方向键主转向：**光标常驻、右键禁用、左键短击选择/长按拖动观察、W/S沿当前观察航向加速、A/D左右转弯、双击总览自动转向并接近。**

观察与指令仍分开。普通移动鼠标、左键观察、缩放或单击选择不会改变舰首、取消导航或更换正在攻击的对象；W/S等明确操舰动作才接管运动。“交战”明确设置目标并启动接近与自动开火；原武器资格继续生效。本轮不增加新舰种、付费资产、联机功能、锁定计时或另一套数值。

运动重影需分别检查完整模型重复、渲染姿态与HUD投影不同步，以及相机输入残留。此前v0.6.2确认并修复了HUD重复标记通道，独立样本未发现完整模型副本；该结论不能替代本轮运动中的检查或承诺个人存档全部场景已解决。

## 3. 已确认操作契约

| 输入/动作 | 行为与边界 |
| --- | --- |
| 普通鼠标移动 | 光标可见；不操舰、不取消导航、不发射武器 |
| 场景左键短击 | 选择实际模型；总览/雷达单击同样只选择 |
| 场景左键长按拖动 | 观察相机，松开保留角度；不自动改变舰首或接管导航 |
| 右键 | 禁用，不观察、不转向、不隐藏光标 |
| 滚轮 | 缩放现有允许缩放的视角；不执行导航 |
| W/S | 沿当前观察航向加速/反向加速；向上观察后按W可以向上航行，仍受真实转速与推进能力限制 |
| A/D | 左右转弯；不再表示左右平移 |
| Space/C、Q/E | 上下移动、滚转，保留三维航行能力 |
| 双击总览实际目标 | 明确下令转向并接近；远景天体只选择，不接近 |
| Ctrl | 发射固定武器；原挂点、射界、弹丸与能源规则不变 |
| Z | 已有自动开火时一律停止，不受当前选中对象影响；没有自动开火时才启动对所选合法敌舰的开火，保留既有接近/环绕 |
| 目标卡开火按钮 | 明确对所选敌舰启动/停止，可显式切换开火目标；与Z优先停火的行为区分，停止开火独立于停船 |
| 交战按钮 | 对有效敌舰明确设置开火目标，并启动普通接近 |
| X / 停船按钮 | 停止移动与导航；不关闭独立自动开火 |
| Shift、F、V | 真实推进设备、原条件交互、现有三种视角；F不会自动接近 |
| 显示舰船 | 明确恢复默认观察角度、距离与居中跟随；不改变舰船位置或速度 |

非跃迁导航被明确手动输入接管时保留惯性，在当前物理步响应输入，不强制回正相机。取消跃迁继续安全停船，避免停进碰撞体。跨星系虫洞的准备/提交与保存事务保持原边界。

## 4. 输入与界面事件归属

键盘操舰检查`keyboard_blocked()`与窗口焦点；菜单、业务页、站内及文字输入阻断操舰。常驻指针悬停总览、仪表、设备或雷达不阻断飞行快捷键。

场景鼠标入口检查`ui_input_blocked()`；旧`input_blocked()`保留同义接口。UI面板与按钮优先消费事件，拖动总览、设备或菜单不拖动相机。场景拖动一旦开始，由主输入流程持续跟踪至松开；跨过HUD时不残留拖动状态，退出、失焦或打开菜单清理临时输入。

总览目标按钮的`pressed`只发`selected(id)`；`gui_input`仅在左键`pressed && double_click`时消费事件，先选择，再对真实目标发一次`command("nav_approach", id)`。释放或普通单击不再发导航请求；失效/跨区/不合资格的目标由Main执行时重新检查。组件仅提出命令，不能直接写舰船姿态或位置。

## 5. 选择、导航与开火分离

界面`target_id`、已接受导航的目标与独立开火目标具有不同职责。单击换选中对象只更新名称、距离、唯一标记与操作卡；不改已接受的导航或开火目标。双击总览是显式接近命令；“交战”是显式设置开火目标并接近。

UI发出`requested("combat_engage", selected_id, 1, "")`，只按Main提供的`combat_engage_ready/reason`启用按钮；缺字段默认禁用。目标卡开火按钮是对所选敌舰的明确动作，可以切换开火目标；Z已有自动开火时优先停止当前开火，无自动开火时才启动所选合法敌舰。操作卡读取`combat_target_title/status`显示实际开火对象，即使当前查看另一个目标；`combat_active`只描述当前所选目标是否正被辅助攻击，不替代全局开火对象。

武器继续逐次检查真实敌舰状态、局部探测、射程、前向射界、视线、配装完整性、冷却、电容和热量。待机原因由真实业务状态提供；“已开启”“正在接近”不代表命中，不能用UI文字扩大射界、直接扣血或绕过数据库条件。目标消失、死亡、跨区和禁止开火的过渡按业务规则停止辅助。

## 6. 运动姿态与持久状态

已启用工程物理插值。相机rig与Camera3D自身关闭自动插值，由`camera.step()`每渲染帧采样并缓存舰船的插值姿态；Main先更新相机再更新UI，NavigationHUD的目标、虚线和雷达统一使用同帧渲染姿态。物理推进、DTO、碰撞、资格距离与SQLite快照仍使用实际物理姿态和速度，显示层不反写平滑位置。

新实体完成最终出生位置后先启动插值采样再重置历史；玩家换舰、载入或跃迁安全位置修正按相同边界初始化，避免从旧坐标插值到新位置。替换/销毁实体先隐藏并从场景树移除，再`queue_free()`，避免延迟释放期间旧模型与新模型同时留在可渲染场景中。这些是已落实的源码修正；原生运动样本已单独通过下方检查。

下方专项分别证明场景结构、真实插值投影和主客户端运动几何；不能据headless几何宣称视觉上所有个人存档重影均已复现并解决。没有把TAA认定为已证实原因，独立探针的渲染配置也不替代实际客户端配置或实机画面。

常驻指针是固定输入规则，不新增需要保存的pointer模式字段。既有相机模式与存读档契约继续适用；最终实际姿态仍写入SQLite，不以UI变量、JSON或Resource维护另一套存档或平衡数值。原数值与正式美术资产未因键位和提示改变而获得修改授权。

明确退出/返回主菜单的保存请求清理held固定武器、拖动、待选取与临时操舰输入，停止自动开火和导航。等待稳定边界期间阻止新操舰、武器及业务命令，允许取消保存、明确放弃进度退出和偏好操作；现有设备周期、弹丸与交战计时继续按原模拟完成，再提交SQLite端点。不能只停止autoFire却让按住Ctrl继续产生新周期，也不能为了退出直接跳过业务稳定条件。
