# 航行HUD布局与通知去重

v0.8.2；2026-10-03；源码、专项和实际Mac发布包独立验收已完成。源码结果与交付包分别记录，最终身份和结果见 [26](26-开发阶段与交付记录.md)。

## 1. 本轮问题与范围

用户反馈：全宽保存状态条遮挡两侧信息，黄色状态文字重复表达同一件事；右侧目标总览竖向空间不足；底部舰况和设备分层占用中央画面，希望二者左右并排，菜单入口移到顶部。

本轮只调整航行HUD布局与通知呈现。继续使用既有舰船、装备、任务、导航、矿池与保存状态；不改数据库结构、平衡数值、存档权威来源、操舰规则或保存稳定条件。矿量和教学预留继续遵守 [34](34-教学采矿保障与矿点情报.md)，常驻光标与左键操作继续遵守 [33](33-指令式操舰与运动重影修正.md)。

## 2. 布局契约

以下是已落地的源码契约；本轮已检查航行几何、滚动和文字可见性，具体范围与实际包证据见第5节。

| 区域 | 要求与内容 |
| --- | --- |
| 顶部入口 | 右上工具条包含“显示舰船”“任务 J”“星图 M”“系统 Esc”四个真实入口，退出底部设备区；紧凑模式的“显示舰船”tooltip保留完整操控说明 |
| 左侧 | 导航与任务分工保持，作业显示实际扫描/采矿信息；任务/作业按实际最小高度排布，雷达随其避让。宽布局操控文字在顶部左侧，紧凑布局隐藏常驻长提示、保留tooltip |
| 保存/全局操作通知 | 居中放在左右侧栏之间，有限宽度并随中央可用空间收窄；保留真实阶段、阻碍、“取消等待”和完整tooltip，不使用全宽覆盖条 |
| 右侧 | 常规布局按可用高度扩展目标列表，保留过滤、排序、真实距离和操作卡；紧凑布局将选中详情置顶，通过侧栏滚动访问详情和列表 |
| 底部 | `flight_dock`为全宽底座，HBox中舰况在左、设备在右始终同排；速度、防护、电容/热量、真实设备周期和开关继续读取实际状态 |
| 雷达与条件交互 | 雷达与右侧总览止于底座上沿，保留实际雷达、F资格提示、单一目标标注和淡白虚线；中央通知与底座的避让由本轮画面验收核对 |

最小窗口1280×720在200%界面缩放下只有640×360逻辑空间。本轮使用紧凑布局和滚动分配空间，不保证所有设备和所有目标同时展开。设备较多时横向滚动设备栏，右侧总览/详情使用侧栏滚动；所有项仍须能访问，文字保持可读字号，不靠缩成难辨小字或裁掉实际数据过关。标准窗口与200%布局已检查舰况/设备同排、标题/菜单避让及通知出现/消失后的重排。

设备区展示真实舰船全槽位。已安装模块保留实际启用状态、周期、冷却、能耗与开关；空槽由当前舰船typed `SLOT` 容器推导，是disabled的只读提示，tooltip说明需进站配装。空槽不伪造模块实例，不写入 `module_records` 作为可用设备，也不改变SQLite配装或数值。

## 3. 通知去重与保存保护

保存、跨系事务和业务反馈按实际来源呈现。保存等待和提交是持久状态，由紧凑操作提示承载；Main删除两处重复“等待保存/保存中”的普通通知调用，保存完成、失败和取消反馈保留。本星系导航已有左侧导航及右侧目标卡，不另显示重复的全局导航横幅。飞行中的短期toast在中央通知下方独立小行；只有文字与当前operation完全相同时隐藏，其他失败或不同业务结果仍显示，随后按原短期反馈规则退场，不能把去重变成吞掉错误。

进入菜单后，普通通知放在页面底部预留区；返回航行重新回到中央位置。空间站有普通通知时，服务区及离港按钮让出通知位置；通知消失后恢复。位置切换不清掉仍需显示的失败或保存结果。实际包档案页与空间站普通通知画面已复查；没有将全部错误文本及所有页面组合描述为逐一人工验收。

必须保留 `cancel_save` 入口及实际状态：等待保存只能取消等待请求，不能撤销已应用业务、伪造COMMIT成功或跳过交战、在途弹丸、未完成周期和转移屏障。提交中的真实不可取消阶段继续按原契约禁用按钮。保存成功、等待、失败和业务已应用仍是不同事实，不因为提示收小就合并成同一个“完成”。

“保存并退出/返回主菜单”继续先停止新输入、导航及自动开火；已有周期、弹丸和交战计时推进至可保存边界后再保存离开。可取消保存恢复操作，或明确放弃未保存进度退出；这些入口和保护不因HUD移动而删除。普通业务反馈的显示时长是界面行为，不推进数据库世界时间或资源再生。

## 4. 数据与输入边界

总览仍只选择目标，双击合法实际目标才下令接近；移动菜单和设备不会让鼠标穿透至舰船选择或观察。HUD消费鼠标，飞行键位与菜单/文字输入/窗口焦点隔离沿用原实现。设备开关、增推及选中目标动作继续发真实业务命令，不增装饰按钮或假周期。

当前星系已知矿点可以远距离显示真实余额、容量、教学预留和世界时间再生；未访问外星区不泄露实时库存，已知产物与可读取的实际矿量继续区分。侧栏缩放和通知去重不得删掉矿点信息、已满舱/错设备/预留等真实阻碍，信息来源仍为同一typed DTO与冻结SQLite定义。

## 5. 验收范围与证据

上述源码契约已落地。最终HUD headless246项、Metal/CoreAudio原生324项/20图通过；原生涵盖1440×900与1280×720各100%/200%，追加1920×1080。相关UI104、生命周期27、源码内置表现66项通过，完整输出及独立引擎日志严格诊断0；字体111文件/84表/858字符、缺字/编码缺陷0。已复查标准、紧凑和宽屏画面。检查范围：

- 1440×900与1280×720，各100%/200%布局；标准和最小逻辑空间下的可读文字、底栏同排、无相互遮挡及舰船中央可视区。
- 多设备、真实全槽位/空槽、多目标与较长中文名称；实际滚动可访问末项、完整tooltip及操作按钮，空槽不能发出设备业务。
- 保存等待/取消/提交/失败/成功、保存后退出及菜单切换；完全相同操作文字去重，非重复错误仍可见；菜单返航行与空间站通知不得遮挡操作入口。
- 实际导航、目标卡、雷达/F、矿点情报、设备启用/真实周期及输入消费回归；不沿用旧布局断言代替新布局检查。
- 实际Mac发布包独立检查、资源/数据库/临时签名及构建身份；Windows原生仍须实机。

实际Mac发布包已独立运行66项/11图通过，6项数据库、125项资源和临时签名通过，8份构建日志严格诊断0；构建`0.8.2-f9063ee1-20261003-212516`、两个ZIP摘要和交付路径在26登记。源码结果与实际包分别验证。全部专项使用独立tmp SQLite；位置、解锁、九舰及长通知为明确夹具，不代替个人档案人工试玩或自然通关。最终构建身份和实际包结果在26登记。
