# 星系尺度、跃迁体验与任务筛选

2026-10-06，v0.15.0。用户选择真实战略航路＋局部空间：各地点在同一恒星系内有真实的天文位置，地点附近以米制物理操舰，地点间由跃迁连接。星图中的跨星系虫洞网络仍是拓扑示意，没有虚构光年坐标。

## 原有尺度核查

v0.14.1 的十系可交互锚点跨度只有13.162–15.157 km，站到门3.000–5.978 km，站到矿1.882–3.002 km，站到信号1.651–4.202 km，站到敌群约3.394–9.434 km。多数后续星系复用布局。恒星使用约26–28 km压缩坐标，背景行星中心约9–10 km、半径1.8–2.3 km；普通几公里飞行就有过大的天体视差和来光方向变化。`sector_runtime_defs.bounds_radius_m`原先未在运行时执行。

本系导航v1最短300m、20km/s、充能2s，且检查目标中心距。空间站中心510m时，500m落点只需移动10m，也能触发跃迁；大多数运行段仅几帧。旧画面只有40条二维低透明度径向线，没有环境模糊和世界航向尾流。

原来的距离文字并非全部为m：总览已有m/km换算，雷达固定km，投影标签和设备射程固定m，口径不一致。

## 新空间与单位

正式catalog schema6 / `v0.7-space` / `singleplayer_space_v3`，新增`site_defs`、`anchor_site_defs`、`celestial_defs`三表。79地点、160锚点唯一映射、20天体；十系最小地点间距0.019–0.136 AU，最大地点跨度1.887–6.316 AU，各星系不再复用同一战略布局。

`site_defs`存储真实米制战略中心和旧局部基准pivot。已有锚点和实体xyz仍是唯一的局部位置，世界位置按`site中心 + encoded位置 − pivot`推导；三轴战略值用SQLite REAL和GDScript float64标量计算。地点内Vector3、碰撞、炮弹、舰船跟随相机保持米制，绝不将AU绝对位置交给Node3D。Godot标准Vector3是单精度，直接在1 AU米制坐标上模拟会丢失公里级精度；双精度构建还需重编引擎、模板和原生扩展。[Godot 4.7坐标说明](https://docs.godotengine.org/en/4.7/tutorials/physics/large_world_coordinates.html)。

`spatial_state`明确绑定所有船体、NPC和残骸的site，包含死亡/归还历史。NPC固定在出生地点，实体真正删除才删除绑定。场景中只显示当前地点实体并开启其碰撞；其他已知地点作为隐藏战略目标，用真实距离和单位方向绘制航向符号，不能冒充局部回波。各地点局部航行半径150km，以encoded位置减pivot计算，越界制动并提示使用跃迁；地点间不提供连续普通飞行。

统一`XJSpaceUnits`：不足1km用m，较远用km，达到0.001 AU才用AU，防止小距离显示为0.00 AU；局部速度m/s、高弹速km/s、战略跃迁AU/s。1 AU严格等于149597870700m，不是重贴标签。[IAU定义](https://iauarchive.eso.org/public/themes/measuring/)。远景天体按真实方位和角半径投影到安全裁剪内，局部移动不会令恒星像近处灯具迅速转位；战略航路和换地点则改变方位、角大小和方向光。

以下局部规则保持已有玩法的尺度，没有统一乘倍率：

| 项目 | 现有局部规则 |
| --- | --- |
| 停靠 / 航门 / 残骸回收 | 600m及20m/s / 120m及20m/s / 100m |
| 扫描 / 采矿 / 维修 | 基础扫描500m、阵列3–3.45km / 180–207m / 250–287.5m |
| 玩家标记 / 雷达档 | 6km / 500m、2km、6km |
| NPC发现 / 丢失 / 巡逻约束 | 800–1400m / 1200–1900m / 1–2.4km |
| 常规舰速 / 加速度 / 巡航 | 80–300m/s / 4–35m/s² / 3倍 |
| 武器 | 脉冲600–980m、针锋900–1320m、热束1050–1650m、中轨1.7–2.6km、重轨2.6–3.8km、无人机控制1.2–1.85km |

这些值来自正式SQLite，属于局部战术规则。任务抵达、作业周期、伤害、NPC感知、安全区、仓库服务、航门与停靠都验证同地点身份，防止两个地点恰有相同encoded坐标而绕过资格。

机库是独立展示舞台，室内灯保持展台照明；新版舷窗使用当前冻结内容中空间站的真实天体方向、角半径和恒星光向，按实际相机到窗片的射线呈现，天体不在窗外视野时不会强行绘制固定蓝色行星。原机库材质/清单字节保留，旧世界恢复原材质。

## 导航与演出

保留v1数据库/清单和旧规则路径，新增独立固定`local-navigation-v2`。新空间世界使用v2：到安全落点的**实际航程**至少150km；充能2s并按舰体真实转速对准；战略平均速度0.18 AU/s，短合法航程至少3s。最短时间限制实际航行速度，不让特效单独拖延已完成的位置。

远站“停靠”或远地点“接近”先提交稳定出发快照，再跃迁到安全落点，最后进入局部接近/停靠；远地点环绕先明确要求抵达。当前地点附近目标只使用接近/停靠。战略航路进度只推进float64标量，暂停冻结，暂态过程禁止保存和业务操作，抵达现场检查后才转移site和发布自动快照。取消/失效返回已持久保存的出发地点并归零速度；这是战略航路方案的明确边界。局部v1连续航行保留实时安全采样，采样预算封顶256。

新跃迁演出使用HUD之前的屏幕颜色：低强度定向采样和mipmap虚化，投影舰体包围盒形成柔边清晰区域；绑定实际插值姿态和世界航向的3D细流线从舰旁向后延伸，镜头轻微增加4度视野，有0.35s渐入/退出。强度0关闭模糊、尾流和镜头扩展，暂停冻结时钟，世界卸载立即复原。表现不消费玩法随机数、不参与碰撞/伤害/持久位置。[Godot屏幕读取](https://docs.godotengine.org/en/4.7/tutorials/shaders/screen-reading_shaders.html)。

## 任务界面

将七个互斥且混合含义的按钮拆成独立类型、状态、地点三组，短标签和明确选中样式，筛选相互保留。默认全部类型/全部状态/本站（飞行时本星系）；推荐卡显示实际任务名和状态，未接取标记接取站，进行中标记任务目标，待交付标记交付站。精确前置任务入口清除状态/地点限制并定位实际任务类型与页码，锁定或远站任务仍可查看；空结果可清除筛选。任务前置、解锁、借船、驻站、冷却和限额的真实资格没有放宽。

## 旧档与验证边界

新增011/format8、固定v0.7适配器；001–010原始迁移和旧冻结定义保持。先完整备份，在新规则分支增加实体地点上下文，保持旧xyz、资产、装备品质/耐久、信用、任务与RNG。船在站时按明确站点，NPC按出生锚点，旧空域船/无来源残骸在迁移中按最近旧pivot确定唯一映射；这只用于升级，不作为新版运行时缺失上下文的兜底。可模拟舰船或未回收残骸超150km时拒绝升级并保留原位，用户可用旧规则返航/回收后重试；已毁/归还船体是历史记录，保留原始远处坐标与绑定，不渲染，也不永久阻止世界升级。新候选准备、封印、指针发布或提交失败都回滚，旧手动槽保留，成功后同源端点幂等复用。

专项入口：`test_space_catalog.py`，`verify_combat_v18.py --only mission-display spatial-business spatial-navigation warp-visual space-upgrade`。源码及实际Windows PCK使用同一受限固定Node入口，所有测试数据在fresh UUID tmp库。原生像素检查区分背景变化、舰体与HUD保护，另有真实导航链、SQLite重开及升级故障注入；不把夹具授权的解锁/站位宣称自然通关，也不把本机检查宣称长期平衡或所有硬件性能保证。最终运行计数、包身份和日志见[26](26-开发阶段与交付记录.md)。
