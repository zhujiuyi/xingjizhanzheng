# 数据服务实现与验证

本页记录已实现的数据服务。设计契约见 [17](17-首版行为与实现契约.md)、[18](18-进度数据库与存档实现规格.md)、[21](21-模块接口与开发验收规格.md)；当前实现入口为 [XJGameStore](../code/runtime/data/store.gd)。服务不把状态塞入JSON/BLOB，数值从catalog或对应世界的冻结副本读取。联机、服务器与并行后台写入不在本实现范围。

## 1. 数据身份与正式结构

当前进度格式5，按编号应用 [八份固定SQL](../code/database/progress/README.md)，包含131关系表、365触发器、32组持久状态。旧001–004格式1仍按原字节核验；005增加高级内容与基地状态，006增加异常解锁及游离虫洞寿命，007记录菜单当前世界，008将付费推进周期的保存许可扩展为受审engine组。

当前v0.4-singleplayer catalog有84表、4个派生视图。一次封存复制全部定义记录和表/列/复合主键manifest，并记录视图定义的UTF-8原文摘要。当前构建内容逻辑摘要为 `d0afb0813f3bbddcd5efcb3865b894095d57ad55825efdbcb55973806a24e8ac`；数值种子升级后应以数据库自身摘要重新核验，不能把本页文本作为运行权威。加载按冻结适配器重建独立内存catalog并核逻辑摘要，不执行存档内的视图/DDL文本。已封存定义、manifest和状态不可直接修改。

完整兼容身份为catalog内容摘要、规则代码版本、资产版本、canonical资产清单摘要和固定适配器版本五元组。当前规则代码 `singleplayer_full_v1`、适配器 `frozen_catalog_v0_4_r2`；旧B档仍支持 `singleplayer_b_v1` 与 `frozen_catalog_v0_3`。不相同的完整身份不会复用冻结副本。

正式资产清单为 [assets/manifest.json](../code/assets/manifest.json)，版本art-full-v1、79条资源，canonical摘要 `1ec8b2bfdcbd1fc75d0d9749b416f651df564f6b3a4eeec1a4e348da4e9a0e6e`。每条原始文件另按真实bytes做SHA256校验。旧placeholder-b-v1清单仍有显式路径映射，供旧档兼容；不会用排版后完整JSON的文件摘要代替canonical摘要。

## 2. 稳定服务接口

| 类型/路径 | 接口与责任 |
| --- | --- |
| [XJCatalog](../code/runtime/data/catalog.gd) | `open(path)`、`rows(table)`、`one(table,key,value)`、`rule(parameter_id)`、`last_error`；只读缓存返回副本，核受审结构和catalog_hash_v1 |
| [XJRuntimeState](../code/runtime/state.gd) | typed `snapshot`，world/session/epoch/capture_sequence上下文；`rows/find/add/remove/player/ship/current_sector`；32组DTO数组 |
| [XJStateCodec](../code/runtime/data/codec.gd) | 显式NULL标志、SQL标量、enum名称与typed DTO双向适配；不存Node、Vector3或任意配置字典 |
| [XJInitialState](../code/runtime/data/initial_state.gd) | 从数据库构造保障舰、所有船槽、已装设备/耗材、普通起始材料、任务offer、世界矿点/门/商店及随机流 |
| [XJGameStore](../code/runtime/data/store.gd) | `open/new_world/save/load/list_slots/resume/clone_state/save_endpoint/set_transfer_barrier/backup/prune/preferences/set_preference` |
| [XJRng](../code/runtime/rng.gd) | `initialize/valid/next_uint32/bounded`；PCG32整数limb实现，直接恢复hi/lo状态 |

`load(slot_id,expected_snapshot,expected_generation,prepare)` 支持固定槽选择和CAS。`staging_catalog`仅在prepare阶段提供目标世界冻结定义；调用方用它搭建候选场景。失败后清空，成功切换后成为当前catalog。

`new_world(name,seed,prepare)`也支持候选构造：完整内容身份、初始状态与冻结catalog核验后调用prepare，成功才封存/发布槽并COMMIT。构造失败回滚新世界全部记录，保留旧active_state/catalog/profile身份，旧世界仍能保存。新建阶段在一个暂停串行写事务中完成准备；加载阶段则不持数据库事务构造场景。

`profile_resume`独立于世界的快照端点，成功新建、保存或加载时与会话更新同事务写入。`resume()`只选该世界的合法已封存resume_snapshot_id，避免在多世界间根据最近自动槽误选。旧格式首次升级缺少真实跨世界激活时间，迁移按最后持久端点确定一次fallback；此后记录精确激活身份。

显示偏好写入独立 `profile_preference`，验证鼠标灵敏度、0–1音量/特效强度和质量档位。缺少偏好行的新profile使用鼠标灵敏度0.002 rad/pixel；已有显式值保持原值，打开设置不自动覆盖。偏好不随个人回档还原。初始设备enabled代表许可开关，扫描/采矿/推进仍由明确请求启动；免费基础推进不因此耗能。

## 3. 原子保存、加载与跨区端点

当前为暂停模拟后的串行写入，公开busy/phase和status_changed；SQLite busy_timeout为2秒。没有工作线程，也不会逐帧写库。业务原子内存操作与持久成功分开，只有COMMIT返回true。

保存先核活跃world/session/epoch，深复制完整typed状态并分配新请求/快照/捕获序号。一个IMMEDIATE事务内插入全部状态、验证预算和外键、封存、CAS更新槽generation、推进session提交序号与resume、更新菜单当前世界；任何步骤失败ROLLBACK，原槽端点不变。手动与自动槽由数据库约束控制。旧会话或旧序号不能写回已加载世界。

加载屏障由客户端暂停/排空旧操作。服务在读事务固定槽快照/generation，核冻结内容、资产、DTO/数据约束，结束读事务后用prepare构造场景；直到准备成功才在写事务CAS更新session/epoch和当前世界。准备失败保留旧epoch和旧世界，原世界仍可保存。切换成功后旧epoch写入拒绝。

跨区调用方先完成出发地保存和转移屏障，深复制候选状态，在候选中一次写齐目的地、位置、成本和转移receipt，候选场景准备成功后 `save_endpoint` 持久完整目的地。读取仅恢复已提交端点，不恢复半段动画。相关玩法资格和场景装配由主客户端负责；数据服务验证端点receipt及数据库一致性。

已付费引擎周期保存active_remaining/cooldown/cycle_paid，恢复不二次扣费。其他活动工作周期、敌对AI acquire/pursue/attack/disengage由上层SaveEligibility推迟，SQL封存再次拒绝。游离虫洞剩余寿命以世界时间存储，固定门为NULL；是否已解锁和何时开始倒计时由玩法状态判断。

## 4. 升级、备份与保留

打开已有库先检查application_id、格式、迁移数量和每份固定SQL的SHA256。未知格式、摘要改变或结构/DTO注册缺失立即拒绝并保留文件。升级前通过SQLite Backup API生成临时备份，验证物理/FK完整性及每个冻结内容摘要，再原子改名。所有待执行迁移在同一延迟FK事务完成，失败还原旧格式及旧端点。

磁盘备份验证使用SQLite原生文件VFS并启用query_only；packed资源catalog才用插件Godot只读VFS。备份目标必须确实存在后才打开，不能让验证连接创建空库。已精确复现插件只读VFS打开中文外部绝对路径报Error7，即使Godot FileAccess确认文件存在；同副本用native VFS及query_only可通过。该问题在Editor也出现，客户端默认中文app_userdata路径的升级备份据此修复，并非文件被锁。实际旧格式2库已成功升级5，原格式2备份保留且两者integrity均ok。

`prune(keep_recent)`保留所有手动/自动槽、世界初始化grant、session加载点和resume点，以及每世界最近N份记录；lineage允许删除中间祖先。资产或规则更新不自动替换旧世界的冻结定义。有效旧档不可通过删除绕过迁移。

```sh

```

当前Python31项通过，覆盖关系约束、完整引用闭包、内容冻结、资产身份、事务阶段、槽CAS/epoch、任务/借船状态和原子跨区端点。原生Godot4.7.2+SQLite扩展数据服务共247条断言通过：历史B内容72、完整当前内容75、历史升级52、独立跨区控制器48；运行日志在 `jiaoben/logs/store-native.log`。

原生覆盖32组全部DTO字段往返、真实新建→保存→关闭→重开→加载、基地状态、II/III引擎有效周期、保存state/seal/pointer三故障点、新建/加载场景prepare失败、旧槽选择/旧epoch/旧捕获序号拒绝、备份/保留、独立偏好、跨世界继续及PCG32官方42/54黄金六输出与SQL恢复后的128输出。格式1历史库由原四份SQL和 [历史夹具](../jiaoben/tests/store_fixtures/README.md)创建；005–008任一步故障均回滚，重试升级格式5后仍能读旧73表内容及placeholder资产。历史迁移摘要篡改被拒绝。独立 [travel审阅](../jiaoben/tests/store_travel_review.gd)覆盖取消、起点保存/目的场景/目的地保存失败不扣费，成功仅扣一次、旧origin回调拒绝、重开恢复destination。它不替代实际3D穿门/碰撞测试。故障注入证明事务与保存端点，不模拟断电、磁盘损坏或外部恶意改库。

另以真实Main、UI、Gameplay和关系存档运行 [客户端生命周期边界](../jiaoben/tests/client_edges.gd)，headless缺省Dummy后端的28条功能断言通过，但 [进程检查入口](../jiaoben/tests/client_edges_run.py)的退出guard未通过，日志 `jiaoben/logs/client-edges.log`。覆盖新建/加载prepare失败时原场景与原会话保留且仍可保存、手动等待请求不被自动保存替换、暂停冻结世界时间和脱战倒计时但保存等待提示按真实UI时间出现、UI遮挡期间松开鼠标仍清除射击/观察保持状态、远端毁舰后救援重建完整目的星区目标并能COMMIT、实际“不保存并退出”按钮取消待保存意图且槽端点不变，以及新缺省灵敏度和已有显式值保留。测试使用独立tmp库和独立 `--log-file`，不覆盖实际GUI客户端默认日志；仅两个刻意注入的STAGING_FAILED为预期，其他ERROR、WARNING、脚本错误或超时仍使guard失败。

该生命周期测试在退出前等待有限UI确认音按资源时长自然结束，模拟新页面显示后再点击退出；等待期间世界仍暂停。测试已将同栈 `host.free()` 改为标准 `queue_free()`，Dummy复验仍出现3个ObjectDB引用与1个资源退出告警。verbose记录 `jiaoben/logs/client-edges-verbose.log`定位为两个AudioStreamPlaybackWAV和 `ui_confirm.wav` AudioStreamWAV；尚未证明是测试即时销毁单独造成，也未可靠消除该Dummy后端退出时的音频引用释放问题。没有修改运行时代码、关闭guard或为游戏新增退出延时。该Dummy运行只认定功能断言通过，不认定进程检查通过；玩家交互、视觉、音频听感或Windows宿主实测需独立证据。

随后对同一脚本显式指定 `--audio-driver CoreAudio`：锁定引擎帮助确认headless缺省使用Dummy，CoreAudio为本机支持的原生后端。verbose日志确认CoreAudio实际运行，2声道、48000Hz、512frames；28功能断言及相同严格guard均通过，无WARNING或资源退出告警，证据在 `jiaoben/logs/client-edges-coreaudio.log`。测试入口已提供该选项并分开日志；Dummy失败证据保留。该对照证明本机复现存在音频后端差异，不能推导Dummy或所有其他宿主问题均已修复。真实Mac图形客户端使用原生后端，其独立运行记录见26。

独立包的原始资源由 [XJ Raw Asset Integrity导出插件](../code/addons/xj-asset-export/plugin.gd)使用 `EditorExportPlugin.add_file(...,false)` 注入，同时保留Godot默认导入/remap行为。[官方导出接口](https://docs.godotengine.org/en/stable/classes/class_editorexportplugin.html)支持此附加文件方式。官方Release模板不接受外部路径/脚本override，因此 [store_release.gd](../jiaoben/tests/store_release.gd)仅作为Editor/PCK辅助探针；实际app使用 [固定内置诊断](../code/runtime/data/diagnostic.gd)，显式flag和绝对jiaoben/tmp环境路径共同启用，无任意脚本加载入口。
