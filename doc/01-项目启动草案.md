# 星际战舰 · 项目启动草案

本草案保留立项与首版开发准备阶段的需求和决策。完整单人内容与桌面客户端已实现；当前开发、构建和验收状态以 [开发阶段与交付记录](26-开发阶段与交付记录.md) 为准，v0.8.0操作契约见 [操舰与运动修正](33-指令式操舰与运动重影修正.md)。下文“待实现”描述原准备阶段，不作为当前未开发功能清单。

## 已确认需求

- 游戏名：**星际战舰**。
- 核心活动：在星际间探索、采矿和战斗，完成相关任务。
- 玩家可操作不同样式、类型和功能的星际战舰。
- 参考 EVE 的多星系、资源分布、势力科技、舰船配装与风险收益设计；本项目的采用与改编边界见总纲和 EVE 参考文档。
- 工作区分工：`code/` 保存游戏代码；`doc/` 保存设定和技术文档；`jiaoben/` 保存测试、临时脚本和文件。
- 交付目标：3D 游戏，以 macOS `.app`、Windows `.exe` 独立客户端运行；视角与操控已有原型默认值，最终手感和画面风格待样例验证。
- 技术栈已确定为 Godot 4 标准版 + 有类型标注的 GDScript + Forward+ + Blender。Unity 保留为历史备选；用户已授权后续按所选路线文档完成必要开发软件安装。
- 只供自己和朋友玩，不公开发行；不采用需要收费授权的技术栈，不安排付费发行签名与公证。
- 需要飞行操作与视角转换，以及穿梭器虫洞穿越和舰船战斗的视觉效果。
- 朋友电脑主要为 Apple Silicon Mac 或近几年带独显的 Windows 电脑。
- 保存与读取存档必须使用数据库；舰船、装备等游戏数值也必须由数据库维护。
- 世界包含多个星系，各有侧重或独有产出；星系/所属势力的舰船、武器、护甲科技有差异。
- 星系通过特定虫洞传送门连接；采用高、中、低安全区，NPC 等级有所不同。
- 要在上述要求基础上参考 EVE 的成熟系统，编写完整设定；示例不代表全部范围。
- 第一阶段先完成单人闭环，保留联机所需的数据和接口，不把同场联机作为首版交付前提。

技术路线见 [Godot 技术方案](05-技术栈与空间玩法建议.md)，数据库设计见 [数据库与存读档技术方案](10-数据库与存读档技术方案.md)。整体设计以 [游戏设定总纲](06-游戏设定总纲.md) 与其链接的分文档为准；原创名称、具体数值和阶段划分均是第一版提案。

## 建议的首个可玩闭环

以下作为首版单人原型的实施基线，具体手感通过样例调整：

**选择战舰 → 出航探索 → 发现资源点并采矿 → 遭遇敌舰并战斗或撤离 → 返航交付任务。**

- A 技术样例与 B 首个可玩闭环的内容范围统一以 [总纲分期](06-游戏设定总纲.md) 为准；B 为锚港、回声带和四种基础舰船。
- 新世界、教学借船、任务交付、换舰、存档与跨区恢复按 [首版实现契约](17-首版行为与实现契约.md) 实施。
- 数值基线与数据库材料见 [数值系统](15-数值系统与平衡基线.md)。

## 实施选择与后续实测

- 首版先在本机 Mac 验证，再交付 Windows x64 试玩；Mac 包 universal，实际目标优先 Apple Silicon。Windows 原生运行属于首版交付验收。
- 最终 3D 表现风格、镜头与操控手感；原型先使用实现契约中的默认方案。
- 后续是否开放同场联机、合作人数与接入方式；首个版本单人已确认。
- Godot、数据库扩展和导出模板已核验固定，见 [22](22-工具链锁定与技术验证.md)；升级时重新检查兼容性。
- 通过样例测量确定画面质量与性能预算；内容和验收先按总纲及实现契约推进。

目录规则、正式内容库、关系存档、完整单人玩法与桌面客户端均已实现。当前验收与交付见 [26](26-开发阶段与交付记录.md)；[21](21-模块接口与开发验收规格.md) 保留初始接口与编码契约，不作为当前未完成清单。
