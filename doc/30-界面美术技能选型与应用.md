# 界面美术技能选型与应用

2026-10-03按用户要求检索、下载并应用游戏开发技能。目标是0.5客户端的整体界面与美术重塑，处理光标偏移转向、镜头构图偏移、界面缺乏材质及空间站只有菜单的问题。具体实现和实测见 [29](29-操控与界面重塑方案.md)。

## 来源与安装

选择 [gamedev-skills/awesome-gamedev-agent-skills](https://github.com/gamedev-skills/awesome-gamedev-agent-skills)，源版本锁定 `d4b0e35550c55ae70bdfcab4ef5a0e94610438a9`。通过GitHub API核对仓库和Apache-2.0许可，读取实际技能与所引用的参考文件后安装。技能提供工作方法与代码参考，没有要求购买素材或外部生成API。

使用Codex自带skill-installer安装到本机 `/Users/a0000/.codex/skills/`。默认HTTP下载曾遇本机Python证书链错误，改用安装器的Git方法成功；未禁用TLS校验。每个目录保留上游 `LICENSE.upstream`。安装位置、源提交及每份 `SKILL.md` 摘要记录在 `jiaoben/gamedev_skills_install.json`。

新安装技能需在后续任务启动时被自动发现。本轮已经逐份读取并实际应用，不以是否自动出现在技能菜单作为实施完成的依据。

## 已应用范围

| 技能 | 本项目实际应用 |
| --- | --- |
| `game-ui-ux` | 飞行信息层级、中心视野留白、颜色语义、服务与业务页导航、可取消保存及键盘焦点 |
| `godot-ui-control` | Theme、锚点与容器、可滚动卡片、分辨率重排、100%/200%字体与焦点链验证 |
| `create-game-assets` | 定义工业科幻形状/调色板/材质/灯光；原图来源、摘要、导入参数、实际上下文审核及资产清单 |
| `game-feel` | 相对鼠标角度请求、观察与转舰分离、观察结束回正、HUD即时状态与操作反馈 |
| `godot-3d-essentials` | 实际3D机库、人员模型、私有表现层与Environment、舰船纯视觉展示、法线和原有碰撞分离 |
| `camera-systems` | 以实际舰船为镜头中心、平移指数平滑后精确瞄向中心、舰首继承舰姿、碰撞遮挡与观察回正 |
| `godot-shaders` | 金属纹理的sRGB采样、低幅度材质变化、原舰色/玻璃/发光保留、UI切角金属模块 |

图像生成另使用已提供的 `imagegen` 技能和内置图像工具，制作原创标题主视觉、四职业肖像图集及低对比金属纹理。实际工具没有披露模型标识，因此资源清单不编造模型版本。首次金属图在3×3重复审核中发现接缝，重新编辑后才用于正式效果；两次来源均保留。没有输入EVE游戏纹理、模型或角色图。

## 交付与数据边界

界面、机库与舰船表面采用统一的碳灰金属、冰蓝信息和少量琥珀警示。参考EVE的工业空间氛围、功能层级及舰船尺度感，所有新增图像、3D模型、布局和代码均为本项目原创。肖像为2D插图；场景职业人员为单独的3D模型，不能把肖像质量当成人物网格质量。

新增 `interface-v2` 与 `hangar-v2` 表现包拥有独立资源清单、来源和摘要；导出时保留原始字节，实际客户端启动和固定发布诊断均核对表现包完整性。原79条 `art-full-v1` 资源及SQLite内容库保持原摘要，原存档的冻结内容身份不被替换。美术几何、材质和布局参数不定义战舰战力、经济平衡或持久状态；这些继续由SQLite统一管理。

技能安装与读取本身不构成验收。验收使用真实Godot客户端、Metal渲染、不同分辨率和字体比例、九舰镜头投影、已有存档恢复及实际Mac包构建检查；证据与限制随29及 [26](26-开发阶段与交付记录.md) 记录。Windows交叉导出成功也不等于Windows真实宿主运行通过。
