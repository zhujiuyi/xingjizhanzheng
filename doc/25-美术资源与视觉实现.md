# 美术资源与视觉实现

本轮交付 `art-full-v1` 原创运行资产：9 艘玩家舰船、1 艘遗构无人舰、轨道站、锚定虫洞门、8 种矿体、残骸，共 21 个 GLB；另有碰撞/挂点场景、10 个星区资源入口、4 个 shader 和 15 个原创合成音效。它们已实际导入 Godot 4.7.2，以 Metal Forward+ 渲染检查。完整游戏事件接线与客户端性能验收由运行模块负责，不能以资产截图代替整机测试。

## 1. 参考范围与原创边界

EVE 官方舰船入口区分护卫、驱逐和采矿/工业舰，本项目借鉴“角色能从轮廓辨认”的表达方法。我们的船名、几何、部件布局与配色由本项目重新设计，没有下载、解包或提取 EVE 的模型、贴图和音频。[EVE Academy · Ships](https://www.eveonline.com/eve-academy/ships)

EVE 官方工业舰资料强调货舱、容器及装卸设备；将运输舰画成外露货柜、将采矿舰画成有工业工作臂，是本项目的美术解释，不是对 EVE 舰型的复刻。[EVE Universe · Industrials](https://universe.eveonline.com/lore/industrials)

EVE 的虫洞视觉开发记录用变化的边缘、色彩及目的地空间景观提供信息。本项目只借鉴“效果应表达状态”：固定金属门框围绕原创螺旋光流；可交互、充能、拒绝状态由游戏/UI 显示，shader 不自行决定通行条件。[官方虫洞视觉开发记录](https://www.eveonline.com/zh/news/view/visual-update-of-wormhole-space)

## 3. 坐标、几何与碰撞权威

运行统一使用米、Godot `+Y` 上、`-Z` 艏向。Blender 建模使用 `+Z` 上、`+Y` 艏向；glTF 导入映射为 `(x,y,z) → (x,z,-y)`，三轴实测证据。

固定几何由 `code/assets/models/geometry.json` 和受版本控制的 `.tscn/.glb` 保存，不写入 catalog 的第二份船体尺寸。9 艘玩家舰长度/宽度/高度为：雨燕 18/10/6、提灯 28/14/8、游隼 30/18/9、铁砧 56/36/20、矛隼 70/30/18、远际 115/60/34、磐垒 220/110/65、长旅 145/75/48、织桥 90/65/28 米。这些是版本化模型结构，不是可热调的战斗数值。

`code/assets/ships/` 的 10 个 wrapper 包含 `CharacterBody3D`、固定盒碰撞、`VisualRoot/Model`、`Hardpoints`、`FXAnchors/engine_*`、`CameraTarget`、`FrontCamera`、`InteractionAnchor`。前 4 舰的碰撞尺寸、功能挂点与镜头标记保持原占位场景约定；其余玩家舰的槽数逐一对应 `ship_slot_defs`。遗构无人舰具有独立几何，不冒充玩家 catalog 舰型。

`code/assets/objects/` 的站、8 矿、残骸采用实际导入 GLB 的 AABB 生成固定盒碰撞；站点外包围盒为 440×230×440 米。门框使用 12 段固定复合碰撞，保留中央通道；视觉门框尺寸约 205×205×30 米。碰撞层初值为环境 1、舰船 2，运行方可设置查询 mask。该版采用简化体积碰撞，命中不逐三角匹配装甲缝隙。

更改外形、碰撞、挂点或视觉解析代码后，必须重建 manifest 并升级资产兼容身份。旧存档使用 `asset_manifest_version + asset_manifest_sha256` 校验，不能无提示地混用旧档和新几何。进度兼容规则见 [18-进度数据库与存档实现规格.md](18-进度数据库与存档实现规格.md)。

## 4. 加载接口与星区装配

入口 `code/runtime/visuals/visual_factory.gd` 提供 `XJVisualFactory`，不包含游戏控制器：

| 调用 | 输出 / 约束 |
|---|---|
| `ship(ship_id, color=TRANSPARENT)` | 仅可视 Node3D；可选染色不改变发光识别色 |
| `scene(ship_id)` | 含固定碰撞与挂点的 CharacterBody3D；不存在的 ID 返回 null 并报错 |
| `geometry(ship_id)` | 只读固定几何元数据，运行方不从 DB 另造尺寸 |
| `static_body(kind, entity_id, resource_id='')` | station/gate/ore/wreck 的 StaticBody3D；矿以资源 ID 选模型 |
| `enemy_scene(archetype)` | scout→游隼、raider→矛隼、guardian→远际、silent/relic→遗构；也接受具体玩家舰 ID |
| `station/gate/ore/wreck/enemy` | 仅可视 Node3D，适用于展示，不应另外猜碰撞尺寸 |
| `sector(sector_id)` | 10 个 `scene_sector_*` 场景入口；站、矿、门及出生位置仍读取 catalog anchors |
| `space_background(config)` | 含一个 WorldEnvironment 的背景根节点；调用者避免再建重复 WorldEnvironment |
| `sound(sound_id)` | AudioStream；循环音效返回独立 LOOP_FORWARD 音频实例 |
| `configure(node, profile)` | 接收运行方的可见距离和阴影设置，不另存平衡默认值 |

`scene_sector_*` 与 catalog 的 `sector_runtime_defs.scene_asset_id` 一致。通用星空/星云接收 `visual_seed`、`nebula_color`、`nebula_accent`；视觉噪声不消费世界 PCG 随机流，不生成掉落或改变存档。新增地点通过 catalog 坐标装配，不将一套任务位置复制到 10 个场景。

## 5. 特效、预算与音频

`XJVisualEffects` 返回受星区根节点持有的纯视觉对象，删除/替换星区时一并清除：

- `beam(from,to,color,config)` 表达已经判定的光束路径，不计算命中；宽度、寿命读取 `fx_beam_width_m`、`fx_beam_lifetime_s`。
- `shield(radius,color,config)` 表达命中反馈；寿命读取 `fx_shield_lifetime_s`，输入半径来自固定模型几何。
- `explosion(at,radius,color,config)` 采用一次性发光粒子，读取 `fx_explosion_lifetime_s` 和 `explosion_particles_near`。运行方用模型尺度及 `fx_explosion_radius_ship_multiplier` 得到视觉半径。
- `wormhole(radius,color,config)` 采用可动画螺旋 shader，读取 `fx_wormhole_intensity`；门框半径属于固定几何。
- `engine_trail(nozzle_radius,color,config)` 读取 `engine_particles_near`、`fx_engine_particle_lifetime_s` 和 `fx_engine_emission`；拖尾从挂点 `-Z` 喷出，不产生推力。

缺失非正的必需表现参数会拒绝创建该效果并给出诊断，不暗中补第二套数值。定时 shader 使用节点视觉时钟，避免 Godot 的 `TIME` 在暂停时继续推进；游戏暂停/跳跃屏障仍由运行方统一控制。空间/实体 shader 依据官方语法实现。[Sky shader](https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/sky_shader.html)、[Spatial shader](https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/spatial_shader.html)

舰船各 5 个材质面，站/门各 3 个，矿/残骸各 2 个；最多的单个模型为磐垒 16,012 三角。GLB 导入设置开启 `meshes/generate_lods`，Godot 按屏幕尺寸选择自动网格 LOD；DB 的 near/mid/far 距离用于运行表现档位，不宣称自动 LOD 恰在这些距离切换。全局实例、粒子、动态光与声道预算由运行调度器应用 catalog 值，helper 本身不是全局预算管理器。[Godot Mesh LOD](https://docs.godotengine.org/en/stable/tutorials/3d/mesh_lod.html)

15 个原创 44.1 kHz、单声道 16-bit WAV：确认/错误、引擎循环、采矿循环、修理循环、站点环境、三类开火、扫描、跃迁充能/到达、护盾命中、装甲命中、爆炸。编码与波形时长属于媒体；音量和混音预算读取 `audio_*` presentation 值，音效播放不能改变业务周期或奖励。

## 6. 可重建来源与清单

编辑母版位于 `code/assets/source/original_fleet.blend`，所有模型置于独立命名 collection。该目录 `.gdignore` 隔离离线母版，运行只加载 GLB，不要求用户安装 Blender。正式源文件保留，导出客户端无需携带母版。

生成脚本依次为 `jiaoben/art/build_models.py`（Blender）、`build_audio.py`（Python）、`build_wrappers.py`（Python）、`build_static_wrappers.gd`（在 GLB 导入后读取实际几何）、`build_manifest.py`（Python）。构建顺序：离线模型/音频 → 舰 wrapper → Godot import → 静态 wrapper → manifest。模型 builder 每次重新写几何基础，必须执行后续 wrapper 步骤再发布。过程文件和指标留，日志留在 `jiaoben/logs/`。

正式清单为 `code/assets/manifest.json`，版本 `art-full-v1`，79 条运行资源；SHA256 覆盖资源原始 bytes，manifest 自身使用删除 `manifest_sha256` 后按键排序、无额外空白的 canonical JSON SHA256。当前逻辑 hash：`1ec8b2bfdcbd1fc75d0d9749b416f651df564f6b3a4eeec1a4e348da4e9a0e6e`。清单包含被加载的旧 4 舰占位几何兼容文件，不包含编辑母版或引擎缓存。

导出必须保留清单里的原始资源 bytes；仅能从 Godot 导入缓存/remap 加载，不足以证明 FileAccess SHA 校验可用。正式 `.app/.exe` 的启动和清单验证属于打包验收，源工程验证不能代替它。
