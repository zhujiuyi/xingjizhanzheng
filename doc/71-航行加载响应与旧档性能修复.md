# 航行加载响应与旧档性能修复

## 问题与实测定位

2026-10-14 用户反馈点击新建、继续后客户端卡死，确认约等待 5–10 秒后关闭。原 v0.33.0 Windows PCK 的实际标题鼠标测试复现了连续主线程阻塞：新空库新建约 5.5 秒；个人旧档的关闭副本中新建约 32.6 秒、继续约 7.8 秒。场景准备分别只用约 0.14–0.23 秒，不能将主要阻塞归因于新模型或 GPU 材质。

个人原件及其热回滚日志仅作字节复制；在 `jiaoben/tmp/startup-investigation/` 的副本中让 SQLite 恢复，`quick_check=ok`。个人原件不参与任何写入测试。

旧副本含 56 份快照、38,640 行商品库存。库存状态表只有以 snapshot 开头的主键，无法服务以 content 开头的定义外键查询。冻结新目录的 4,097 条库存定义因此反复扫描历史行。仅在临时副本运行 SQL 冻结复制并回滚的测量为：

| 条件 | 176 表、18,600 行冻结复制 | 其中库存定义插入 |
| --- | ---: | ---: |
| 原索引 | 28.542489 秒 | 27.709723 秒 |
| 两个外键索引 | 0.824471 秒 | 0.020223 秒 |

这是 Python SQLite 的隔离 SQL 测量，不是完整客户端加载时间。实测记录位于 `jiaoben/tmp/startup-investigation/fk-index-probe-ef5306c6-fcd4-40bf-948d-f2fd7ef6913c/benchmark.json`。

## 实现与数据边界

- 新建、继续、手动读档以及保存后退出/返回标题使用同一串行后台任务；普通自动/手动保存仍沿用原有路径。
- 唯一 Store 在任务期间由工作线程独占。Main 及继承子树停止处理，旧 UI 隐藏，延期界面回调由明确的加载门闩拒绝。工作线程结束并 join 后才恢复读取和交互。
- Store 的同步事务、验证、回滚与发布接口不变。准备场景时工作线程通过 Mutex/Semaphore 交接候选状态，等待主线程构建；不在工作线程创建或修改活动场景。
- 独立加载层持续显示当前阶段、真实累计秒数和活动条，不显示估算百分比。关闭窗口时等待档案操作完成后退出；清理先解除 prepare 等待、join，再关闭数据库。
- 新增 `030_loading_indexes.sql`，进度格式升至 27，只增加商品/舰船库存外键索引。原 001–029 SQL、目录数据库、平衡值、封存定义和存档内容保持原有契约。升级前沿用 Store 的关闭备份与校验流程。

线程边界依据 [Godot 线程安全 API](https://docs.godotengine.org/en/stable/tutorials/performance/thread_safe_apis.html) 和 [Thread 生命周期](https://docs.godotengine.org/en/stable/classes/class_thread.html)：活动场景仅主线程处理，退出前释放等待并完成 join。

## 回归入口与验收范围

`py jiaoben/tests/startup_navigation_run.py` 使用真实标题按钮鼠标按下/抬起，验证新建、保存返回标题、继续；加载后各运行至少 5 秒和 120 帧。用户点击期间的最大帧间隔必须低于 1 秒，加载状态须实际渲染并更新耗时，完成后 Main/物理处理恢复。首次可交互标题出现之前单独记录初始化耗时，限定 15 秒，不与点击后的响应预算混为一项。

`--profile-copy <jiaoben/tmp 中已关闭的副本>` 先继续原世界，再返回标题新建，校验输入副本 SHA 不变。`--executable <v0.33.1 EXE>` 仅使用固定 v62 诊断；原 v0.33.0 的反例使用 `--legacy-v61` 在 tmp 下暂存固定后缀的脚本，不修改真实 v61 测试，不挂载源码工程。

源码旧档副本的 46 项检查已通过：继续期间最大帧间隔 170 ms，新建 228 ms，保存回标题 426 ms；加载层分别实际绘制 4,239、1,026、634 帧。旧档首次继续仍须验证历史内容分支，持续时间与新档不同；这里证明界面持续响应，不宣称所有加载瞬时完成。原生共享交互专项 115 项通过，双日志无错误、警告或泄漏。

源码验收：空库启动 42 项、旧档副本启动 46 项、失败/安全停止 30 项、共享交互 115 项、Store 基础 6 项通过，共 239 项。失败专项只允许每份日志各一次固定的 Missing save slot 和 STAGING_FAILED 注入诊断，验证原世界/持久槽保留、旧回调拒绝，以及在等待 prepare 时走真实 Main 退出路径解除等待、join、关闭与重开数据库。其余错误、警告和泄漏仍严格拒绝。

Python 全量 381 项初跑通过 380 项；唯一失败为战役测试仍断言最新格式 26，已更新为 27，该模块 8 项复测通过。新增索引专项 5 项含旧 26 升级、数据/历史 SQL 字节保护、失败回滚和 SEARCH 查询计划，均包含在全量覆盖中。
