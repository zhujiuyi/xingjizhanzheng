# 星际战舰 · 星系与势力科技设定

当前文明与54星系扩展以[49](49-文明声望与星域战争.md)及SQLite文明扩展定义为准。下文十星系表保留为早期蓝图；原十星系现属于中立主权航路，站点经营者与领土归属分开。

版本：v0.1-draft。日期：2026-10-02。状态：完整世界蓝图的第一版提案，名称、产出、科技优势、敌人强度与实施分期尚未实测。

本文件维护星系目录、特色资源、固定航路与势力科技的权威设计表。其他文档引用这些表，不另维护一套。已确认需求见 [总纲](06-游戏设定总纲.md)，世界背景见 [世界观](07-世界观设定.md)，舰船能力见 [战舰](08-战舰设定.md)，活动流程见 [玩法](09-玩法设定.md)，正式数据库 schema 与存档恢复见 [数据库方案](10-数据库与存读档技术方案.md)。

## 1. 用户补充需求与设计边界

已确认要全面研究成熟的 EVE 机制作为设计参考，不能把世界范围限制在探索、采矿和简单战斗几个例子；需要多星系、多势力、差异化产出与科技体系，并通过特定虫洞传送门连接星系。高、中、低安全区的敌对 NPC 强度应有差异。

本提案给出十个核心星系组成的断航星域。**完整设计范围与制作批次分开**：十星系、势力科技链、跨区物流、蓝图制造、任务与战斗体系共同构成蓝图；先制作锚港与回声带用于验证，不意味着成品只包含两个星系。

EVE 官方安全类别是高安全、低安全和零安全；本项目使用“高安全、中安全、低安全”三个原创类别，不能逐字对应或照搬其执法机制与数值。[EVE 官方安全类别](https://developers.eveonline.com/docs/guides/system-security/)

安全程度、所属势力、发现状态与内容阶段是不同属性：一个低安全星系可以已被充分测绘；一个高安全星系也可能存在未知信号。“未知”不等于最低安全等级。

## 2. 星系目录

一个星系包含恒星、行星与轨道设施、资源站、任务地点和门节点。星区是工程加载单位：首轮每个星系只有一个可游玩的主星区，后续可以增加局部星区和地点；不在同一坐标空间模拟整个天文尺度。下表沿用已有 `sector_*` 作为星系主星区标识，由区域定义关联所属 `system_id`；它不是“一个星系永久只有一个场景”的约束，正式关系以数据库方案为准。

下表的主要资源为常规产出，特色资源为该星系的原生或主要工业产出。敌人等级指常规敌对 NPC 的建议范围，不代表友方设施的固定强度，也不等于玩家等级。具体生成权重、精英配置与任务例外均由数据库驱动。

统治势力不代表所有 NPC 都属于该势力。高安全区域仍可有被明确标记的海盗据点、无人故障区和任务敌人；中低安全区域也可有中立补给站、贸易船和救援设施。

星系特色不仅体现在矿种：空间天气、可用服务、任务类型、敌人战术、门容量与制造设施共同产生差异。曜炉的热辐射提高作业与散热压力；雾帆的干扰使扫描和锁定更困难；静默渊的异常设施改变交战环境。这些效果都应有明确提示和数据库定义，不能临时由美术场景隐式决定伤害。

行星用于背景、轨道任务、资源供应与空间设施定位；第一阶段不直接登陆行星。行星工业若进入后续制作，通过空间站服务、运输订单和轨道设施交互完成，地表驾驶与步行另作独立范围决定。

## 3. 特色资源与替代获取

“特色或独有产出”表示自然分布或原创制造工艺集中在某星系，**不表示最终物品只能在原产地取得**。资源可以进入贸易、任务和回收渠道；玩家不应被一条关闭航路、敌对声望或已经耗尽的矿点永久卡住。

原矿、精炼材料、组件、蓝图、模块和舰体分别使用物品定义；制造输入输出用配方引用表达。资源、科技和舰船的具体配方由相应设计与数据库文档维护，不在本表再造一套精确数值。

## 4. 势力科技矩阵

势力科技是制造与使用理念，不是职业锁。玩家可以购买、学习和混合配装多个势力的产品；是否可装由挂点、尺寸、功率、算力、热量、质量及授权状态决定。基础阵营访问不能不可逆地锁死其他阵营的通行和补给。

| 势力与建议 ID | 武器路线 | 装甲与护盾 | 引擎与传感 | 制造及解锁特色 | 短板与取舍 |
| --- | --- | --- | --- | --- | --- |
| 航路议会 `faction_route_council` | 稳定脉冲束、精密火控与拦截设备 | 分区护盾、轻量修复与可靠防护；厚装甲能力一般 | 导航校准、远距测绘、稳定巡航 | 航路许可、探索资料与维护任务解锁；穿梭器、探索舰及精密模块 | 持续重火力与大宗作业效率不突出；高精传感器占算力和功率 |
| 深铸联合体 `faction_deepforge` | 动能炮、重型定向束及持续压制设备 | 重装甲、结构冗余、工业修复；护盾与精密传感不占优 | 高负载推进、拖运设备、矿物测读 | 原矿加工、工业合同与设施能力解锁；采矿舰、运输舰、重装舰和反应堆 | 质量大、转向与启动慢；高功率设备需要散热并提高维护负担 |
| 游弋同盟 `faction_roaming_alliance` | 快速弹道、导弹、诱饵与电子干扰 | 轻装甲、短时屏障、脱离与规避 | 高姿态响应、短时推进、干扰环境中的方向感知 | 航路情报、救援与运输贡献解锁；机动护卫舰、侦察舰、推进改装和混合装配 | 运载和持续承伤较弱；爆发推进与攻击争用能源和热量，复杂改装可靠性需管理 |
| 静默遗构 `faction_silent_relics` | 异常场域、无人协同与脉冲扰动 | 自适应场层、封闭结构与局部能量转移 | 异常定位、局部位移响应及无人感知 | 遗构资料、特殊组件和分阶段逆向研究解锁；先开放研究模块，再评估可驾驶舰体 | 对通用补给与常规配装兼容性差；能耗、热量和研究成本高，失去协同后暴露弱点 |

静默遗构是无人技术遗存，不能直接按普通商店阵营处理。其“科技解锁”由研究站、探索进度和逆向项目完成；敌方能力也不自动全部成为玩家可装模块。高级舰体开放需有专门任务与兼容验证。

科技差异需要体现在战斗和经济中：议会提供先发现和稳定用能的优势，深铸提供长时作业与正面承压，游弋提供选择接敌和脱离窗口，遗构提供条件性的场域变化。三种常规势力在可靠性、维护、材料与操控上形成取舍；不存在覆盖所有用途的最高阵营。

## 5. 科技层级与跨势力组合

建议科技按功能解锁而非只按伤害倍率升级：

1. **通用层**：基础飞行、采矿、扫描、防护与修理；锚港可以取得，确保开始与恢复可玩。
2. **专业层**：阵营角色强化；需要任务信誉、相关蓝图与材料，开放更多明确取舍。
3. **先进层**：重型设施或高阶资料支持；覆盖持续作业、专门火控、较大舰体与航路设备。
4. **遗构研究层**：探索、资料校验与特殊组件共同解锁异常设备；不设计为无条件超越常规科技。

同一武器或防护类别可有不同势力版本，但应改变射程、启动、持续耗能、热量、补给或维护方式，不单纯做相同模型的数字提高。生产地服务、蓝图解锁地点与原料来源可以不同，形成运输、贸易和护航需求。

解锁条件必须可查：缺少哪个任务、资料、材料、设备许可或制造设施，应在界面具体显示。关系恶化可以提高价格、关闭专属合同或延迟供应；恢复关系、代理采购与通用替代途径需可执行。首版不把驾驶基础船的资格绑定在现实时间等待上。

## 6. 锚定虫洞传送门网络

**锚定虫洞传送门是固定跨星系主航线。** 门的位置、起终点和出口明确，默认双向；玩家不能依靠持续飞行、星系内巡航或任意坐标跳跃绕过跨星系门。舰船没有门外自由跨星系航行能力。

“固定”指连接关系稳定，不表示所有门从开局就已启用。断航事件导致一些节点需要修复、许可或任务解锁；主线门有可预见的恢复条件。下表维护主航路，每条连接有独立 ID 与两端门实体，数据库以明确端点表示方向和准入条件。

| `conn_mirror_iron` | 镜湖 ↔ 铁环 | 中型 | 维护与救援合同恢复 | 议会与深铸之间的替代贸易路线 |

通行等级只表达船体能力与载荷限制的层次，具体千克上限等参数在 [数值基线](15-数值系统与平衡基线.md) 与数据库中维护。实际判断包括船型标签、当前船体和货物质量、稳定器资格、能源与门状态。教程门保证首轮四型的合法配装和合法满载均可双向通行，不要求消耗式燃料或通行费，也不会耗尽最后返程容量；后续门的容量以配装和载荷校验，不能只看舰级名称。

门容量、维护负荷、准备时间、冷却与费用由 `connection_defs` 等正式数据定义表达。固定主航线的日常负荷可以影响排队或服务，不应像游离虫洞一样无提示永久消失；任务关闭时提供公告、备用路线或修复入口。

航路规划应支持最短、较安全和满足当前舰船条件三种目的。出发前验证整段已知路线，而非到了半途才提示最后一门不兼容；对未知出口明确标记不确定性。路线图不承诺精确到现实空间距离，门网络就是跨星系拓扑。

## 7. 游离虫洞

游离虫洞是可选、需要发现的临时路线，可以连接既有星系的远地点或一次性探索区域。它不能替代固定主航线，也不能成为唯一的主线、基础材料或返程获取手段。

借鉴 EVE 虫洞的发现、寿命和质量限制关系，但稳定锚定门与本作游离虫洞的规则不同；EVE 官方事实见 [虫洞说明](https://support.eveonline.com/hc/en-us/articles/203209772-Wormholes)，改造边界见 [参考说明](11-EVE参考与原创边界.md)。

游离虫洞显示出口情报、容量、预计稳定度、返程状态和关闭风险；侦察专业舰获得更完整信息。消耗与剩余状态持久化，重读同一存档不凭空生成一条新的奖励航路。失效恢复至少包含备用出口、救援信标或带明示代价的撤离服务。

固定门与游离虫洞共同使用进入检查、加载、出口放置和状态提交流程，但拥有不同定义与运行实例；视觉可以体现固定门的装置结构和游离虫洞的自然边界。传送演出结束后恢复玩家此前镜头模式，飞行控制与实际位置由模拟和数据库恢复规则决定。

## 8. 安全区、任务难度与敌人生态

高安全以基础学习、补给和低强度作业为主；中安全要求配装与撤离判断；低安全引入组合敌群、环境压力和高价值目标。本文件维护常规敌对 NPC 的基础等级区间，星系目录在基础区间内细分各地生成范围；[玩法设定](09-玩法设定.md) 解释角色、AI 与任务行为，不另维护一套区间。

| 安全类别 | 常规敌对 NPC 基础等级区间草案 | 难度侧重 |
| --- | --- | --- |
| 高安全 | 1–5 | 基础识别、少量目标、清楚的警戒与撤离提示 |
| 中安全 | 3–8 | 配装取舍、编组与追击、有限环境压力 |
| 低安全 | 6–12 | 精英组合、干扰与协同、环境压力和撤离规划 |

等级区间是未平衡提案，实际值和生成配置由数据库维护。星系表的常规范围不得超出所属安全类别的基础范围；特殊剧情任务的越级情况按照下文的预警与例外规则单独配置。

等级区间允许重叠：同等级敌人在高安全区通常数量少、战术简单，中低安全区可以编组、干扰、追击或配合环境。NPC 等级不等于舰级，小型精英舰与大型普通舰有不同能力；配装、行为、数量、掉落与场景共同决定实际难度。

危险剧情任务可以高于当地常规范围，但接受任务和靠近地点前须显示等级、推荐角色/配装、环境威胁与撤退条件。星图进入高安全区的基础体验不会无预警变成高阶团战。友方或中立 NPC 是否变敌对由关系与任务规则决定，不由安全标签自动决定。

各势力 NPC 应有可辨战术：议会重视警戒、拦截和保护节点；深铸偏持续压制、装甲与作业防卫；游弋偏机动包抄、干扰和撤离；静默遗构偏协同节点、异常场域和无人增援。行为复杂度逐批增加，先让玩家看懂预警、弱点与脱离窗口。

## 9. 分布、再生与持久化

资源分布以星系、地点、资源标签、稀有度和生成种子定义；矿脉实例保存剩余量、发现状态、枯竭时间和下一次恢复条件。再生由世界时间、维护事件或明确补货规则触发，读档本身不触发再生。首轮世界时间随游玩推进，暂停或退出不强制离线倒计时。

同一业务更新原子应用资源扣除与库存增加，交易同时应用库存、收货与支付，制造同时应用材料、队列及交付状态。这些是运行内存中的一致变更，随后由完整快照统一持久化；只有 SQL 提交后才算保存成功。双向门是否启用、修复进度、控制变化、发现与通行消耗同样进入进度快照。重新加载场景不能重置已采空矿点或已解锁门，跨区中断遵循 [实现契约](17-首版行为与实现契约.md)。

| 概念数据组 | 设计职责 |
| --- | --- |
| `sector_defs` | 星系内容 ID、安全类别、基础控制势力、地点与服务引用、环境配置 |
| `connection_defs` | 门类型、明确两端、方向、等级、容量、许可、能源和开放条件 |
| `faction_tech_defs` | 势力技术路线、功能标签、许可和解锁条件，引用舰船、模块、材料与配方 |
| `resource_distribution_defs` | 资源原生分布、生成规则、稀有度、再生与补充策略 |
| `npc_defs` | NPC 模板、等级、阵营、舰型、配装、行为与掉落引用 |
| 对应进度实例 | 当前控制、发现、门状态、资源剩余、补货、敌人持久状态与世界时间 |

以上为概念职责，不自作 SQL 列名和约束。实际 schema、迁移、版本兼容、事务及备份以 [数据库与存读档技术方案](10-数据库与存读档技术方案.md) 为准。配置数据库给出“能发生什么”，进度数据库保存“这个世界已经发生什么”。

## 10. 实施分期与验收

| 批次 | 开放内容 | 验收要点 |
| --- | --- | --- |
| A：技术样例 | 锚港与回声带对应的两个测试星区、双向基础门、简化战舰与穿梭器、敌方目标 | 核验操控、镜头、穿越与数据库恢复；保存退出后恢复位置、货物与资源状态，验证 Mac 与 Windows 导出和数据库加载 |
| B：首个可玩闭环 | 锚港、回声带、基础4资源与首轮4舰；扫描、采矿、战斗、通行、基础配装与加工 | 四型能力差异可感知；任务出航到返航交付完整；教程双向通行可靠；资源扣除、奖励和存读档一致 |
| C：内容扩充 | 按批次开放3–6个星系，覆盖镜湖、熔脊、铁环、游弋渡；三常规势力初始科技、贸易与制造 | 星系各有任务与产出；配装和采购能产生差异；至少两条替代物流路径，缺稀有材料也能继续基础成长 |
| D1：后续扩展·危险航区 | 扩充曜炉、雾帆、断弦；高阶模块、环境压力、精英组合敌人、可选游离虫洞 | 进入前危险可预知；等级重叠但战术难度有差异；返回、采购及恢复方案可执行；资源再生不受读档重置 |
| D2：后续扩展·遗构研究 | 静默渊、两条遗构入口、高阶研究与特殊设备，完成十个核心星系的开放 | 研究不是随机掉落唯一门槛；关键材料有替代路线；高级装备具有明确短板，不能覆盖所有阵营用途 |
| D3：后续扩展·成熟活动深化 | 扩展蓝图研究、生产订单、区域事件、关系与任务链、舰队/合作职责 | 对完整机制逐项验收，按实际性能和维护成本确定开放规模；不以最小原型替代完整设计目标 |

批次是工程建议，不是削减用户的完整世界要求。若暂未建模的星系已进入配置数据库，应标记为未开放，避免星图显示可到达但客户端没有地点。实现状态、开放状态与设计状态分别记录。

本文件的下一轮评审重点是：星系特色是否足够区分、资源贸易是否产生合理路线、各势力短板是否真实、门容量是否支持玩家换舰，以及危险区奖励能否抵偿实际风险。精确产率、价格、敌人属性和门参数待原型实测后入库，不借用 EVE 的平衡数字。
